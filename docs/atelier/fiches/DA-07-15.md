# DA-07-15 — Rooms / Pièces — module M05 → Atelier — lot 3a

**État : prototype (lot 3a)** (à spécifier → spécifiée → prototype → vérifiée → disponible). Preuve liée : recette `apps/web/e2e/atelier-nouveau.mjs`, tests `apps/web/src/modules/atelier/nouveau/nouveau.test.ts` et `packages/atelier-model/src/commandes/commandes.test.ts` ; compte rendu `lots/lot-3a.md`.

| Champ | Contenu |
| --- | --- |
| Identité | DA-07-15 (M05, étape cible P1). Une pièce est un objet de classe `piece` (building.architecture) : un ou plusieurs polygones, un code, un nom, une catégorie, une aire déclarée et une aire calculée qui restent deux grandeurs distinctes. Sous-exigences : -a détecter les pièces candidates depuis les murs fermés (`piece.detecter`, proposition) ; -b créer (`piece.creer`) ; -c modifier (`piece.modifier`) ; -d supprimer (`piece.supprimer`). Référence de comportement : prototype, les 45 pièces de P.118 (`polygons`, `code`, `name`, `area`, `category`, `notes`, `label`). |
| Situation utilisateur | Délimiter les pièces d'un niveau à partir de ses murs fermés ou à la main, les nommer et les coder, et comparer l'aire déclarée à l'aire calculée sans que l'une remplace l'autre. |
| Entrées et unités | `niveauId` ; `polygones` (un ou plusieurs contours fermés `{ x, y, frame: "local", unit: "m" }`) ; `code`, `nom`, `categorie` (texte du projet, aucune liste imposée) ; `aireDeclaree` (m², provenance `saisie`, ou `prototype` à l'import) ; `notes` ; `etiquette`. `aireCalculee` est dérivée des `polygones` (m²), jamais saisie. |
| | Détection : ligne de délimitation (face intérieure des murs ou axe) choisie explicitement, sans valeur par défaut. Unité autre que m ou m² refusée (T03). Aucun code, nom, catégorie ni aire par défaut (R3) : absents, ils restent « non évalués ». |
| Comportement | **Détection (proposition).** `piece.detecter` calcule, à partir des murs du niveau, les régions fermées par les murs ; pour chacune : polygone, aire calculée, murs délimitants. Elle ne crée ni ne modifie rien : exécutée en aperçu (navigateur) ou à blanc (`POST /commands/essai`, scripts et assistant), elle ne produit ni révision ni entrée de journal. Les régions sont affichées en surimpression, acceptables une à une et modifiables, jamais imposées. |
| | **Cycle.** Outil « Pièce » → détection proposée ou tracé manuel (polygone, ou clic dans une région fermée) → paramètres (code, nom, catégorie, aire déclarée facultative) → aperçu (polygone, aire calculée, aire déclarée, écart) → contrôle → validation : `piece.creer` (un lot, libellé « Créer N pièces ») ; Échap annule sans commande. |
| | **Aire déclarée et aire calculée.** Toujours affichées ensemble. Un écart au-delà de la tolérance d'aire (valeur à consigner dans `decisions.md`, non posée ici) est un problème listé ; aucune des deux n'est remplacée en silence. `piece.modifier` peut, sur demande explicite, déclarer l'aire calculée (provenance `calcul`). L'aire calculée est l'aire géométrique des polygones, pas une surface réglementaire. |
| | **Pièce non fermée et références (R12).** Boucle de murs ouverte : aucune région proposée, interstice listé (extrémités, distance) avec proposition de `mur.joindre` (DA-07-01) ; le tracé manuel reste possible. Murs modifiés après création : la pièce ne bouge pas, sa délimitation différente est un problème listé, `piece.detecter` propose, `piece.modifier` adopte. Liaison `programme` à l'espace programmé (existante) : conservée par `piece.modifier`, « à réparer » avec propositions si la pièce est supprimée. Candidat recouvrant une pièce existante : présenté comme « pièce existante, polygone différent », jamais comme doublon. |
| | **Palette (UX2) et aide (UX4).** « pièce » ; synonymes « room », « local » ; actif si le niveau actif contient des murs, ou en tracé manuel ; exemple court : détecter les pièces fermées du niveau actif (exemple, jamais valeur par défaut). |
| Données et dépendances | Classe `piece` ; relation `delimitee-par` → `mur` (dérivée) et `delimite` des murs ; `programme` → espace programmé (liaison existante) ; `niveauId` ; annotation `etiquette` ; zone qui `contient` la pièce (DA-07-17). `core-geometry` (régions fermées, aires, jonctions) ; événement `atelier.commande.validee` : vues, quantités et bilan Harmonie « à recalculer » (R11, T07) ; microversion +1. |
| Résultats | Pièces créées ou modifiées ; propositions de détection (sans écriture) ; écart d'aire et pièces désalignées listés dans le panneau des modifications ; inverse = valeurs précédentes. |
| Cas limites | **Géométrie.** Boucle non fermée (interstice listé) ; région d'aire sous la tolérance ; polygone auto-intersecté ou de moins de 3 sommets : refusé (400 avec `chemin`) ; deux pièces de même `code` : signalées, non refusées ; pièce sans mur (tracé manuel) admise ; scission ou déplacement d'un mur : délimitation à revoir, listée ; niveau sans mur : aucune proposition. |
| | **Concurrence, réseau, droits.** `baseRevision` dépassée et pièce ou mur délimitant modifié ou supprimé depuis → 409 avec `conflits[].objetId` et état serveur ; même `requestId` → réponse enregistrée, aucune seconde révision (T06) ; hors ligne : réducteur local, file Dexie, rejeu dans l'ordre, brouillon si incompatible ; 403 motivé, 404 sans accès, 423 pendant une réservation d'autrui (R13). |
| Compatibilité | Import P.118 (section 6) : 45 `piece` ; `area` → `aireDeclaree` (provenance `prototype`), aire calculée dérivée, écart > tolérance → problème listé ; `label` → `etiquette` ; tracés `role = room` rattachés à `piece.polygones` si le code correspond, sinon `espace` (DA-07-16) ; jamais une pièce en double. |
| | IFC (annexe C, lot 6) : `IfcSpace`, aires en `Qto_SpaceBaseQuantities` (aire calculée, source de chaque valeur nommée) ; aire déclarée en propriété distincte. DXF : aucune sortie propre. |
| Validation | **Unité** (`packages/atelier-model/src/commandes/piece.test.ts`) : détection sur quatre murs fermés : une région, aire calculée à la tolérance, modèle inchangé (empreinte identique avant et après) ; boucle ouverte : aucune région, interstice listé ; deux boucles : deux régions ; `piece.creer` d'une région acceptée ; aire déclarée ≠ calculée : écart listé, aucune valeur remplacée ; candidat recouvrant une pièce existante : « polygone différent », pas de doublon ; mur déplacé : pièce inchangée, désalignement listé ; inverse restitue l'état. |
| | **API** (`apps/api/src/routes/atelier-commands.test.ts`) : `POST /commands/essai` avec `piece.detecter` → 200, propositions, aucune révision ni entrée de journal ; `piece.creer` → 200, révision +1 ; polygone auto-intersecté → 400 avec `chemin` ; même `requestId` → même réponse ; `baseRevision` périmée et mur délimitant modifié → 409 avec `conflits[].objetId` ; rôle lecture → 403 ; réservation d'autrui → 423. |
| | **e2e** (`apps/web/e2e/scenarios/05-atelier.mjs`, bloc « 2D · pièces ») : copie de travail de P.118 : 45 pièces listées avec aire déclarée et aire calculée, écarts listés d'après le rapport d'import ; détection lancée sur un niveau : propositions affichées, révision inchangée ; accepter une proposition : révision +1, annuler, rétablir ; second navigateur à la même révision. |
| Règles métier | Aucune règle de surface ni de pièce (surface minimale, hauteur, éclairement, catégorie réglementaire : non fournies ; règles selon pays, usage et version identifiés, à fournir avec leur source). R3 : aucune aire ni aucun code par défaut ; l'aire déclarée n'est jamais présentée comme vérifiée. R9 : détection = proposition jamais imposée (annexe B), création par commande. R10 : niveau actif et propositions affichées hors révision. R11. |
| Extensions à spécifier | Détection sur plusieurs niveaux ; pièces à hauteur propre ; règle de mesure des surfaces, à fournir avec sa source ; numérotation automatique des codes ; fusion et scission de pièces ; création de la liaison à l'espace programmé depuis l'Atelier (Programmation). |

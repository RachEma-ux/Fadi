Preuve liée : tests `packages/atelier-model/src/commandes/bloc.test.ts` (définition depuis 3 objets, mur refusé, 2 occurrences, redéfinition version + 1, décomposition, inverse) ; recette `apps/web/e2e/atelier-documents.mjs` ; compte rendu `lots/lot-5.md`.

| Champ | Contenu |
| --- | --- |
| Identité | DA-05-06 (M04, étape cible P1). Sous-exigences : -a définir un bloc depuis une sélection (`bloc.definir`) ; -b placer des occurrences (`bloc.placer`) ; -c redéfinir un bloc (version suivante) ; -d décomposer une occurrence (`transformer.decomposer`). Un bloc est une `definition` du catalogue versionné (§5.2) dont les occurrences sont des objets placés ; il ne contient que du dessin réutilisable. Distinct du groupe (DA-05-05) et du composant (DA-05-09). |
| Situation utilisateur | Réutiliser un dessin (symbole, détail, solide) à plusieurs endroits : le définir une fois, le placer autant de fois que nécessaire et corriger toutes les occurrences en modifiant la définition. |
| Entrées et unités | `bloc.definir` : `nom`, `pointDeBase` `{ x, y, frame: "local", unit: "m" }`, `cibles` (objets sources d'un niveau), option « remplacer la sélection par une occurrence » ; un `blocId` existant = redéfinition. `bloc.placer` : `blocId`, `niveauId`, `calqueId`, `position` (point local, m), `angle` (°). Coordonnées de la définition : vecteurs locaux relatifs au point de base. Aucune échelle propre à l'occurrence (extension). |
| Comportement | **Cycle.** Définition : sélection → point de base (accroché, DA-02-15) → nom → aperçu (symbole, nombre d'objets, classes) → contrôle → validation. Placement : choix du bloc dans la bibliothèque (DA-05-07) → position et angle (clic ou saisie, DA-02-16) → aperçu fantôme → validation ; Échap annule sans commande. |
| | **Commandes.** `bloc.definir`, `bloc.placer` (lot 5, annexe B) ; `transformer.decomposer` remplace une occurrence par des copies indépendantes (nouvelles identités). Redéfinir un bloc crée la version n + 1 : les occurrences gardent leur identité et suivent la dernière version ; l'aperçu liste le nombre d'occurrences et les niveaux touchés, et aucune occurrence n'est modifiée sans cet aperçu. |
| | **Contrôles.** Classes admises dans une définition : `esquisse.*`, `solide`, `texte` ; refusées : classes qui portent des relations ou des références (`mur`, `ouverture`, `escalier`, `piece`, `cotation`, `etiquette`, R12) ; bloc contenant une de ses propres occurrences refusé ; sources d'un calque verrouillé refusées seulement avec « remplacer la sélection » ; occurrence sur un calque ou un niveau verrouillé refusée ; unité ≠ m refusée (T03). |
| | **R15.** La géométrie canonique est celle de la définition ; une occurrence n'en copie aucune : son plan 2D et son solide sont des représentations dérivées (autorité `derivee`, moteur et version enregistrés, `empreinteEntrees` de la définition et du placement). |
| Données et dépendances | Entités `definition` (bloc : `nom`, `version`, `pointDeBase`, objets en coordonnées locales relatives) et `occurrence` (`blocId`, version, `niveauId`, `calqueId`, `position`, `angle`) ; classe d'occurrence de bloc absente du tableau 5.2, à y ajouter avant le lot 5 (écart signalé au chef de projet). Aucune caractéristique nommée de bloc n'existe en 5.2 : aucune cotation ni étiquette ne peut s'y rattacher, donc aucune référence à réparer. |
| | Événement de commande validée : vues et quantités « à recalculer » (R11, T07) ; microversion +1. |
| Résultats | Une définition versionnée et des occurrences sélectionnables, déplaçables (`transformer.*`) et annulables ; effets listés (occurrences touchées par une redéfinition) ; inverse = version et placement précédents. |
| Cas limites | **État.** Sélection vide ou sans classe admise : refusée ; redéfinition qui viderait le bloc : refusée ; occurrence dont la définition est introuvable (import tronqué) : affichée « définition manquante », jamais effacée ; décomposition d'une occurrence sur un calque verrouillé : refusée. |
| | **Concurrence et réseau.** `baseRevision` dépassée et définition modifiée depuis → 409 avec `conflits[].objetId` (le `blocId`) ; occurrence supprimée par autrui : elle ne réapparaît pas ; même `requestId` → une seule révision et une seule version (T06). Hors ligne : réducteur local, file Dexie, rejeu dans l'ordre ; deux redéfinitions concurrentes : la seconde passe en brouillon. 403 / 404 / 423 selon R13. |
| Compatibilité | Import P.118 : aucun bloc ; les 32 occurrences d'escalier restent des `escalier`. DXF : `BLOCK` et `INSERT` à l'export des vues, à spécifier avec l'export DXF (lot 5) ; l'import DXF 2D (lot 6) produit un `reference-plan`, pas de bloc. IFC : `IfcRepresentationMap` et `IfcMappedItem` candidats, à confirmer à l'annexe C (lot 6) ; un objet importé n'a pas d'historique inventé (R16). |
| Validation | **Unité** (`packages/atelier-model/src/commandes/bloc.test.ts`) : définition depuis 3 objets ; classe refusée (`mur`) ; 2 occurrences placées : même `blocId`, identités distinctes ; redéfinition : version +1, occurrences suivent, `empreinteEntrees` change, identités inchangées ; décomposition : copies indépendantes, occurrence supprimée, effets listés ; inverse restitue la version précédente. |

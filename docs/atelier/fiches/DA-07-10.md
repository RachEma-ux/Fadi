# DA-07-10 — Stairs / Escaliers (escalier droit) — module M05 → Atelier — lot 3a

**État : prototype (lot 3a)** (à spécifier → spécifiée → prototype → vérifiée → disponible). Preuve liée : recette `apps/web/e2e/atelier-nouveau.mjs`, tests `apps/web/src/modules/atelier/nouveau/nouveau.test.ts` et `packages/atelier-model/src/commandes/commandes.test.ts` ; compte rendu `lots/lot-3a.md`.

| Champ | Contenu |
| --- | --- |
| Identité | DA-07-10 (M05, étape cible P2). Reprend la fiche d'exemple de l'Exigences V4 (escalier droit paramétrique reliant deux niveaux, exemple à approuver par les essais métier, qui ne représente pas tous les types d'escaliers visés) et la complète pour Fadi : un escalier est un objet de classe `escalier` (building.architecture), relation `relie` vers un niveau de départ et un niveau d'arrivée. Sous-exigences : -a créer (`escalier.creer`) ; -b modifier (`escalier.modifier`) ; -c supprimer (`escalier.supprimer`) ; -d occurrences et groupe d'un même escalier physique. Référence de comportement : prototype, les 32 occurrences d'escaliers de P.118 (vues par niveau d'escaliers physiques). |
| Situation utilisateur | Relier deux niveaux par un escalier droit paramétrique, voir les valeurs effectivement retenues et leurs contradictions avec les niveaux, sans qu'aucun objet voisin ne bouge en silence. |
| Entrées et unités | `niveauDepartId`, `niveauArriveeId` (deux niveaux existants et distincts) ; `axe` `a`, `b` `{ x, y, frame: "local", unit: "m" }` (longueur supérieure à la tolérance de longueur, DA-01-01) ; `largeur`, `hauteurAFranchir`, `epaisseurPaillasse`, `decalageBase` `{ value, unit: "m" }` (largeur et hauteur à franchir > 0 ; décalage signé) ; `contremarches`, `marches` (entiers ≥ 1) ; `groupe` (identifiant de l'escalier physique) ; `referencePlanSeulement` (booléen). Points accrochés (DA-02-15) ou saisis (DA-02-16). |
| | Au choix, un nombre de contremarches ou une hauteur de contremarche cible (le nombre entier le plus proche est alors proposé). Unité autre que m refusée (T03). Aucune valeur par défaut (R3) : un paramètre absent reste « non évalué » et bloque ce qui en dépend sans rien déduire ; l'écart d'élévations des deux niveaux peut être proposé comme `hauteurAFranchir` candidate, retenue seulement sur validation. |
| Comportement | **Cycle.** Outil « Escalier » → niveaux de départ (niveau actif) et d'arrivée → paramètres (largeur, hauteur à franchir, contremarches ou hauteur cible, épaisseur de paillasse, décalage de base) → axe par points accrochés ou saisis → aperçu (plan, valeurs retenues, contradictions) → contrôle → validation ; Échap annule sans commande. |
| | **Proposition de calcul.** Compatible avec les paramètres saisis, jamais appliquée d'office. Avec `hauteurAFranchir` H et `contremarches` n, la hauteur de contremarche retenue vaut H / n (non arrondie) ; avec une hauteur cible, les deux entiers n qui l'encadrent sont proposés avec la hauteur qui en résulte ; giron dérivé = longueur de l'axe / `marches` (convention de décompte à confirmer sur les 32 occurrences de P.118). L'aperçu affiche, par grandeur, valeur saisie, valeur retenue et contradictions (somme des contremarches ≠ H, écart avec la différence d'élévations des niveaux, `marches` incohérent avec `contremarches`), sans rien corriger. Aucune limite de hauteur de marche, de giron ni de largeur n'est appliquée (R3). |
| | **Niveaux de départ et d'arrivée.** `escalier.creer` refusé si un niveau est absent, inconnu ou si les deux sont identiques (400 avec `chemin`) ; à l'import, un niveau d'arrivée absent ou inconnu laisse l'escalier en place avec le problème « niveau d'arrivée introuvable » (jamais supprimé, jamais deviné). Changer l'élévation d'un des deux niveaux (`niveau.modifier`, DA-05-04) ne modifie pas l'escalier : la contradiction est listée avec les valeurs retenues et une proposition d'`escalier.modifier`. Trémie : l'aperçu signale une dalle du niveau supérieur sans trou à l'emprise de l'escalier, avec proposition de `dalle.modifier` (DA-07-06), jamais appliquée sans accord. |
| | **Occurrences et groupe.** Un escalier physique peut avoir une occurrence par niveau (vue par niveau) ; `groupe` les relie sans les fusionner. `referencePlanSeulement` vrai : occurrence conservée et affichée en plan comme référence, valeur importée telle quelle ; son effet sur les quantités et la 3D n'est pas interprété ici (Extensions). `escalier.modifier` sur une occurrence ne change aucune autre occurrence du même `groupe` : l'aperçu les liste avec les écarts créés et propose « ajouter au lot » ; avec accord, une `escalier.modifier` par occurrence, dans un seul lot. |
| | **Palette (UX2) et aide (UX4).** « escalier » ; synonymes « stair », « escalier droit » ; actif si le modèle compte au moins deux niveaux ; exemple court : relier deux niveaux par un escalier de 1,00 m de large (exemple, jamais valeur par défaut). |
| Données et dépendances | Classe `escalier` ; relation `relie` → `niveau` (départ, arrivée) ; `groupe` ; caractéristiques `escalier:depart`, `escalier:arrivee` (cotations) ; trémie = `trous` d'une `dalle` (DA-07-06) ; garde-corps : DA-07-12 (P2), référence créée seulement lorsqu'il existera. Dépendances : M02 (géométrie), M03 (contraintes, lot 5), M11 (vues et quantités, lot 5), objets hébergés coordonnés explicitement. |
| | `core-geometry` ; événement `atelier.commande.validee` : vues, quantités et bilan Harmonie « à recalculer » (R11, T07) ; microversion +1. |
| Résultats | Escalier créé, modifié ou supprimé ; valeurs retenues, contradictions, trémie absente et occurrences divergentes listées dans le panneau des modifications ; aucun objet adjacent déplacé ; documents et quantités « à recalculer » ; inverse = valeurs précédentes enregistrées. |
| Cas limites | **Valeurs.** Niveau de départ ou d'arrivée absent, inconnu ou identique ; `hauteurAFranchir` ou `largeur` ≤ 0 ; `contremarches` ou `marches` non entier ou < 1 ; axe de longueur nulle ; arrivée située sous le départ ou écart d'élévations nul : admis, contradiction affichée (sens de montée explicite), rien corrigé. |
| | **Concurrence, réseau, droits.** `baseRevision` dépassée et escalier, groupe ou niveau modifié depuis → 409 avec `conflits[].objetId` et état serveur ; niveau supprimé par autrui pendant la saisie : refus au rejeu ; même `requestId` → une seule révision (T06) ; hors ligne : réducteur local, file Dexie, rejeu dans l'ordre, brouillon si incompatible ; 403 / 404 / 423 selon R13. |
| Compatibilité | Import P.118 (section 6) : 32 `escalier` (occurrences) avec `relie` (`sourceLevel`, `targetLevel`), `referencePlanSeulement` (`planReferenceOnly`), `groupe` (`stairGroup`) en propriété sans fusion silencieuse ; `width`, `height`, `baseOffset`, `steps`, `risers`, `waistThickness` conservés exactement ; `designRevision` en propriété de provenance `import`. |
| | IFC (annexe C, lot 6) : `IfcStair` (+ `IfcStairFlight` si décomposé), paramètres en `Pset_StairCommon` ; une seule `IfcStair` par escalier physique (`groupe`) à l'export, occurrences exclues nommées au rapport d'échange (règle à préciser au lot 6). DXF : aucune sortie propre. |
| Validation | **Unité** (`packages/atelier-model/src/commandes/escalier.test.ts`) : création avec niveaux de départ et d'arrivée ; niveau absent, inconnu ou identique refusé ; unité ≠ m refusée ; H = 3,00 m et n = 17 (entrées de test sans valeur normative) : hauteur de contremarche = H / n non arrondie, somme des contremarches = H à la tolérance de longueur ; hauteur cible : deux entiers proposés, aucun appliqué ; élévation d'un niveau modifiée : contradiction listée, aucun paramètre de l'escalier modifié ; modification d'une occurrence : autres occurrences du `groupe` listées, non modifiées ; `referencePlanSeulement` conservé après aller-retour ; inverse restitue l'état. |
| | **API** (`apps/api/src/routes/atelier-commands.test.ts`) : `escalier.creer` → 200, révision +1, `effets` (trémie à examiner, contradictions) ; niveau d'arrivée absent → 400 avec `chemin` ; même `requestId` → même réponse ; `baseRevision` périmée et niveau ou escalier modifié → 409 avec `conflits[].objetId` ; rôle lecture → 403 ; réservation d'autrui → 423. |
| | **e2e** (`apps/web/e2e/scenarios/05-atelier.mjs`, bloc « 2D · escaliers ») : copie de travail de P.118 : 32 occurrences listées, regroupées par `groupe` sans fusion, occurrences `referencePlanSeulement` repérées ; créer un escalier entre deux niveaux, annuler, rétablir ; changer l'élévation du niveau supérieur : contradiction affichée avec les valeurs retenues, aucun escalier ni objet adjacent déplacé ; second navigateur à la même révision. |
| Règles métier | Aucune règle réglementaire d'escalier n'est posée (hauteur de marche, giron, largeur, marches par volée, palier, garde-corps, échappement). Les règles applicables selon pays, usage et version identifiés restent à fournir avec leur source ; sans elles, aucune conformité n'est affichée et les grandeurs concernées restent « non évaluées ». R3 : proposition, valeur retenue et contradiction sont trois choses distinctes. R9 : tout par commande ; R10 : niveau actif et sélection hors révision. Le résultat n'est jamais présenté comme conforme sans les contrôles nécessaires (Exigences V4). |
| Extensions à spécifier | Volées multiples, paliers, escaliers tournants et hélicoïdaux ; détails constructifs, matériaux, méthodes de fabrication (reprise de l'exemple V4) ; garde-corps (DA-07-12) et trémie créée avec l'escalier ; sens exact de `referencePlanSeulement` et décompte des quantités par `groupe` (lot 5), à fixer avec le maître d'ouvrage ; convention de combinaison de `decalageBase` avec les élévations, à vérifier sur P.118. |

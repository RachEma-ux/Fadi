| Champ | Contenu |
| --- | --- |
| Identité | **DA-02-13** « Explode » (Exigences V4.1, annexe B.3, module M02, étape cible P1 ; critère de recette commun B.3 : « Transformations réversibles ; sélection, copie et dépendances conservées »). Retenue (proposition §5.1, lot 3) ; tâche **L3a.2**. Sous-exigences : **DA-02-13-a** décomposer une primitive composée d'esquisse en primitives plus simples ; **-b** décomposer un `solide` en son contour d'esquisse ; **-c** décomposer un groupe (= dissoudre un niveau de groupe) ; **-d** liste des pertes de paramètres et accord explicite ; **-e** refus motivé pour les objets d'architecture. Fiches liées : DA-01-02 à 06, 11 (primitives, hachure), DA-05-05 (groupes), DA-05-06 (blocs, lot 5), DA-07-01 (murs). |
| Situation utilisateur | L'architecte veut retravailler un morceau d'une forme : supprimer un côté d'un rectangle, reprendre une polyligne segment par segment, récupérer le contour d'un volume, défaire un groupe. Résultat : des objets plus simples, éditables séparément, **en sachant exactement ce qui est perdu**. |
| Entrées et unités | `cibles` : sélection typée ; `pertesAcceptees` : liste des pertes renvoyée par l'aperçu (`POST /commands/essai`), à renvoyer telle quelle pour valider. Aucun autre paramètre ; aucune unité saisie. |
| Comportement | Cycle UX3 : outil « Décomposer » (synonymes « explode », « éclater », « dégrouper ») → sélection → **aperçu** : objets produits (contours fantômes) et **tableau des pertes** (objet, paramètre perdu, valeur) → contrôle → validation par accord explicite si la liste des pertes n'est pas vide.<br>Commande émise (annexe B) : `{ type: "transformer.decomposer", cibles: [id…], params: { pertesAcceptees: [{ objetId, parametre }] } }`. Résultat par classe (**Recommandation** de cette fiche, à confirmer par L1.2) :<br>• `esquisse.rectangle` → `esquisse.polyligne` fermée de 4 sommets (perte : paramètres largeur, hauteur, angle du rectangle) ; décomposé à nouveau → 4 `esquisse.ligne`.<br>• `esquisse.polygone` → `esquisse.polyligne` fermée (perte : nombre de côtés / rayon s'il est régulier).<br>• `esquisse.polyligne` → une `esquisse.ligne` par segment (perte : fermeture, identité de contour) ; segments d'arc éventuels → `esquisse.arc`.<br>• `esquisse.spline` → `esquisse.polyligne` approchée avec une flèche ≤ `tolCorde` 0,001 m (**proposée, à confirmer**) — l'approximation est une perte listée (« forme exacte de la spline »).<br>• `esquisse.hachure` → son ou ses contours en `esquisse.polyligne` fermées ; le motif n'est **pas** transformé en lignes (perte listée : motif, échelle, angle).<br>• `esquisse.ligne`, `esquisse.arc`, `esquisse.cercle`, `esquisse.construction` → objets élémentaires : refus « rien à décomposer ».<br>• `solide` → `esquisse.polyligne` fermée du contour + une par trou (perte listée : `hauteur`, `decalageBase`, `epaisseur`, `role`, `couleur`, `vertexOffsets` / `topOffsets` s'il y en a, propriétés de provenance `import`).<br>• **groupe** → la commande émise est `groupe.dissoudre` (annexe B) ; les membres sont conservés intacts, un seul niveau d'imbrication à la fois ; aucune perte de paramètre.<br>• `mur`, `porte`, `fenetre`, `ouverture`, `dalle`, `toiture`, `escalier`, `piece`, `espace`, `zone`, `poteau`, `niveau`, `cotation`, `texte`, `etiquette` → **refus** « un objet d'architecture ne se décompose pas » : le décomposer détruirait hébergement, type, pièces délimitées et quantités. Le contour d'un mur s'obtient par les vues et l'export DXF (lot 5), jamais par décomposition du modèle. Une sélection mixte contenant une classe refusée est refusée entière (tout ou rien) avec la liste.<br>Effets : suppression de la cible, création des produits (identifiants neufs, même niveau, même calque), propriété de provenance `decomposeDe: <id>` (`provenance: calcul`). Inverse : recréation de l'objet d'origine **avec son identifiant et ses paramètres exacts** (conservés dans l'inverse du journal) et suppression des produits. |
| Données et dépendances | Réducteur `transformer.decomposer` (`packages/atelier-model`) ; calcul de la liste des pertes dans le réducteur (même calcul en aperçu et sur le serveur) ; échantillonnage de spline dans `packages/core-geometry`. Écritures `atelier_objects` (1 suppression, N créations), journal (inverse complet), événement → vues du niveau « à recalculer » ; un `solide` décomposé retire un volume : vues 3D, quantités et aperçu conceptuel marqués. **Références** : toute référence vers une caractéristique de l'objet décomposé (`esquisse:segment[i]`…) passe **« à réparer »** avec la proposition du produit correspondant (R12, T05) ; jamais de rattachement silencieux. |
| Résultats | Objets produits visibles et sélectionnables séparément ; tableau des pertes conservé dans l'entrée de journal (« Décomposer — pertes acceptées : … ») ; références à réparer listées dans le panneau des problèmes ; révision `n + 1`. |
| Cas limites | Pertes non vides et `pertesAcceptees` absente ou différente de la liste calculée par le serveur (l'objet a changé entre l'aperçu et l'envoi) → 400 « pertes non acceptées » avec la liste à jour. Objet élémentaire → refus. Classe d'architecture → refus motivé. Groupe vide → refus. Objet sur un calque verrouillé → refus « calque verrouillé : <nom> ». Spline dont l'approximation dépasserait la taille d'enveloppe (cahier §8, 1 Mo) → refus. Lecteur 403 ; réservation 423 ; objet modifié par autrui 409 ; `requestId` répété → une seule décomposition (T06) ; hors ligne : exécution locale (la liste des pertes est calculée localement par le même réducteur), rejouée ; incompatibilité au retour → brouillon visible. |
| Compatibilité | Les produits suivent les fiches de leur classe (DXF `LWPOLYLINE` / `LINE` des vues au lot 5, à confirmer par DA-22-03 ; esquisses omises de l'export IFC et listées au rapport, R7). Import P.118 : 807 tracés `solid` et 35 `clearance` deviennent des `solide` décomposables sous accord (le `role` et les `vertexOffsets` éventuels apparaissent dans les pertes) ; aucun groupe dans les données. Prototype : pas d'outil de décomposition. |
| Validation | **Unité** (`packages/atelier-model/src/commandes/transformer.test.ts`) : rectangle 4 × 3 → polyligne fermée (0 ; 0), (4 ; 0), (4 ; 3), (0 ; 3), pertes = [largeur, hauteur, angle] ; polyligne → 4 lignes de longueurs 4, 3, 4, 3 m ; solide P.118 à `vertexOffsets` → contour + pertes incluant `vertexOffsets` ; hachure → contour, pertes motif / échelle / angle ; mur → refus ; sélection mixte mur + rectangle → refus entier ; groupe → `groupe.dissoudre`, membres identiques ; pertes non acceptées → 400 ; inverse → objet d'origine avec **le même identifiant**, empreinte identique ; cotation attachée à un segment de polyligne → « à réparer » avec proposition. **API** : 400 pertes ; idempotence ; 403. **Scénario** `05-atelier.mjs` : rectangle tracé sur la mezzanine, décomposé, tableau des pertes affiché, accord, 4 côtés sélectionnables, suppression d'un côté, annuler deux fois → rectangle d'origine. |
| Règles métier | Aucune règle réglementaire. Règle AGENTS.md « ne rien omettre silencieusement » appliquée aux paramètres : toute perte est listée et acceptée. |

# DA-02-13 — Explode / Décomposer — module M02 → Atelier — lot 3a

**État : prototype (lot 3a)** (à spécifier → spécifiée → prototype → vérifiée → disponible). Preuve liée : recette `apps/web/e2e/atelier-nouveau.mjs`, tests `apps/web/src/modules/atelier/nouveau/nouveau.test.ts` et `packages/atelier-model/src/commandes/commandes.test.ts` ; compte rendu `lots/lot-3a.md`.

| Champ | Contenu |
| --- | --- |
| Identité | DA-02-13 (M02, étape cible P1). `transformer.decomposer`. Pas de référence dans le prototype. |
| Situation utilisateur | Défaire un objet d'esquisse composé (polyligne, polygone, rectangle) en objets simples indépendants pour les ajuster, les raccorder ou les supprimer séparément. |
| Entrées et unités | `niveauId` ; `cibles` ; `nouveauxIds` (un par ligne créée, fournis ou dérivés du `requestId`). |
| | Classes admises : `esquisse.polyligne` (N − 1 lignes), `esquisse.polygone` et `esquisse.rectangle` (N lignes, le contour n'est plus fermé) ; blocs (`bloc.placer`) au lot 5 ; un `groupe` se dissout par `groupe.dissoudre`. **Jamais** décomposés : `mur`, `dalle`, `toiture`, `escalier`, `poteau`, `solide`, `piece` (R15) ni `cotation` (elle perdrait son sens de mesure). |
| Comportement | **Cycle.** Sélection (aucun point à poser : accrochages et saisie de précision sans objet) → aperçu : « N lignes » et, pour un contour fermé, « le contour n'est plus un profil » → contrôle → validation = un lot ; Échap annule sans commande. |
| | **Résultat.** Chaque objet décomposé est remplacé par ses lignes (nouveaux identifiants, même calque, même niveau) ; l'objet d'origine disparaît ; l'inverse le restaure avec ses identifiants. |
| | **Pourquoi pas les objets bâtis.** Leur géométrie canonique est paramétrique (R15) et leur sens métier se perdrait : une ligne n'est pas un mur (Concept §3), un mur n'est pas un jeu de lignes. |
| | **Références (R12).** Les cotations, contraintes (lot 5) et références qui visaient l'objet d'origine passent « à réparer » avec les segments proposés, jamais rattachées en silence ; l'aperçu annonce leur nombre et la validation demande un accord explicite. |
| | **Contrôles.** Cible non décomposable : refus (« Décomposer — un mur ne se décompose pas ; modifiez-le avec ses commandes. ») ; ligne simple : « rien à décomposer » ; cible d'un autre niveau, supprimée ou sur un calque verrouillé : lot refusé en entier. |
| | **Palette (UX2) et aide (UX4).** « décomposer » ; synonymes « explode », « éclater », « casser » ; actif si une polyligne, un polygone ou un rectangle est sélectionné ; exemple court : décomposer un rectangle en quatre lignes ; clavier complet : sélection puis palette. |
| Données et dépendances | Supprime l'occurrence d'origine, crée N occurrences `esquisse.ligne` (identifiants déterministes) ; références à réparer ; événement de commande validée : vues du niveau « à recalculer » (R11, T07). |
| Résultats | N lignes indépendantes sélectionnées après validation, effets listés (1 supprimé, N créés, références à réparer), inverse = objet d'origine restauré et lignes supprimées. |
| Cas limites | **Géométrie.** Cible non décomposable (mur, dalle, solide…) ; ligne simple ; objet déjà décomposé par un autre utilisateur (409) ; contour fermé : la fermeture est perdue, indiquée ; calque verrouillé : lot refusé en entier. |
| | **Concurrence.** `baseRevision` dépassée et cible modifiée ou supprimée depuis → 409 détaillé, résolution explicite côté client ; même `requestId` → pas de seconde décomposition (T06). |
| | **Réseau et droits.** Hors ligne : réducteur local, rejeu identique grâce à `nouveauxIds`, file Dexie rejouée dans l'ordre ; 403 motivé, 404 sans accès, 423 pendant une réservation d'autrui (R13). |
| Compatibilité | Import P.118 : aucun tracé ouvert, aucune polyligne importée (les 967 tracés fermés sont des `solide`, non décomposables) : la commande s'exerce sur les esquisses dessinées dans Fadi. DXF : lignes exportées en `LINE`. IFC : omis au rapport d'échange. |
| Validation | **Unité** (`packages/atelier-model/src/commandes/transformer.test.ts`) : rectangle → 4 lignes dont les extrémités se rejoignent ; polyligne de 5 sommets → 4 lignes ; mur refusé ; cotation référencée : « à réparer » avec 4 propositions ; inverse restaure l'objet et ses identifiants ; mêmes identifiants pour la même enveloppe. |
| | **API** (`apps/api/src/routes/atelier-commands.test.ts`) : `transformer.decomposer` sur un rectangle → 200 avec `effets` (1 supprimé, 4 créés) ; sur un mur → 400 avec motif ; même `requestId` → une seule révision ; `baseRevision` périmée → 409. |
| | **e2e** (`apps/web/e2e/scenarios/05-atelier.mjs`, bloc « 2D · décomposer ») : sur la copie de travail de P.118, un rectangle d'esquisse décomposé en 4 lignes sur la mezzanine ; un mur sélectionné : action refusée avec son message ; annuler : le rectangle revient ; second navigateur. |
| Règles métier | Aucune règle réglementaire. R12 : références jamais rattachées en silence ; R15 : aucun objet bâti décomposé en lignes. |
| Extensions à spécifier | Joindre (inverse : lignes jointives en polyligne) ; décomposer arcs, splines et hachures ; décomposer un bloc (lot 5) ; objets « représentation importée » (lot 6). |

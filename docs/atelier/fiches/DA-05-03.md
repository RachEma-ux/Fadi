# DA-05-03 — Levels / Niveaux CAO (organisation d'affichage) — module M04 → Atelier — lot 3a

**État : prototype (lot 3a)** (à spécifier → spécifiée → prototype → vérifiée → disponible). Preuve liée : recette `apps/web/e2e/atelier-nouveau.mjs`, tests `apps/web/src/modules/atelier/nouveau/nouveau.test.ts` et `packages/atelier-model/src/commandes/commandes.test.ts` ; compte rendu `lots/lot-3a.md`.

| Champ | Contenu |
| --- | --- |
| Identité | DA-05-03 (M04, étape cible P1). Interprétation de l'inventaire : « Levels » = organisation d'affichage, à distinguer du niveau du bâtiment (`niveau`, étage, DA-05-04). Un level CAO n'est pas un objet du modèle : il est réalisé par des **ensembles d'affichage** (préréglages nommés de calques et de classes affichés). Sous-exigences : -a créer, appliquer, renommer et supprimer un ensemble ; -b vocabulaire : « niveau » désigne seulement l'étage dans toute l'interface. |
| Situation utilisateur | Passer d'une organisation d'affichage à une autre (par exemple n'afficher que certains calques et certaines classes) sans toucher au modèle et sans confondre cette organisation avec les étages du bâtiment. |
| Entrées et unités | `nom` de l'ensemble ; `calquesAffiches` (identifiants de calques) ; `classesAffichees` (classes du tableau 5.2). Aucune grandeur : pas d'unité ; un ensemble ne porte ni élévation ni hauteur, qui appartiennent au `niveau` (étage). |
| Comportement | **Cycle.** Panneau Ensembles d'affichage → « enregistrer l'affichage actuel » (nom) ou choix d'un ensemble existant → aperçu immédiat du plan filtré avec le nombre d'objets masqués → application. Pas de contrôle ni de validation serveur : aucune commande n'est émise (R10, §5.3) ; Échap ferme le panneau sans changement. |
| | **Composition.** Visibilité effective = `visible` du calque (modèle, DA-05-01) ET ensemble appliqué ET filtre de classe (DA-05-02) ET niveau visible. Un ensemble réduit l'affichage, il ne le révèle jamais : un calque masqué dans le modèle reste masqué et l'ensemble le signale (« masqué dans le modèle ») avec un lien vers `calque.modifier`. |
| | **Vocabulaire (R1, R2).** « Niveau » = étage ; « calque » = DA-05-01 ; « ensemble d'affichage » = level CAO. Aucun libellé d'interface n'emploie « niveau » pour un ensemble ; la navigation entre étages reste celle de DA-05-04. |
| Données et dépendances | Aucune classe du modèle, aucune commande, aucune révision. Ensembles conservés localement par utilisateur et par projet (Dexie) ; références aux calques par identifiant : un identifiant disparu est retiré au chargement, avec un message. Une vue figée (lot 5) peut enregistrer l'ensemble utilisé et porte alors la révision dont elle est issue (R11). |
| Résultats | Plan filtré par l'ensemble appliqué ; liste d'ensembles de l'utilisateur ; rien n'est ajouté au journal, aux quantités ni aux exports. |
| Cas limites | **Affichage.** Ensemble vide : plan vide avec message ; nom en double refusé localement ; calque supprimé par un autre utilisateur : identifiant retiré de l'ensemble, message au chargement ; calque masqué dans le modèle pendant l'application d'un ensemble : il disparaît du plan, l'ensemble le signale. |
| | **Concurrence et réseau.** Sans objet : aucune requête, donc ni 409, ni requête répétée, ni commande dans la file Dexie ; deux utilisateurs peuvent appliquer des ensembles différents sans effet l'un sur l'autre. Hors ligne : inchangé. |
| Compatibilité | Import P.118 : aucun level CAO ; les 6 niveaux sont des `niveau` (étages, DA-05-04) et les 20 calques des `calque` (DA-05-01) : aucune conversion entre les trois notions. DXF et IFC : aucun équivalent exporté (un ensemble n'est pas un calque). Traduction d'un fichier DGN (levels) : gérée par M17, hors de cette fiche. |
| Validation | **Unité** (`packages/atelier-model/src/affichage.test.ts`) : fonction pure de visibilité effective : un calque masqué dans le modèle reste masqué quel que soit l'ensemble ; ensemble appliqué à l'état importé de P.118 : liste d'objets visibles attendue ; état du modèle strictement identique avant et après (aucune révision). |
| | **API** (`apps/api/src/routes/atelier-commands.test.ts`) : aucune route ; un lot dont une commande porte un champ d'ensemble d'affichage est refusé (400 avec `chemin`). |
| | **e2e** (`apps/web/e2e/scenarios/05-atelier.mjs`, bloc « Organisation · ensembles d'affichage ») : copie de travail de P.118 : enregistrer un ensemble, l'appliquer, recharger la page (ensemble restauré), second navigateur non affecté ; aucune requête de commande émise ; révision identique ; aucun libellé n'emploie « niveau » pour un ensemble (contrôle de texte). |
| Règles métier | Aucune règle réglementaire. R10 : un ensemble d'affichage est un paramètre d'affichage, jamais du modèle ; la part partagée de la visibilité est `visible` du calque (décision en DA-05-01). R3 : aucune élévation, hauteur ni étage n'est déduit d'un ensemble. |
| Extensions à spécifier | Partage d'un ensemble avec l'équipe (lot 5 ou 7) ; association d'un ensemble à un étage ; synchronisation entre appareils d'un même utilisateur ; états de calques versionnés. |

# DA-07-02 — Doors / Portes — module M05 → Atelier — lot 3a

**État : prototype (lot 3a)** (à spécifier → spécifiée → prototype → vérifiée → disponible). Preuve liée : recette `apps/web/e2e/atelier-nouveau.mjs`, tests `apps/web/src/modules/atelier/nouveau/nouveau.test.ts` et `packages/atelier-model/src/commandes/commandes.test.ts` ; compte rendu `lots/lot-3a.md`.

| Champ | Contenu |
| --- | --- |
| Identité | DA-07-02 (M05, étape cible P1). Une porte est un objet de classe `porte` (building.architecture), ouverture hébergée par un mur : elle suit le modèle et les commandes `ouverture.*` décrits en DA-07-04, qui porte la mécanique commune (emprise, déplacement, scission de l'hôte). Sous-exigences : -a poser (`ouverture.poser`, classe `porte`) ; -b modifier (`ouverture.modifier`) ; -c déplacer le long de l'hôte (`ouverture.deplacer`) ; -d supprimer (`ouverture.supprimer`). Référence de comportement : prototype, les 84 portes de P.118 (`hostWallId`, `t`, `width`, `height`, `sill`, `mark`). |
| Situation utilisateur | Poser une porte dans un mur à une position et avec des dimensions choisies, la repérer, la déplacer le long de son mur et la voir suivre son mur. |
| Entrées et unités | `murHoteId` ; `position` : `t` ∈ [0, 1] le long de l'axe, ou distance saisie en m depuis l'extrémité choisie (`distance` dérivée) ; `largeur`, `hauteur`, `allege` `{ value, unit: "m" }` (un seuil au sol est une allège saisie à 0 m, jamais supposée) ; `repere` ; `typeId` (définition du catalogue). |
| | Unité autre que m refusée (T03). Aucune dimension, allège, repère ni type par défaut (R3) : les valeurs d'exemple de la palette (UX4) ne pré-remplissent aucun champ. Sens d'ouverture, battement et ferrage ne sont pas des paramètres canoniques au lot 3a (extension) ; le symbole en plan est dérivé (R15), jamais saisi. |
| Comportement | **Cycle.** Outil « Porte » → survol d'un mur (hôte candidat surligné) → paramètres → position par clic accroché ou distance saisie → aperçu avec distances aux extrémités du mur et aux ouvertures voisines → contrôle → validation ; Échap annule sans commande. |
| | **Commandes et contrôles.** `ouverture.poser` (classe `porte`), `ouverture.modifier`, `ouverture.deplacer`, `ouverture.supprimer` ; contrôles de DA-07-04 : emprise dans l'axe de l'hôte à la tolérance de longueur (DA-01-01), recouvrement, hauteur du mur. Aucune règle de largeur de passage ni de hauteur de porte n'est appliquée (R3). |
| | **Suivre l'hôte (R12).** Mur déplacé : la porte suit, `t` inchangé. Mur scindé : porte réaffectée, `t` recalculé, position inchangée ; scission dans son emprise refusée. Mur raccourci : emprise hors du mur, porte « à réparer » (déplacer, supprimer, détacher), jamais déplacée en silence. Cotations sur `ouverture:centre` : référence conservée, valeur recalculée. |
| | **Palette (UX2) et aide (UX4).** « porte » ; synonymes « door » ; actif si un mur est survolé ou sélectionné ; exemple court : poser une porte à 1,00 m de l'extrémité d'un mur (exemple, jamais valeur par défaut). |
| Données et dépendances | Classe `porte` ; relation `heberge-par` → `mur` (inverse `heberge`) ; caractéristique `ouverture:centre` ; `typeId` vers une définition. Symbole en plan et vide en 3D dérivés ; événement `atelier.commande.validee` : vues, quantités (portes par type, lot 5) et bilan Harmonie « à recalculer » (R11, T07) ; microversion +1. |
| Résultats | Porte posée, modifiée, déplacée ou supprimée ; `distance` dérivée affichée ; effets dans le panneau des modifications (références à réparer, quantités à recalculer) ; inverse = valeurs précédentes enregistrées. |
| Cas limites | **Hôte et géométrie.** `murHoteId` jamais existé → 400 avec `chemin` ; hôte supprimé par autrui depuis `baseRevision` → 409 avec `conflits[].objetId` ; porte importée sans hôte : conservée avec le problème « hôte introuvable ». Largeur ≤ 0 ; mur plus court que la largeur ; emprise hors du mur hôte : refus avec la plage de `t` admise ; mur de hauteur « non évaluée » : contrôle vertical « non évalué », porte posée ; repère en double : signalé, jamais renuméroté. |
| | **Concurrence, réseau, droits.** `baseRevision` dépassée et porte ou hôte modifié depuis → 409, résolution explicite ; même `requestId` → aucune seconde révision (T06) ; hors ligne : réducteur local, file Dexie, rejeu dans l'ordre, brouillon si incompatible ; 403 motivé, 404 sans accès, 423 pendant une réservation d'autrui (R13). |
| Compatibilité | Import P.118 (section 6) : 84 `porte` hébergées, relation `heberge-par` complète ; `t` conservé, `distance` dérivée, `sill` → `allege`, `mark` → `repere` ; hôte absent → objet créé et problème « hôte introuvable », jamais supprimé. |
| | IFC (annexe C, lot 6) : `IfcDoor` + `IfcOpeningElement`, `IfcRelVoidsElement` (mur → vide), `IfcRelFillsElement` (vide → porte) ; `largeur` et `hauteur` exportées en dimensions de la porte (attributs exacts validés au lot 6). DXF : aucune sortie propre. |

R3 : aucune dimension par défaut, valeurs absentes « non évaluées ». R9 : tout par commande ; R10 : niveau actif et sélection hors révision ; R12. |

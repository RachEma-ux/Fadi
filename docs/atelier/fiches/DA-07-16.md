# DA-07-16 — Spaces / Espaces — module M05 → module Fadi Atelier — lot 3a

**État : prototype** (à spécifier → spécifiée → prototype → vérifiée → disponible). Preuve liée : `creer.espace` par contour fermé, nom et catégorie saisis en texte, « Espace n » par défaut (`apps/web/src/modules/atelier/objets/outils/espaces.ts`), surface calculée dans l'inspecteur (`apps/web/src/modules/atelier/objets/inspecteur.ts`) ; tests `apps/web/src/modules/atelier/objets/espaces.test.ts` « contour fermé sur le premier point, nom et catégorie saisis en texte (D-038) », « sans nom : « Espace n » libre du niveau ; moins de trois sommets : rien n'est créé » ; PR #60. Reste : -a création depuis une esquisse fermée ou une proposition de `piece.detecter` ; -b modification du contour ; -c suppression (aucun outil de suppression dans le nouvel Atelier (`plan2d/controleur.ts` ne transmet Retour arrière / Suppr qu'à l'outil actif)) ; -d conversion espace ↔ pièce ; étapes « 05-atelier.mjs » du champ Validation (ancien Atelier) non reprises dans `apps/web/e2e/scenarios/14-nouvel-atelier.mjs` et « 04-programmation.mjs ».

| Champ | Contenu |
| --- | --- |
| Identité | **DA-07-16** « Spaces » (Exigences V4, annexe B.8, module M05, étape cible P1 ; critère commun B.8). Classe `espace` de l'ontologie `building.architecture` (cahier §5.2 : `polygones`, `nom`, `categorie` ; contenu dans une zone). Interprétation retenue : un **espace** est une surface fonctionnelle nommée qui n'est pas une pièce codée — partie de local, palier, réserve d'adaptation, bloc sanitaire dessiné à l'intérieur d'une pièce — distincte de la pièce (DA-07-15, codée, délimitée par des murs) et de la zone (DA-07-17, regroupement). Sous-exigences : **DA-07-16-a** créer un espace par contour (dessiné, esquisse fermée, proposition de `piece.detecter`) ; **-b** modifier nom, catégorie, contour ; **-c** supprimer ; **-d** convertir un espace en pièce (ou l'inverse) par une commande explicite ; **-e** aire calculée ; **-f** liaison au programme conservée ; **-g** importer les espaces de P.118. Fiches liées : DA-07-15, DA-07-17, DA-06-07. |
| Situation utilisateur | L'architecte délimite une surface utile au projet (un palier de manutention, une réserve, un bloc sanitaire dans une pièce) sans en faire une pièce codée, la nomme, lit sa surface et la relie si besoin au programme ; plus tard il peut la promouvoir en pièce. |
| Entrées et unités | `niveauId` ; `polygones` (fermés, avec trous, points `{ x, y, frame: "local", unit: "m" }`) ; `nom` ; `categorie` (texte, facultatif) ; aire calculée dérivée (m², jamais saisie). Aucune valeur par défaut (R3). |
| Comportement | Outil Espace → contour → aperçu (remplissage du calque) → contrôle (contour fermé et simple, aire > 0,01 m² **proposée**, niveau existant, repère `local`) → validation = `espace.creer` ; `espace.modifier`, `espace.supprimer` (famille `espace.*` de l'annexe B, noms exacts figés par L1.2). Un espace peut chevaucher une pièce (bloc sanitaire dans un local) : admis, sans découpe implicite de la pièce. **Convertir** en pièce = un lot atomique `espace.supprimer` + `piece.creer` (même contour, code saisi par l'utilisateur), liaison au programme reportée et listée avant accord ; inverse disponible. |
| Données et dépendances | Occurrence `espace` (`atelier_objects`) ; relation `contient` depuis une zone (DA-07-17) ; liaison `programme` : la Programmation lie aujourd'hui des espaces programmés aux **tracés de pièces** du prototype (`roomLinks`, identifiants `niveau\|tracé`), que ces tracés portent un code ou non (`analyseRooms` les lit tous) — les espaces issus de tracés sans code doivent donc pouvoir porter cette liaison comme les pièces (écart au cahier §5.2, où `programme` n'est cité que pour `piece` : signalé au chef de projet). Quantités (L1.3) : surfaces par espace et par niveau. Consommateurs (cahier §5.6) marqués « à recalculer » par `atelier.commande.validee`. |
| Résultats | Espaces nommés avec aire calculée ; journal, révision `n + 1`. |
| Cas limites | Contour ouvert, auto-intersecté ou d'aire nulle → refus 400. Repère non `local` → refus (R5). Conversion en pièce avec un code déjà utilisé sur le niveau → refus. Espace hors de toute dalle → admis, signalé (pas de règle implicite). Deux comptes → 409 ; requête répétée → une révision (T06) ; hors ligne → file Dexie. |
| Compatibilité | **Import P.118** (cahier §6 : tracés `role = room` sans code correspondant → `espace`) : 33 espaces — « Adaptation périphérique » (17 : 3 par niveau, 2 en mezzanine), « MC · Palier de manutention » (6, un par niveau), blocs « Sanitaires Femmes / Hommes … » (10 : 2 par niveau de rdc à r3) ; calque `Espaces` ; trous conservés ; propriétés importées `sanitaryBlock`, `designRevision` (DA-06-07) ; `name` → `nom` sans renommage. Le rattachement par code dépend de la règle de DA-07-15 (préfixe du nom) : tout changement de cette règle change ce décompte, à re-tester. **IFC 4.3** (lot 6, annexe C) : `IfcSpace` ; distinction pièce / espace en IFC (type prédéfini ou propriété) **non évaluée**, à fixer au lot 6. |
| Validation | **Unité `packages/atelier-model`** : créer / modifier / supprimer avec inverse exact ; conversion espace → pièce et retour, liaison au programme conservée ; aire calculée reproductible ; import P.118 : 33 espaces (ss 4, rdc 6, mezz 5, r1 6, r2 6, r3 6), aucun tracé de rôle `room` perdu ni compté deux fois (41 rattachés aux pièces + 33 espaces = 74). **API** : idempotence, 409, 403. **Scénario `05-atelier.mjs`** : sur P.118, sélectionner un « Palier de manutention », lire son aire, le renommer, annuler ; `04-programmation.mjs` : sommes du cas P.118 inchangées (1 366,02 / 567,49 / 2 932,26 m², preuve actuelle de la matrice de migration) après import dans le modèle typé (lot 4). |
| Règles métier | Aucune règle d'usage ni de surface réglementaire (R3) ; les mentions « dont 1 adapté » des noms importés ne valent pas contrôle d'accessibilité. |
| Extensions à spécifier | Espaces techniques (MEP, hors périmètre), espaces sur plusieurs niveaux, hauteur propre. **Question au maître d'ouvrage** : l'interprétation « espace = surface nommée non codée » vous convient-elle, ou souhaitez-vous que les blocs sanitaires de P.118 deviennent des pièces (conversion explicite après import) ? |

| Identité | **DA-05-04** « Stories » (Exigences V4.1, annexe B.6, module M05, P1 ; critère B.6 : « Identités, occurrences et références stables lors de la réutilisation »). Classe `niveau` de l'ontologie `building.architecture` (cahier §5.2 : `nom`, `elevation` (m, décimal), `hauteur` (m), `ordre` ; relation « contient les objets du niveau »). Sous-exigences : **DA-05-04-a** créer un niveau ; **-b** modifier nom, altitude, hauteur, ordre ; **-c** supprimer un niveau (vide, ou avec destination des objets) ; **-d** changer de niveau actif (affichage, R10) ; **-e** importer les 6 niveaux de P.118. Tâches : L1.1, L1.2, L1.4, L3a.1, L3a.3 (« étages »). Fiches liées : DA-07-01 (`niveauHaut` des murs), DA-07-10 (escalier, `relie` deux niveaux), DA-05-03 (levels CAO), DA-05-12 (objets). |
| Situation utilisateur | L'architecte structure le bâtiment en étages (sous-sol, rez, mezzanine, étages courants), règle leurs altitudes et hauteurs, passe de l'un à l'autre pour dessiner. Résultat : une liste ordonnée de niveaux avec altitudes décimales exactes ; chaque objet appartient à un niveau ; changer de niveau actif ne crée aucune révision. |
| Entrées et unités | `nom` (texte non vide, unique dans le projet, **proposé**) ; `elevation` `{ value, unit: "m" }` (décimal, négatif permis, altitude relative au zéro du projet en repère `local` — **hypothèse** : le zéro altimétrique du projet n'est pas une altitude géographique ; toute liaison à une altitude `geographic` passe par une conversion explicite, hors de cette fiche) ; `hauteur` `{ value, unit: "m" }` > 0 ; `ordre` (entier ≥ 0, unique). Aucune hauteur d'étage par défaut tirée de P.118 (3,2 ou 3,4 m) ni d'une norme (R3) : champ vide à remplir, ou dernière valeur saisie par l'utilisateur dans la session. Niveau actif : identifiant (état d'affichage). |
| Comportement | Commandes de l'annexe B : `niveau.creer` (`params: { nom, elevation, hauteur, ordre }`), inverse `niveau.supprimer` ; `niveau.modifier` (`cibles: [niveauId]`, paramètres modifiés), inverse `niveau.modifier` avec les anciennes valeurs ; `niveau.supprimer` (`params: { niveauDestinationId? }`), inverse `niveau.creer` + réaffectation inverse (même identifiant). Annexe B : « supprimer = verrou logique (lot 7) ; refus si des objets existent sans destination ».<br>Cycle UX3 : navigateur (repère « Niveaux ») → inspecteur → **aperçu** (pour une modification d'altitude ou de hauteur : liste des objets dont la géométrie dérivée change — murs à `niveauHaut`, escaliers `relie`, dalles) → contrôle → validation.<br>**Modifier l'altitude** : les objets du niveau suivent (leur géométrie est relative au niveau) ; les objets qui en dépendent (mur dont `niveauHaut` = ce niveau, escalier qui le relie) sont **recalculés ou signalés**, jamais déplacés silencieusement (exemple DA-07-10 de l'Exigences) : un escalier dont la hauteur à franchir ne correspond plus aux paramètres est listé « à vérifier » dans le panneau des problèmes.<br>**Niveau actif** : sélecteur de la zone de travail ; état d'affichage local, jamais une commande, révision inchangée (R10 ; `ui.activeLevel` de P.118 n'est pas importé dans le modèle). |
| Données et dépendances | `atelier_objects` (`ontology = "building.architecture"`, `class = "niveau"`, `params`) ou table dédiée selon L2.1 ; `atelier_objects.level_id` des autres objets. Relations : `contient` (niveau → objets) ; `relie` (escalier → deux niveaux) ; référence `niveauHaut` (mur). Modules : `atelier-model` (réducteurs ; contrôle d'ordre et d'altitudes), `core-geometry` (géométrie dérivée en altitude), API (`GET /model/niveaux/:niveauId`, chargement par niveau), rendu 3D (scène par niveau), Documents (plans par niveau marqués « à recalculer » ; aperçu conceptuel et bilan Harmonie périmés par `atelier.commande.validee`). Microversion `model_revision + 1`. |
| Résultats | Niveau créé / modifié / supprimé ; objets réaffectés le cas échéant ; problèmes « à vérifier » listés ; plans, coupes, quantités par niveau marqués « à recalculer » ; journal, révision `n + 1`. Navigateur : niveaux triés par `ordre`, altitude et hauteur affichées (m, 2 décimales), effectif d'objets. |
| Cas limites | Nom vide ou en double → 400. `hauteur` ≤ 0, unité non métrique, valeur non finie → 400 `{ chemin, message }` (T03). `ordre` en double → 400. Altitudes non croissantes avec l'ordre → **avertissement** (problème listé), pas un refus (**proposé, à confirmer**) ; `elevation + hauteur` différent de l'altitude du niveau suivant (au-delà de `tolCoincidence`) → information au panneau, aucun ajustement automatique. Suppression d'un niveau non vide sans destination → 400 listant les objets ; d'un niveau cité comme `niveauHaut` ou relié par un escalier → refus listant les dépendants. Suppression du dernier niveau → refus (**proposé**). Objet créé sur un niveau supprimé entre l'aperçu et l'envoi → 409 « niveau introuvable ». Deux utilisateurs modifient le même niveau → 409. Requête répétée → T06 ; lecteur → 403 ; réservation → 423. Hors ligne : commandes exécutables localement, rejouées. |

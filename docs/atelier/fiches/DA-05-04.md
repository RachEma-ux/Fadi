# DA-05-04 — Stories / Étages (niveaux du bâtiment) — module M05 → Atelier — lot 3a

Preuve liée : recette `apps/web/e2e/atelier-nouveau.mjs`, tests `apps/web/src/modules/atelier/nouveau/nouveau.test.ts` et `packages/atelier-model/src/commandes/commandes.test.ts` ; compte rendu `lots/lot-3a.md`.

| Champ | Contenu |
| --- | --- |
| Identité | DA-05-04 (M05, étape cible P1). Un étage est un `niveau` du modèle (classe `niveau`, building.architecture), à distinguer d'un level CAO (DA-05-03, affichage). Sous-exigences : -a créer un niveau ; -b modifier nom, élévation, hauteur, ordre ; -c supprimer (suppression logique, lot 7). Référence de comportement : prototype, les 6 niveaux de P.118 à altitudes décimales. |
| Situation utilisateur | Définir les étages du bâtiment, leur altitude et leur hauteur, auxquels tout objet est rattaché, et passer de l'un à l'autre pour dessiner. |
| Entrées et unités | `niveau` : `nom`, `elevation` `{ value, unit: "m" }` (décimal, négatif admis, aucun arrondi), `hauteur` `{ value, unit: "m" }` (> 0 ; « non évaluée » si absente), `ordre` (entier) ; `niveauId` stable. Unité autre que m refusée (T03). Niveau actif et niveaux visibles : paramètres de session (R10). |
| Comportement | **Cycle.** Panneau Étages (liste verticale triée par `ordre`) → sélection d'un niveau ou « Nouveau niveau » → paramètres (nom, élévation, hauteur, rang) → aperçu en coupe schématique avec les élévations → contrôle → validation ; Échap annule sans commande. |
| | **Commandes.** `niveau.creer`, `niveau.modifier`, `niveau.supprimer` (annexe B). Insertion à un rang : les `ordre` suivants sont décalés dans le même lot, effets listés. `niveau.supprimer` : refus tant que des objets existent sans destination (liste fournie) ; au lot 3a aucune réaffectation automatique ; suppression logique par verrou au lot 7. |
| | **Sans correction silencieuse (R3, R12).** L'aperçu signale sans jamais corriger : `ordre` incohérent avec l'ordre des élévations ; recouvrement de deux niveaux ; `hauteur` absente (aucune valeur déduite de l'écart des élévations) ; murs dont `niveauHaut` désigne ce niveau (hauteur dérivée modifiée par un changement d'élévation) ; écart entre la différence d'élévations et la `hauteurAFranchir` d'un `escalier` qui relie ce niveau (contradiction affichée avec les valeurs retenues, voir DA-07-10). |
| | **Palette (UX2) et aide (UX4).** « niveau », « étage » ; synonymes « story », « niveau de bâtiment » ; exemple court : ajouter un étage à l'élévation 3,00 m (exemple, jamais valeur par défaut). |
| Données et dépendances | Classe `niveau` ; relation `contient` (objets du niveau) ; `niveauId` des `dalle`, `toiture`, `escalier` (`niveauDepartId`, `niveauArriveeId`) et des objets de dessin, `niveauHaut` des `mur`. Les coordonnées x, y ne changent pas avec l'élévation ; altitudes absolues dérivées. Événement de commande validée : vues par niveau, quantités et bilan Harmonie « à recalculer » (R11, T07) ; microversion +1. |
| Résultats | Niveau créé, modifié ou supprimé ; liste d'étages ordonnée ; effets (objets dont l'altitude absolue change, escaliers à contrôler) dans le panneau des modifications ; inverse = valeurs précédentes. |
| Cas limites | **Valeurs.** Élévation non numérique, unité ≠ m, `hauteur` ≤ 0, nom vide ou en double (casse ignorée) refusés ; deux niveaux de même élévation admis mais signalés ; modification d'élévation d'un niveau qui porte des objets : l'aperçu liste les objets dont l'altitude absolue change, rien d'autre ne bouge. |
| | **Concurrence et réseau.** `baseRevision` dépassée et niveau modifié ou supprimé depuis → 409 avec `conflits[].objetId` et état serveur ; objet créé par autrui dans un niveau que je supprime : refus au rejeu ; même `requestId` → une seule révision (T06). Hors ligne : réducteur local, file Dexie, rejeu dans l'ordre, brouillon si incompatible. Niveau actif supprimé par autrui : bascule vers le niveau voisin avec message (affichage). 403 / 404 / 423 selon R13. |
| Compatibilité | Import P.118 : 6 `niveau` avec élévations décimales conservées exactement (aucun arrondi, R7). IFC : `IfcBuildingStorey` (nom, élévation) à l'import et à l'export (annexe C, lot 6) ; aucune altitude absolue par rapport au site n'est inventée. DXF : pas d'étage natif ; une vue de plan par niveau (lot 5). |
| Validation | **Unité** (`packages/atelier-model/src/commandes/niveau.test.ts`) : création ; `elevation` décimale conservée exactement après aller-retour de sérialisation ; unité ≠ m refusée ; `hauteur` ≤ 0 refusée ; insertion à un rang : `ordre` suivants décalés et effets listés ; suppression d'un niveau non vide refusée avec la liste ; changement d'élévation : objets et escaliers listés, aucun paramètre d'objet modifié ; inverse restitue l'état. |
| | **API** (`apps/api/src/routes/atelier-commands.test.ts`) : `niveau.creer` → 200, révision +1, `effets` ; élévation en pieds → 400 avec `chemin` ; suppression d'un niveau non vide → 400 avec la liste ; même `requestId` → même réponse ; `baseRevision` périmée et niveau modifié → 409 ; rôle lecture → 403. |
| | **e2e** (`apps/web/e2e/scenarios/05-atelier.mjs`, bloc « Organisation · étages ») : copie de travail de P.118 : 6 niveaux listés avec les élévations du rapport d'import ; changer de niveau actif : révision inchangée (R10) ; ajouter un niveau, annuler, rétablir ; second navigateur à la même révision. |
| Règles métier | Aucune règle réglementaire (hauteur libre, nombre de niveaux : non fournis). R3 : aucune élévation ni hauteur par défaut ; valeurs absentes « non évaluées ». R10 : niveau actif et niveaux visibles ne touchent pas la révision. |
| Extensions à spécifier | Réaffectation d'objets vers un autre niveau à la suppression (dépend de l'extension de DA-02-01) ; altitude absolue et repère altimétrique du site (R5) ; copie d'un niveau avec son contenu ; suppression logique et verrou (lot 7). |

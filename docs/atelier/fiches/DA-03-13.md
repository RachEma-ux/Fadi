# DA-03-13 — Architectural modeling / Modélisation architecturale — module M05 → Atelier — lot 3a

**État : prototype (lot 3a)** (à spécifier → spécifiée → prototype → vérifiée → disponible). Preuve liée : recette `apps/web/e2e/atelier-nouveau.mjs`, tests `apps/web/src/modules/atelier/nouveau/nouveau.test.ts` et `packages/atelier-model/src/commandes/commandes.test.ts` ; compte rendu `lots/lot-3a.md`.

| Champ | Contenu |
| --- | --- |
| Identité | DA-03-13 (M05, étape cible P1). Capacité d'ensemble de la modélisation du bâtiment : niveaux, murs, ouvertures, dalles, escaliers, pièces, espaces, zones, poteaux (toitures : lot 5) comme objets typés reliés entre eux. Sous-exigences : -a objets et relations du bâtiment ; -b cohérence signalée ; -c représentations en plan et en 3D. Contrôle commun de la section : représentation identifiée, géométrie valide dans les tolérances du cas. Le comportement propre à chaque classe est dans sa fiche (par exemple DA-07-10 pour l'escalier) ; cette fiche en fixe le contrat commun. |
| Situation utilisateur | Construire et corriger le modèle d'un bâtiment par ses éléments (étages, murs, portes, fenêtres, dalles, escaliers, pièces), en sachant ce qui dépend de quoi et ce qui est incohérent. |
| Entrées et unités | Classes du tableau 5.2 (`niveau`, `mur`, `porte`, `fenetre`, `ouverture`, `dalle`, `escalier`, `piece`, `espace`, `zone`, `poteau`) ; paramètres `{ value, unit }` (m, m², °), points `{ x, y, frame: "local", unit: "m" }` ; `niveauId`, `calqueId`. Commandes : `niveau.*`, `mur.*`, `ouverture.*`, `dalle.*`, `escalier.*`, `piece.*`, `espace.*`, `zone.*`, `poteau.*` (annexe B). |
| Comportement | **Cycle.** Choisir l'outil ou la commande (palette, UX2) → niveau et calque actifs → paramètres (saisie, clic, DA-02-15, DA-02-16) → aperçu fantôme avec valeurs dérivées → contrôle → validation ; Échap annule sans commande. Chaque classe suit ce cycle dans sa propre fiche. |
| | **Relations.** `heberge` (mur → ouvertures, maintenue par `ouverture.*`), `joint-a` (murs, dérivée), `delimite` et `delimitee-par` (mur et pièce, dérivées), `porte` (dalle → objets posés, dérivée), `relie` (escalier → deux niveaux), `contient` (niveau, zone). Les relations dérivées sont recalculées, jamais éditées ; les relations maintenues par commande ne changent que par commande. |
| | **Cohérence.** Le panneau des problèmes liste, sans jamais corriger en silence : ouverture hors emprise de son mur hôte, ouverture « à réparer » (R12), mur sans hauteur ni niveau haut (« non évalué »), pièce dont la délimitation ne correspond plus à ses murs, escalier dont les valeurs se contredisent (DA-07-10), objet d'un niveau supprimé. Une détection de pièces est une proposition (`piece.detecter`), jamais imposée. |
| | **Représentations.** Plan 2D (lot 3a) et 3D (lot 3b) dérivés des paramètres (DA-03-09, R15) ; chaque objet porte sa représentation, son moteur et son empreinte ; aucune donnée réglementaire ou structurelle n'est ajoutée à un objet (R3). |
| Données et dépendances | Toutes les classes `building.architecture` du tableau 5.2 et `poteau` (`building.structure`) ; relations ci-dessus ; `definition` pour les types (DA-05-14, DA-05-15). Événement de commande validée : vues, quantités et bilan Harmonie « à recalculer » (R11, T07) ; microversion +1. |
| Résultats | Modèle d'un bâtiment cohérent : objets typés, relations, panneau des problèmes, représentations 2D (puis 3D) identifiées ; inverse par commande. |
| Cas limites | **Cohérence.** Objet sur un niveau inexistant ou supprimé : refusé ; ouverture posée hors du mur : refusée à l'aperçu (emprise) ; mur dupliqué ou superposé : signalé, jamais fusionné ; pièce sans murs fermés : proposition seulement ; escalier entre deux niveaux sans `hauteurAFranchir` : « non évaluée ». |
| | **Concurrence et réseau.** `baseRevision` dépassée et objet ou niveau modifié ou supprimé depuis → 409 avec `conflits[].objetId` ; un objet supprimé par autrui ne réapparaît pas, ses références passent « à réparer » (R12) ; même `requestId` → une seule révision (T06). Hors ligne : réducteur local, file Dexie, rejeu dans l'ordre, brouillon si incompatible. 403 / 404 / 423 selon R13. |
| Compatibilité | Import P.118 (R7) : 6 niveaux, 220 murs (210 ouvertures hébergées : 84 portes, 126 fenêtres), 32 escaliers, 6 dalles, 45 pièces, 120 poteaux ; chaque objet a une destination dans le modèle typé et figure au rapport nominatif. IFC (lot 6) : correspondance classe Fadi → classe IFC fixée à l'annexe C (par exemple `IfcWall` pour `mur`), nommée au rapport d'échange ; une classification posée par l'utilisateur (DA-06-08) prime ; rien n'est deviné. DXF : vues de plan (lot 5). |
| Validation | **Unité** (`packages/atelier-model/src/coherence.test.ts`) : état importé de P.118 : comptes par classe = rapport ; ouverture hors emprise listée ; pièce désalignée listée ; relations dérivées recalculées après `mur.modifier` ; aucune correction automatique (état identique après contrôle) ; inverse restitue. |
| | **API** (`apps/api/src/routes/atelier-commands.test.ts`) : `mur.tracer`, `ouverture.poser`, `dalle.creer` sur la copie → 200, révision +1, `effets` ; niveau inexistant → 400 avec `chemin` ; même `requestId` → même réponse ; `baseRevision` périmée et objet supprimé → 409. |
| | **e2e** (`apps/web/e2e/scenarios/05-atelier.mjs`, bloc « Objets · bâtiment ») : copie de travail de P.118 : les comptes du rapport d'import s'affichent par niveau ; mur `EX118-mezz-W-009` et porte `EX118-mezz-D-001` : relation d'hébergement lisible ; tracer un mur puis y poser une porte, annuler, rétablir ; panneau des problèmes cohérent ; second navigateur à la même révision. |
| Règles métier | Aucune règle réglementaire n'est appliquée : surfaces, hauteurs, dégagements, accessibilité et incendie ne sont ni fournis ni contrôlés ici, et rien n'est présenté comme conforme (R3). R9 : toute modification par une commande. R12 : références incertaines « à réparer ». R15 : une seule géométrie canonique. |

| Situation utilisateur | L'architecte dessine un contour courbe libre (bord d'aménagement paysager, mobilier, banquette, tracé de cheminement) en posant quelques points ; il ajuste la forme en déplaçant ces points et obtient une courbe lisse, mesurable (longueur, aire si fermée), réutilisable comme contour. |
| Entrées et unités | `niveauId` ; `points` `{ x, y, frame: "local", unit: "m" }[]` (≥ 2 pour une spline ouverte de degré 1 ; ≥ `degre + 1` sinon) ; `mode` ∈ {`controle`, `passage`} ; `degre` (entier, 3 par défaut, **proposée, à confirmer** ; 2 et 3 admis) ; `ferme` (booléen) ; `calqueId` ; `nom`. **Recommandation** : le paramètre canonique est la liste de points avec son `mode` ; pour le mode `passage`, l'interpolation (Catmull-Rom centripète, **hypothèse**, à confirmer par L1.5) est un calcul dérivé de `core-geometry`, versionné (moteur `fadi-geometry`). |
| Comportement | Outil « Spline » (palette, synonymes « spline », « courbe », « curve », « Bézier ») → mode (contrôle / passage), degré, fermeture → **aperçu** de la courbe et du polygone de contrôle, longueur (m) → validation (`Entrée`, double-clic, clic sur le premier point pour fermer) ; `Échap` abandonne. Commande (annexe B) : `{ type: "esquisse.spline", params: { niveauId, points, mode, degre, ferme, calqueId } }`, label « Tracer une spline ». Préconditions : niveau existant ; calque non verrouillé ; repère `local` ; points consécutifs distincts (> `tolCoincidence`) ; nombre de points suffisant pour le degré. Inverse : `esquisse.supprimer`. Modification : `esquisse.modifier` (`points`, `degre`, `ferme`, `mode`), inverse = anciens paramètres. Conversion de mode (contrôle ↔ passage) : modifie la forme, annoncée dans l'aperçu, jamais silencieuse. |
| Données et dépendances | Classe `esquisse.spline` (ontologie `drawing`) ; `atelier_objects.params` ; représentation `plan-2d` `parametrique` ; facettisation d'affichage dérivée par `core-geometry`, flèche maximale `flecheAffichage` = 0,001 m (**proposée, à confirmer**) ; longueur et aire calculées numériquement avec la même tolérance. Caractéristiques proposées pour le lot 5 : `esquisse:point[i]`, `esquisse:debut`, `esquisse:fin` (**recommandation**, L1.1). Événement `atelier.commande.validee` → vues « à recalculer ». |
| Résultats | Courbe visible au plan, navigateur « Esquisse » ; inspecteur : nombre de points, degré, mode, fermée, longueur (dérivée, précision affichée), aire si fermée ; journal ; révision + 1. |
| Cas limites | Points insuffisants pour le degré → refus dans l'aperçu, 400 côté serveur. Points consécutifs confondus → fusionnés dans l'aperçu ; le serveur refuse. Tous les points colinéaires → accepté (courbe droite), signalé. Spline fermée qui se recoupe → acceptée, signalée « auto-intersection » (refusée par DA-04-01 et DA-01-11). `degre` hors {2, 3} → 400. Unité / repère incompatibles → 400 (T03, R5). Calque verrouillé → 400 ; niveau supprimé → 409 ; 403 / 423. Grand nombre de points : borné par l'enveloppe ≤ 1 Mo (cahier §8). Hors ligne : file Dexie, rejeu idempotent (T06). |
| Compatibilité | IFC 4.3 : omis et listé au rapport (T13). DXF (lot 5) : `SPLINE` ou polyligne facettée selon la fiche DA-22-03 (à décider ; facettée = perte déclarée au rapport). Import P.118 : aucune spline dans les données (tracés polygonaux uniquement). |
| Validation | **Unité** (`packages/atelier-model/src/commandes/esquisse.test.ts`) : spline de contrôle degré 3 bornée sur (0;0) (1;0) (2;0) (3;0) → courbe sur l'axe x, longueur 3 m à `tolCoincidence`, extrémités interpolées ; spline de passage par (0;0) (1;1) (2;0) → passe par les trois points à `tolCoincidence` ; refus : 3 points en degré 3 ouvert, points confondus, degré 4 ; modifier puis inverse → points identiques bit à bit. **core-geometry** (`packages/core-geometry/src/spline.test.ts`, nom proposé) : écart max entre facettisation et courbe évaluée ≤ `flecheAffichage` ; même entrée → même sortie (moteur versionné). **Scénario** `05-atelier.mjs` : spline de 4 points tracée, un point déplacé (DA-02-14), annuler / rétablir, second navigateur identique. |

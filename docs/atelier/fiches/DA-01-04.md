# DA-01-04 — Rectangles / Rectangles — module M01 → Atelier — lot 3a

**État : prototype (lot 3a)** (à spécifier → spécifiée → prototype → vérifiée → disponible). Preuve liée : recette `apps/web/e2e/atelier-nouveau.mjs`, tests `apps/web/src/modules/atelier/nouveau/nouveau.test.ts` et `packages/atelier-model/src/commandes/commandes.test.ts` ; compte rendu `lots/lot-3a.md`.

| Champ | Contenu |
| --- | --- |
| Identité | DA-01-04 (M01, étape cible P1). Sous-exigences : -a rectangle par deux coins ; -b rectangle par dimensions saisies (`esquisse.rectangle`). Référence de comportement : prototype, outil « Rectangle » (deux coins, côtés parallèles aux axes, « Deux dimensions non nulles requises », polygone fermé de 4 points nommé « Rectangle »). |
| Situation utilisateur | Esquisser une emprise, un local, un meuble ou un profil rectangulaire, éventuellement tourné, dont les dimensions restent des valeurs lisibles et modifiables. |
| Entrées et unités | `esquisse.rectangle` : `a`, `b` (coins opposés, points locaux, m) et `angle` (°, orientation des côtés : 0 = côtés parallèles aux axes locaux ; les côtés suivent les axes d'angle `angle` passant par `a`). Longueur et largeur en sont déduites (signées, en m). Communs : `niveauId`, `calqueId`. |
| | Saisie : deux coins (clic, toucher), ou premier coin puis longueur et largeur saisies (DA-02-16). Accrochages DA-02-15. |
| Comportement | **Cycle.** Premier coin → second coin → aperçu avec les dimensions affichées → contrôle → validation ; Échap annule sans commande. Une touche modificatrice impose le carré (longueur = largeur) : raccourci à fixer avec la maquette (L0.3). |
| | **Commandes.** `esquisse.rectangle` ; `esquisse.modifier` (longueur, largeur, angle, coin) ; `esquisse.supprimer`. Un rectangle reste un rectangle : déplacer un coin le redimensionne sans le déformer (DA-02-14) ; `transformer.decomposer` le transforme en quatre `esquisse.ligne` (DA-02-13). |
| | **Contrôles.** Longueur ou largeur sous la tolérance de longueur (DA-01-01) refusée (« Rectangle — deux dimensions non nulles requises. Écartez le second coin. ») ; `angle` non fini ou unité différente de ° refusés (T03) ; coins hors borne refusés. |
| | **Clavier et toucher (T16).** Au clavier : coin en coordonnées, puis longueur et largeur (Tab, Entrée). Au toucher : deux appuis ; deux doigts déplacent ou zooment la vue sans poser de point. |
| | **Palette (UX2) et aide (UX4).** « rectangle » ; synonymes « carré », « cadre », « rect » ; exemple court : rectangle de 3,0 m par 2,0 m depuis un coin accroché. |
| Données et dépendances | Occurrence `esquisse.rectangle` (`drawing`) ; les quatre coins sont dérivés (représentation `plan-2d`), jamais stockés comme géométrie canonique (R15). Profil fermé simple pour `solide.extruder` (DA-04-01, lot 3b) et `esquisse.hachure` (DA-01-11). Événement de commande validée : vues du niveau « à recalculer ». |
| | Références : aucune caractéristique nommée d'esquisse avant le lot 5 ; pas de cotation rattachée, donc pas de référence à réparer (R12) au lot 3a. |
| Résultats | Un rectangle par lot, dimensions et angle lisibles dans l'inspecteur avec unités, sélectionnable, modifiable par coin, annulable ; entrée de journal avec inverse. |
| Cas limites | **Géométrie.** Longueur ou largeur nulle ; `a` = `b` ; angle non fini ; coins hors borne ; niveau inconnu ; calque verrouillé : lot refusé en entier, rien n'est écrit. Pour un rectangle tourné, les dimensions se lisent dans son repère, non dans celui du plan. |
| | **Concurrence.** `baseRevision` dépassée → 409 détaillé (objets cibles modifiés ou supprimés depuis) ; résolution explicite côté client, jamais de fusion automatique. Même `requestId` → réponse enregistrée, aucune seconde révision (T06). |
| | **Réseau et droits.** Hors ligne : réducteur local, file Dexie rejouée dans l'ordre, brouillon si incompatible. Rôle `write` exigé : 403 motivé, 404 sans accès, 423 pendant une réservation d'autrui (R13). |
| Compatibilité | Import P.118 : 734 des 967 tracés ont 4 sommets ; ils sont importés en `solide` à contour de 4 points (rôle et calque conservés), sans reconnaissance de rectangle : l'intention n'est jamais déduite (R3, R7). Un « Rectangle » dessiné dans le prototype est de même importé en `solide`. |
| | DXF : `LWPOLYLINE` fermée à l'export des vues (lot 5 ; l'export actuel écrit quatre `LINE`). IFC : omis au rapport d'échange (annexe C sans correspondance). |
| Validation | **Unité** (`packages/atelier-model/src/commandes/esquisse.test.ts`) : a = b refusé ; largeur nulle refusée ; angle 0° : coins aux positions attendues ; angle 90° : mêmes dimensions, coins recalculés à la tolérance près ; aire = longueur × largeur (valeurs vérifiables à la main) ; inverse restitue l'état. |
| | **API** (`apps/api/src/routes/atelier-commands.test.ts`) : `esquisse.rectangle` → 200 ; largeur nulle → 400 avec `chemin` ; `angle` exprimé en « m » → 400 ; même `requestId` → une seule révision ; `baseRevision` périmée → 409. |
| | **e2e** (`apps/web/e2e/scenarios/05-atelier.mjs`, bloc « 2D · rectangle ») : rectangle par deux coins accrochés à la grille 0,50 m, puis par dimensions saisies, sur la mezzanine de la copie de travail P.118 ; dimensions relues dans l'inspecteur ; poignée de coin ; annuler, rétablir, second navigateur. |
| Règles métier | Aucune règle réglementaire. Un rectangle d'esquisse n'est ni un local ni un mur (Concept §3) : `piece.creer` et `mur.tracer` sont des conversions explicites. |
| Extensions à spécifier | Rectangle à coins arrondis (raccord, DA-02-10, sur polygone) ; rectangle par centre ou par trois points ; rectangle inscrit dans un autre ; dimensions pilotées par contrainte (DA-01-07 / 08). |

Preuve prévue : —

| Champ | Contenu |
| --- | --- |
| Identité | DA-12-01 (M08, P2). Catégorie englobante : l'ontologie `mep` porte quatre systèmes (`tuyau`, `gaine`, `chemin-de-cables`, `conduit`) sur les mêmes classes, des ports typés (position, sens, section, système, fluide) et une relation `connecte` vérifiée sans table de valeurs ; l'électricité (M09) reste P3, seuls ses cheminements (chemins de câbles, conduits) sont ici. |
| Situation utilisateur | Dessiner les réseaux d'un bâtiment ou d'un procédé dans le même projet que l'architecture et la structure. |
| Entrées et unités | `ontologie.activer { nom: "mep" }` ; outils de la palette ; `reseau.connecter { a, portA?, b, portB?, forcer? }`, `reseau.deconnecter { id | a, b }`, `reseau.connecterProches { ids? }`. |
| Comportement | Les ports sont une lecture dérivée des objets (`portsDe`) ; une connexion relie deux ports libres ; compatibilité : même système, même section (1 mm), fluides déclarés égaux, sens non contradictoires, ports coïncidents (5 mm) — refus nommé sinon (`forcer` admet et signale). Après chaque commande, chaque connexion est rejugée : un objet déplacé ou modifié produit un problème « reseau » (recalculé, jamais cumulé) ; un objet supprimé emporte ses connexions. Cycle UX : sélection → paramètres → aperçu → contrôle → validation (UX1–UX4) ; l'ontologie ajoute ses outils à la palette et ses classes à l'inspecteur, sans ruban ni écran distinct (T01). |
| Données et dépendances | Ontologie `mep` activable par projet (registre `ontologies/mep/`, T01) ; classes `segment-reseau`, `raccord-reseau`, `vanne`, `equipement-reseau`, `support-reseau` ; définitions `specification` et `catalogue` ; relation `connecte` ; géométrie 3D partagée `geometrie-3d.ts` ; commandes du contrat `atelier-commands/3` ; journal, idempotence, inverse exact (R9) ; contrôle `controlerReseau` après chaque commande (T07). |
| Résultats | Objets de réseau, connexions, problèmes de connectivité ; réseaux connexes dérivés (`reseauxConnexes`). |
| Cas limites | Objet connecté à lui-même, port déjà connecté, port inconnu : refus nommés ; désactivation refusée tant qu'un objet existe. `baseRevision` périmée : 409 avec objets en conflit ; même `requestId` : une seule révision (T06) ; objet verrouillé : 423 ; hors ligne : réducteur local puis file Dexie ; unité absente ou incompatible, dimension requise absente : 400 (T03, R3). |
| Compatibilité | IFC : ports `IfcDistributionPort` emboîtés (`IfcRelNests`), connexions `IfcRelConnectsPorts`, réseaux `IfcDistributionSystem` (DA-03-16). |
| Validation | Tests : refus (sections, fluides, sens, distance, systèmes), connexion forcée signalée, rupture par déplacement puis réparation, suppression ; recette : connexion depuis l'outil, motif lu avant d'agir, rupture signalée. |
| Règles métier | Aucune valeur de réseau dans le code (test : pas de table de DN, pas de débit ni de pression) : sections saisies ou tirées d'un catalogue CSV sourcé (`tubes-raccords.csv`, D-180), fluides et matériaux déclarés, spécifications du projet ; une grandeur absente est « non évaluée » (R3) ; aucun dimensionnement, aucune vérification hydraulique ou aéraulique. |
| Extensions à spécifier | Collisions entre réseaux et bâtiment (réservations, P2-6) ; électricité et automatismes (P3). |

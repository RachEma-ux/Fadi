# DA-05-09 — Components / Composants — module M04 → Atelier — lot 5

**État : prototype (lot 5)** (à spécifier → spécifiée → prototype → vérifiée → disponible). Preuve liée : tests `packages/atelier-model/src/commandes/bloc.test.ts` (propriétés héritées, surcharge conservée à la redéfinition, comptage par définition, nombre sans unité refusé) ; compte rendu `lots/lot-5.md`.

| Champ | Contenu |
| --- | --- |
| Identité | DA-05-09 (M04, étape cible P1). Interprétation retenue : un composant est la définition réutilisable d'un objet du bâtiment (équipement, mobilier, appareil) qui porte une sémantique : propriétés BIM (DA-06-07), classification (DA-06-08), représentation 2D (symbole) et 3D (solide), comptage dans les quantités. Un bloc (DA-05-06) n'est que du dessin réutilisable. Sous-exigences : -a définir un composant ; -b le placer ; -c redéfinir sa définition. |
| Situation utilisateur | Placer des objets réutilisables du bâtiment (équipements, mobilier) dont chaque occurrence garde une identité, des propriétés et une classification, puis les compter. |
| Entrées et unités | Paramètres de `bloc.definir` et de `bloc.placer` (DA-05-06) avec `nature` = `composant` (paramètre proposé par cette fiche, absent de l'annexe B) ; au niveau de la définition : propriétés typées `{ nom, valeur, unite, provenance, statut }` et classification facultative (DA-06-07, DA-06-08) ; au niveau de l'occurrence : `repere` facultatif et valeurs de propriétés propres. Dimensions : celles des objets de la définition, en m ; aucune n'est ajoutée. |
| Comportement | **Cycle.** Identique à DA-05-06 (sélection → point de base → nom → aperçu → contrôle → validation), avec une étape facultative « propriétés et classification » et un aperçu de ce que l'occurrence hérite. Placement : bibliothèque (DA-05-07) → position et angle → aperçu → validation ; Échap annule sans commande. |
| | **Héritage.** Une occurrence hérite les propriétés et la classification de sa définition ; `propriete.definir` et `classification.affecter` sur l'occurrence les surchargent pour elle seule, l'inspecteur montrant l'origine (définition ou occurrence). Modifier la définition ne réécrit jamais une surcharge d'occurrence. |
| | **Quantités (lot 5).** Un composant est compté par définition (et par classification si elle existe) dans les tableaux de quantités ; un bloc simple ne l'est pas. Une propriété requise par une quantité et « non évaluée » donne un comptage sans valeur : aucune valeur n'est déduite. |
| | **Contrôles.** Ceux de DA-05-06 (classes admises `esquisse.*`, `solide`, `texte` ; cycle refusé ; calque verrouillé ; unité m) ; propriété numérique sans unité refusée ; classe IFC ou code jamais déduits du nom ou de la forme (R3). |
| Données et dépendances | Entités `definition` (`nature` = composant, `version`, objets, propriétés, classification) et `occurrence` (classe d'occurrence de composant à ajouter au tableau 5.2 avec celle de DA-05-06) ; l'occurrence vise la définition par `blocId` et version ; R15 : géométrie canonique dans la définition, représentations `plan-2d`, `symbole` et `solide-3d` dérivées. Événement de commande validée : vues, quantités et bilan « à recalculer » (R11, T07) ; microversion +1. |
| Résultats | Définition de composant versionnée ; occurrences identifiées, propriétés héritées ou surchargées, comptées par définition ; effets listés ; inverse = état précédent. |
| Cas limites | **État.** Redéfinition qui change des propriétés : aperçu des occurrences touchées, surcharges d'occurrence conservées et listées ; définition sans objet ou sans nom refusée ; occurrence d'une définition supprimée ou manquante : « définition manquante », conservée. |
| | **Concurrence et réseau.** `baseRevision` dépassée et définition ou occurrence modifiée depuis → 409 avec `conflits[].objetId` ; occurrence supprimée par autrui : elle ne réapparaît pas ; même `requestId` → une seule révision (T06). Hors ligne : réducteur local, file Dexie, rejeu dans l'ordre, brouillon si incompatible. 403 / 404 / 423 selon R13. |
| Compatibilité | Import P.118 : aucun composant ; les 120 `poteau` (`formeId` `basic-square`) et les 84 `porte` et 126 `fenetre` restent des objets d'architecture typés (DA-05-14, DA-05-15). IFC : un composant exporte comme élément typé selon sa classification (`IfcTypeObject` pour la définition) ; sans classe IFC affectée, son traitement est fixé par l'annexe C (lot 6) et nommé au rapport, jamais par déduction (R3). DXF : comme un bloc. |
| Validation | **Unité** (`packages/atelier-model/src/commandes/bloc.test.ts`, cas composant) : définition avec 2 propriétés ; l'occurrence hérite ; surcharge d'une propriété sur l'occurrence ; modification de la définition : surcharge conservée ; comptage par définition = nombre d'occurrences ; propriété numérique sans unité refusée ; inverse restitue. |
| | **API** (`apps/api/src/routes/atelier-commands.test.ts`) : `bloc.definir` (`nature` composant) → 200 et `effets` ; propriété sans unité → 400 avec `chemin` ; même `requestId` → même réponse ; `baseRevision` périmée → 409 ; rôle lecture → 403. |
| | **e2e** (`apps/web/e2e/scenarios/05-atelier.mjs`, bloc « Composants · définir, placer, compter », lot 5) : copie de travail de P.118 : définir un composant, placer 3 occurrences, surcharger une propriété sur l'une ; le tableau de quantités compte 3 ; annuler ; second navigateur à la même révision. |
| Règles métier | Aucune règle réglementaire. R3 : aucun composant, aucune propriété ni aucune classe IFC par défaut ; valeurs absentes « non évaluées ». R12 : aucune référence ne vise l'intérieur d'un composant. R15 : une seule géométrie canonique. |
| Extensions à spécifier | Composants paramétriques ou configurables (DA-05-08, DA-05-16 : P2, aucune compatibilité présumée) ; substitution d'une définition par une autre ; connecteurs et règles de placement ; catalogues de fabricants (DA-05-18, P2). |

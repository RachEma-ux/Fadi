# DA-07-03 — Windows / Fenêtres — module M05 → module Fadi Atelier — lot 3a

**État : prototype** (à spécifier → spécifiée → prototype → vérifiée → disponible). Preuve liée : `creer.fenetre` (F, allège obligatoire) et `modifier.deplacer-baie` (`apps/web/src/modules/atelier/objets/outils/baies.ts`), symbole tableaux / cadre / vitrage (`apps/web/src/modules/atelier/objets/dessinateurs.ts`) ; tests `apps/web/src/modules/atelier/objets/baies.test.ts` « fenêtre : allège obligatoire (aucune valeur proposée) ; distance au centre saisie », « fenêtre : tableaux, cadre et vitrage », « emprise refusée : hors du mur, chevauchement, trop près d'une jonction, hors d'un mur » ; PR #60. Suppression (lot 3b, L3b.0, D-045) : outil « Supprimer » (`modifier.supprimer`, touche Suppr hors outil actif, `apps/web/src/modules/atelier/plan2d/outils/supprimer.ts`), test `apps/web/src/modules/atelier/objets/supprimer.test.ts`, scénario 14 (mur supprimé avec sa porte, annulé, rétabli). Reste : -g répéter une fenêtre le long de son mur (refusé par le réducteur : test « baie seule : refus lisible du réducteur, rien d'écrit » de `plan2d/outils.test.ts`) ; découpe en 3D : part 3b ; étapes « 05-atelier.mjs » du champ Validation (ancien Atelier) non reprises dans `apps/web/e2e/scenarios/14-nouvel-atelier.mjs`.

| Champ | Contenu |
| --- | --- |
| Identité | **DA-07-03** « Windows » (Exigences V4, annexe B.8, module M05, étape cible P1 ; critère commun B.8). Classe `fenetre` de l'ontologie `building.architecture` (cahier §5.2), même mécanique d'hébergement que la porte (DA-07-02), dont cette fiche ne reprend que les différences. Sous-exigences : **DA-07-03-a** poser une fenêtre dans un mur hôte ; **-b** la déplacer le long du mur ; **-c** modifier largeur, hauteur, allège, repère, type ; **-d** la supprimer ; **-e** contrôle d'emprise ; **-f** symbole de plan dérivé ; **-g** répéter une fenêtre le long d'un mur (par la transformation `transformer.repeter`, DA-02, fiche A) ; **-h** importer les fenêtres de P.118. Fiches liées : DA-07-01, DA-07-02, DA-07-04, DA-05-15 (types de fenêtres), DA-06-07, DA-16 (tableau des fenêtres, lot 5). |
| Situation utilisateur | L'architecte dispose des fenêtres sur les murs de façade, règle leur allège et leurs dimensions, les aligne ou les répète à intervalle régulier, change leur type ; il voit les conflits avec les autres baies et la fenêtre suit le mur quand il change. |
| Entrées et unités | `classe = "fenetre"` ; `murHoteId` ; `t` ∈ [0, 1] et `distance` (m, dérivée, au centre, comme DA-07-02) ; `largeur` (m) > 0 ; `hauteur` (m) > 0 ; `allege` (m) ≥ 0, **obligatoire** (jamais une valeur par défaut tirée de P.118) ; `repere` ; `typeId` (`non-type` si aucune définition). Répétition : nombre d'exemplaires et pas (m) ou répartition entre deux distances, saisis par l'utilisateur. Unités explicites, stockage SI (T03). |
| Comportement | Identique à DA-07-02 : `ouverture.poser` (`classe: "fenetre"`), `ouverture.deplacer`, `ouverture.modifier`, `ouverture.supprimer` ; contrôle d'emprise (baie incluse dans l'axe, aucun recouvrement, `allege + hauteur` ≤ hauteur du mur) ; la fenêtre suit son mur lors d'une modification ou d'une scission (DA-07-01). Répétition = un seul lot atomique de `ouverture.poser` (aperçu de toutes les fenêtres, refus global si l'une sort de l'emprise, avec la liste). Symbole de plan dérivé : fenêtre générique (cadre et vitrage simplifiés) ; aucun type d'ouvrant (battant, oscillo-battant, coulissant) n'est déduit en l'absence de donnée. Vue 3D : vide dans le mur, menuiserie simplifiée. |
| Données et dépendances | Occurrence `fenetre` (`atelier_objects`, mêmes `params` que la porte) ; relation `heberge-par` → mur ; caractéristique `ouverture:centre` ; définition de type (DA-05-15) ; représentations dérivées `plan-2d` et `solide-3d` (`core-geometry`). Effectifs et surfaces de baies (largeur × hauteur) parmi les quantités reproductibles (L1.3). Événement `atelier.commande.validee` → vues, quantités, bilan Harmonie « à recalculer ». |
| Résultats | Fenêtre(s) hébergée(s), découpe des murs en 2D et 3D ; effectifs par niveau et par repère ; journal, révision `n + 1`. |
| Cas limites | Ceux de DA-07-02, plus : allège absente → refus « allège obligatoire » ; allège négative → refus ; répétition dont un exemplaire sort du mur ou chevauche une baie → refus du lot entier avec la liste ; fenêtre posée sur un mur intérieur → admise (aucune règle ne l'interdit), sans avertissement réglementaire inventé. Deux comptes sur la même fenêtre → 409 ; requête répétée → une révision (T06). |
| Compatibilité | **Import P.118** (cahier §6) : `windows[]` (126 : ss 0, rdc 22, mezz 26, r1 26, r2 26, r3 26 ; `hostWallId`, `t`, `width`, `height`, `sill`, `mark`, `layer` `Ouvertures`) → `fenetre` + `heberge-par` ; toutes de 2,40 × 2,10 m, allège 0,80 m, repère `F02`, hébergées par les 24 murs extérieurs (sans type) ; aucun autre champ ; 0 hors emprise, 0 chevauchement, 0 hôte introuvable dans la source. Aucune définition de type → `non-type` ; le repère commun `F02` suggère un type unique : **hypothèse** à proposer à l'utilisateur, jamais une définition créée d'office. **IFC 4.3** (lot 6, annexe C) : `IfcWindow` (+ `IfcWindowType` si une définition existe), `IfcOpeningElement`, `IfcRelVoidsElement`, `IfcRelFillsElement` ; `Pset_WindowCommon` non évalué. |
| Validation | **Unité `packages/atelier-model`** : cycle poser / déplacer / modifier / supprimer avec inverse exact ; refus d'allège absente, hors emprise, chevauchement ; répétition atomique (tout ou rien) ; import P.118 : 126 fenêtres, effectifs par niveau égaux à la source, 126 relations complètes, valeurs identiques bit à bit. **API** : idempotence, 409, 403, 400 détaillé. **Scénario `05-atelier.mjs`** : sur un mur de façade de P.118, déplacer une fenêtre `F02`, modifier son allège, annuler, rétablir ; vérifier la découpe en 3D (`05-atelier.mjs`, mode volume, lot 3b). |
| Règles métier | Aucune règle d'éclairement naturel, de garde-corps de fenêtre, de performance thermique ou acoustique n'est appliquée (**non évaluées**, R3). Une allège basse n'entraîne aucune conclusion de sécurité. |

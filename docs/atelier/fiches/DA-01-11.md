# DA-01-11 — Hatching / Hachures — module M01 → Atelier — lot 3a

**État : prototype (lot 3a)** (à spécifier → spécifiée → prototype → vérifiée → disponible). Preuve liée : recette `apps/web/e2e/atelier-nouveau.mjs`, tests `apps/web/src/modules/atelier/nouveau/nouveau.test.ts` et `packages/atelier-model/src/commandes/commandes.test.ts` ; compte rendu `lots/lot-3a.md`.

| Champ | Contenu |
| --- | --- |
| Identité | DA-01-11 (M01, étape cible P1). Objet : `esquisse.hachure`, remplissage d'un contour fermé par un motif générique. Distinct du poché de coupe d'une vue (DA-14, lot 5) et du remplissage de calque (propriété `remplissage` de la classe `calque`). Pas de référence dans le prototype (qui n'a que la couleur et le remplissage des calques). |
| Situation utilisateur | Hachurer une zone fermée d'une esquisse (surface, matériau schématique, zone à distinguer) avec un motif lisible, sans toucher à la géométrie du contour. |
| Entrées et unités | `esquisse.hachure` : `contour` (polygone, repère local, m), `trous` (polygones intérieurs, facultatif), `motif` (`parallele`, `croise` ou `aplat`), `angle` (°), `espacement` (m, au-dessus de la tolérance de longueur ; ignoré pour `aplat`), `couleur` facultative, `niveauId`, `calqueId`. |
| | Sources : objets fermés `esquisse.rectangle`, `.polygone` (contour exact) ou `.cercle` (contour approché à la tolérance de flèche déclarée, indiquée à l'aperçu) ; le contour est copié à la création. |
| Comportement | **Cycle.** Outil Hachure → clic dans un contour fermé (le plus petit objet fermé qui contient le point) ou sélection d'objets fermés → motif, angle, espacement dans l'inspecteur ou saisis au clavier (DA-02-16 ; aucun point à poser, donc aucun accrochage, DA-02-15) → aperçu des traits → contrôle → validation. Les objets fermés entièrement contenus et sans contact sont proposés comme îlots (`trous`), activables un à un. |
| | **Commandes.** `esquisse.hachure` ; `esquisse.modifier` (motif, angle, espacement, couleur) ; `esquisse.supprimer`. Les traits ne sont pas stockés : représentation `plan-2d` dérivée du contour et du motif (R15). |
| | **Contrôles.** Contour ouvert, auto-sécant ou d'aire nulle refusé ; îlots qui se chevauchent, se touchent ou sortent du contour refusés (liste) ; espacement supérieur à la plus grande dimension du contour refusé (aucun trait produit) ; motif inconnu refusé ; clic hors de tout contour fermé : « Aucun contour fermé à cet endroit », aucun lot. |
| | **Association.** Non associative au lot 3a : modifier ou déplacer le contour d'origine ne modifie pas la hachure (contour copié). La hachure se transforme comme une esquisse (DA-02) : le contour est transformé, motif et espacement conservés, l'angle suit une rotation. Hachure associative par référence : extension. |
| | **Affichage.** Un espacement trop fin pour l'échelle d'affichage est dessiné en aplat à l'écran (affichage seul, R10 ; valeur stockée inchangée). |
| | **Palette (UX2) et aide (UX4).** « hachure » ; synonymes « hachurer », « remplissage », « hatch » ; exemple court : hachurer un rectangle à 45°. |
| Données et dépendances | Occurrence `esquisse.hachure` (`drawing`) ; aucune relation ni référence (contour copié) ; consomme des contours d'esquisse (DA-01-02 à 04) ; `core-geometry` : intersection polygone / droites ; événement de commande validée : vues du niveau « à recalculer ». |
| Résultats | Une hachure par lot, motif lisible dans le plan, paramètres modifiables dans l'inspecteur ; entrée de journal avec inverse. |
| Cas limites | **Géométrie.** Contour dégénéré ; îlot tangent au contour ou touchant un autre îlot (refusé, liste) ; contour sans îlot valide ; niveau inconnu ; calque verrouillé : lot refusé en entier. |
| | **Concurrence et réseau.** `baseRevision` dépassée → 409 détaillé, résolution explicite côté client ; même `requestId` → une seule révision (T06) ; hors ligne : réducteur local puis file Dexie rejouée dans l'ordre ; 403 / 404 / 423 selon R13. |
| Compatibilité | Import P.118 : aucune hachure dans le prototype ; le remplissage des 20 calques (couleur, remplissage) est importé en `calque`, jamais converti en hachure (R7). |
| | DXF : entité `HATCH` visée à l'export des vues (lot 5 ; l'export actuel n'écrit que `LINE`) ; sinon la hachure est aplatie en traits et le rapport le dit. IFC : `IfcAnnotation` avec `IfcFillAreaStyleHatching` envisageable au lot 6, sinon « omise ». |
| Validation | **Unité** (`packages/atelier-model/src/commandes/esquisse.test.ts` et `packages/core-geometry`) : carré de côté connu, angle 0°, espacement donné : nombre et longueurs des traits vérifiables à la main ; angle 45° : traits à 45° ; îlot retiré du remplissage ; contour auto-sécant refusé ; `aplat` sans traits ; mêmes entrées, mêmes traits. |
| | **API** (`apps/api/src/routes/atelier-commands.test.ts`) : `esquisse.hachure` → 200 ; `espacement` en « ° » ou nul → 400 avec `chemin` ; même `requestId` → une seule révision ; `baseRevision` périmée → 409. |
| | **e2e** (`apps/web/e2e/scenarios/05-atelier.mjs`, bloc « 2D · hachure ») : sur la mezzanine de la copie de travail P.118, rectangle hachuré avec un cercle en îlot, angle modifié dans l'inspecteur ; annuler, rétablir, second navigateur. |
| Règles métier | Aucune règle réglementaire. Motifs conventionnels par matériau (SIA 400, ISO 128) : non fournis ; seuls des motifs génériques existent, tout motif conventionnel est introduit avec sa source (R3). |
| Extensions à spécifier | Motifs de bibliothèque ; hachure associative ; hachure par détection de contour entre lignes jointives ; espacement en unités papier (vues à l'échelle, lot 5) ; dégradés. |

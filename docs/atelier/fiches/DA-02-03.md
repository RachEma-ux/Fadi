| Identité | **DA-02-03** « Rotate » (Exigences V4.1, annexe B.3, M02, P1). Critère commun B.3. Tâche **L3a.2**. Sous-exigences : **DA-02-03-a** rotation d'une sélection autour d'un centre dans le plan du niveau (axe vertical) ; **-b** rotation avec copie (option `copier`) ; **-c** rotation par référence (aligner une direction sur une autre). Règles communes : fiche **DA-02-01**. Fiches liées : DA-02-15 / 16, DA-02-17 (manipulateur, rotation à la poignée, lot 3b). La rotation de la **vue** (orbite, outil « Rotation vue » du prototype) n'est pas une transformation : état d'affichage (R10). |
| Situation utilisateur | L'architecte fait pivoter un îlot de bureaux, un escalier ou une aile de cloisons autour d'un point accroché, d'un angle exact ou pour l'aligner sur un mur existant. |
| Entrées et unités | `cibles` ; `centre` `{ x, y, frame: "local", unit: "m" }` ; `angle` `{ value, unit: "°" }` (sens trigonométrique, positif = antihoraire vu de dessus) **ou** -c : `directionDepart`, `directionArrivee` (deux vecteurs locaux, l'angle est dérivé et affiché) ; `copier` (booléen, -b). Saisie : centre accroché, angle au clavier ou par deux points ; pas d'angle par défaut. |
| Comportement | Cycle UX3 : sélection → « Tourner » (synonymes « rotate », « pivoter ») → centre → **aperçu** (angle courant en °, fantômes, objets entraînés) → validation.<br>Commande (annexe B) : `{ type: "transformer.tourner", cibles, params: { centre, angle, copier? } }`. Inverse : `transformer.tourner` d'angle `−angle` autour du même centre (sans `copier`) ; avec `copier`, inverse = suppression des copies. Effets par classe : `mur`, `escalier` → axe tourné (épaisseur, hauteur, alignement inchangés) ; `poteau` → `point` tourné **et** `angle` du poteau incrémenté (P.118 porte `angle` sur chaque poteau) ; `dalle`, `solide`, `piece`, `espace`, `zone`, esquisses → contours / trous tournés ; `texte` → position tournée, orientation du texte incrémentée si le texte porte une orientation (sinon reste horizontal — **Hypothèse**, à figer par L1.1) ; `cotation` → selon règle commune 4 (DA-02-01). Ouvertures hébergées : suivent leur mur (relatives). Calque verrouillé : tout ou rien. Repère : centre en `local` exclusivement. |
| Données et dépendances | Paramètres géométriques modifiés (comme DA-02-01) + `angle` des poteaux ; jonctions de murs recalculées ; pièces proposées à la redétection. Calcul : `core-geometry` (rotation 2D pure), stockage en valeurs non arrondies. Événement → vues et quantités « à recalculer ». |
| Résultats | Objets tournés (ou copies tournées) ; jonctions rompues listées ; journal « Tourner n objets de α° ». |
| Cas limites | Angle nul (|α| < `tolAngle` = 1·10⁻⁶ rad, **proposée, à confirmer**) → pas de commande. Angle multiple de 360° → refus « rotation sans effet » (**Recommandation**). Angle en radians ou unité absente → 400 (T03). Accumulation d'erreur flottante : après rotation de 90° quatre fois, retour au point de départ à `tolCoincidence` = 1·10⁻⁶ m près ; les valeurs ne sont **jamais** « corrigées » par arrondi (R7). -c avec une direction de longueur nulle → refus. Objet hébergé seul → refus (règle commune 2). 403 / 409 / 423 ; idempotence ; hors ligne rejoué. |
| Compatibilité | Aucun format concerné. IFC : orientation résultante (`IfcLocalPlacement`). Prototype : « Tourner objet » — fonction conservée. Données P.118 : `angle` des poteaux en degrés (**Hypothèse** d'unité à confirmer par L1.4 sur les données). |
| Validation | **Unité** `transformer.test.ts` : mur (0 ; 0)→(4 ; 0) tourné de 90° autour de (0 ; 0) → (0 ; 0)→(0 ; 4) à 1·10⁻⁶ m ; poteau `angle` 0° tourné de 30° → `angle` 30° et point tourné ; 4 × 90° → état initial à `tolCoincidence` ; inverse → empreinte identique à la tolérance ; `copier` → original intact + copie. **API** : 400 sur `{ value: 1.57, unit: "rad" }` ; idempotence. **Scénario** `05-atelier.mjs` : tourner un poteau de P.118 de 45° au clavier ; annuler / rétablir ; second navigateur. `11-accessibilite.mjs` : clavier. |

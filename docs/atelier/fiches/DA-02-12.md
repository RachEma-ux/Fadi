# DA-02-12 — Arrays and patterns / Réseaux et répétitions — module M02 → Atelier — lot 3a

**État : prototype (lot 3a)** (à spécifier → spécifiée → prototype → vérifiée → disponible). Preuve liée : recette `apps/web/e2e/atelier-nouveau.mjs`, tests `apps/web/src/modules/atelier/nouveau/nouveau.test.ts` et `packages/atelier-model/src/commandes/commandes.test.ts` ; compte rendu `lots/lot-3a.md`.

| Champ | Contenu |
| --- | --- |
| Identité | DA-02-12 (M02, étape cible P1). `transformer.repeter` : copies régulières, non associatives. Sous-exigences : -a réseau rectangulaire ; -b réseau polaire. Pas de référence dans le prototype (qui copie un objet à la fois). |
| Situation utilisateur | Répéter un objet ou un groupe d'objets selon une trame régulière (rangée de poteaux, fenêtres identiques, places en couronne) en un seul geste annulable. |
| Entrées et unités | `niveauId` ; `cibles` ; `nouveauxIds` (un par objet créé, fournis ou dérivés du `requestId`). Mode `rectangulaire` : `lignes`, `colonnes` (entiers supérieurs ou égaux à 1, au moins 2 copies au total), `pasLignes`, `pasColonnes` (m, signés), `angle` (°, direction des colonnes, 0 = axe x local). |
| | Mode `polaire` : `centre` (point local, m), `nombre` (entier supérieur ou égal à 2, original compris), `angleTotal` (°, signé, 360 par défaut), `pivoterObjets` (booléen). Classes admises : celles de DA-02-02. |
| Comportement | **Cycle.** Sélection → mode et paramètres (compte, pas, angle) dans l'inspecteur ou saisis (DA-02-16) ; centre polaire accroché (DA-02-15) → aperçu de toutes les copies avec leur nombre → contrôle → validation = un lot, une action annulable ; Échap annule sans commande. |
| | **Règles.** L'original est la cellule (1, 1). Polaire à 360° : pas = 360° / `nombre`, la dernière copie ne retombe pas sur l'original ; à moins de 360° : pas = `angleTotal` / (`nombre` − 1), la dernière copie est à l'angle total. Copies indépendantes : aucune association au lot 3a, modifier l'une ne change pas les autres. |
| | **Contenu des copies.** Murs : chaque copie emporte ses ouvertures (comme DA-02-02 ; `repere` et `exterieur` non recopiés). Poteaux : `statutConception` non recopié. Une trame de poteaux s'obtient par un réseau rectangulaire d'un poteau : même commande pour l'interface et pour les scripts (T19). |
| | **Contrôles.** Pas nul ou angle total nul refusés (copies superposées) ; nombre total d'objets créés borné par le serveur (plafond fixé au lot 2, 400 explicite, jamais de troncature silencieuse) ; coordonnées hors borne refusées ; superposition avec des objets existants : signalée à l'aperçu, non bloquante ; cible d'un autre niveau, supprimée ou sur un calque verrouillé : lot refusé en entier. |
| | **Palette (UX2) et aide (UX4).** « répéter » ; synonymes « array », « réseau », « matrice », « trame » ; actif si au moins un objet d'une classe admise est sélectionné ; exemple court : répéter un poteau en 3 colonnes de pas 4,00 m ; clavier complet : paramètres saisis dans l'inspecteur. |
| Données et dépendances | Crée (lignes × colonnes − 1) ou (nombre − 1) jeux d'occurrences (identifiants déterministes) et leurs relations `heberge-par` ; aucune référence existante modifiée (R12 sans objet) ; événement de commande validée : vues, quantités et bilan Harmonie « à recalculer ». |
| Résultats | Les copies, sélectionnées après validation, avec l'effectif créé affiché ; inverse = suppression exacte des copies ; un seul lot dans le journal. |
| Cas limites | **Géométrie.** Une seule cellule ; pas ou angle total nuls ; plafond du serveur dépassé ; copies hors borne ; copies qui se recouvrent entre elles (pas inférieur à l'objet : signalé) ; cible d'un autre niveau, supprimée ou sur un calque verrouillé : lot refusé en entier. |
| | **Concurrence.** `baseRevision` dépassée et cible modifiée ou supprimée depuis → 409 détaillé, résolution explicite côté client ; même `requestId` → mêmes objets, aucun second réseau (T06). |
| | **Réseau et droits.** Hors ligne : réducteur local, rejeu identique grâce à `nouveauxIds`, file Dexie rejouée dans l'ordre ; 403 motivé, 404 sans accès, 423 pendant une réservation d'autrui (R13). |
| Compatibilité | Import P.118 : un réseau peut s'appliquer aux 120 poteaux (20 par niveau, `basic-square`), aux murs avec ouvertures, aux solides ; l'importeur ne reconnaît aucun réseau dans les données (R3, R7). |
| | IFC : chaque copie est un objet distinct (aucun regroupement de réseau inventé). DXF : aucune sortie propre. |
| Validation | **Unité** (`packages/atelier-model/src/commandes/transformer.test.ts`) : réseau 3 × 2 de pas connus : 5 copies aux positions attendues (valeurs vérifiables à la main) ; polaire de 4 à 360° : copies à 90°, 180° et 270° ; polaire de 3 à 180° : copies à 90° et 180° ; pas nul refusé ; plafond dépassé refusé ; mur et porte : 2 × (mur + porte) ; même enveloppe, mêmes identifiants ; inverse supprime exactement les copies. |
| | **API** (`apps/api/src/routes/atelier-commands.test.ts`) : `transformer.repeter` → 200, `applique[0].objetIds` de la taille attendue ; plafond dépassé → 400 avec motif ; `lignes` nul → 400 avec `chemin` ; même `requestId` → un seul réseau ; `baseRevision` périmée → 409. |
| | **e2e** (`apps/web/e2e/scenarios/05-atelier.mjs`, bloc « 2D · réseau ») : sur la copie de travail de P.118, réseau rectangulaire 3 × 2 d'un poteau de la mezzanine : poteaux +5 en un seul lot, annulation en une seule action ; réseau polaire d'une esquisse ; second navigateur. |
| Règles métier | Aucune règle réglementaire. R3 : un réseau n'est pas un dimensionnement ; aucun pas, entraxe ou portée n'est proposé par défaut, les pas sont toujours saisis. |
| Extensions à spécifier | Réseau associatif (modifier le pas recalcule les copies) ; réseau suivant une trajectoire ; réseau 3D ; numérotation automatique des repères ; réseau de blocs (lot 5). |

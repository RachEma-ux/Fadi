# DA-05-15 — Standard-component libraries / Bibliothèque de composants : placer et changer de type — module M04 → module Fadi Atelier — lot 1 + 3a

**État : spécifiée** (à spécifier → spécifiée → prototype → vérifiée → disponible). Preuve liée : — (à lier aux lots 1 et 3a).

Interprétation : voir DA-05-14 (proposition §5.1 « 14 / 15 = catalogue de portes / fenêtres / murs
versionné »). Cette fiche couvre l'**usage** du catalogue (**recommandation**, ambiguïté signalée) : choisir un
type pour placer une occurrence, changer le type d'occurrences existantes, mettre à jour la version de catalogue
d'un projet. Les composants libres réutilisables (blocs, composants) sont DA-05-06 / 07 / 09, lot 5.

| Champ | Contenu |
| --- | --- |
| Identité | **DA-05-15** « Standard-component libraries » (Exigences V4.1, annexe B.6, M04, P1 ; critère B.6 : « Identités, occurrences et références stables lors de la réutilisation »). Exigence transversale T15. Sous-exigences : **DA-05-15-a** choisir un type du catalogue avant de placer un mur, une porte, une fenêtre ou une ouverture (outil + liste de types) ; **-b** changer le type d'une ou plusieurs occurrences (`<classe>.modifier { typeId }`) ; **-c** sélectionner toutes les occurrences d'un type (affichage) ; **-d** mettre à jour un projet vers une nouvelle version de catalogue, avec rapport ; **-e** occurrences importées de P.118 rattachées à leur type. Tâches : L1.2, L1.4, L3a.3. Fiches liées : DA-05-14 (catalogue), DA-07-01 (murs), DA-07-02 / 03 / 04 (ouvertures), DA-05-12 (objets), DA-05-06 / 07 / 09 (blocs et composants, lot 5). |
| Situation utilisateur | L'architecte prend « Cloison » dans le catalogue et trace ; plus tard il remplace le type de dix cloisons par « Mur » en une fois, en voyant ce qui change ; il retrouve toutes les occurrences d'un type. Résultat : des occurrences qui pointent vers une définition versionnée, modifiables en lot, avec ouvertures et références conservées. |
| Entrées et unités | `typeId` (définition existante de la classe visée, DA-05-14) ; `objetIds[]` (occurrences de la même classe) ; pour la mise à jour de catalogue : version cible (entier). Les dimensions de placement (épaisseur, hauteur, largeur…) restent celles de la fiche de la classe, en m ; si le type porte une valeur proposée (DA-05-14), elle pré-remplit le champ, modifiable ; sinon champ vide ou dernière valeur saisie (R3). |
| Comportement | Placement : l'outil de la classe (Mur, Porte, Fenêtre, Ouverture) affiche la liste des types de la classe (dernier type utilisé présélectionné — état d'interface, pas une donnée) ; la commande émise est celle de la classe (annexe B : `mur.tracer { typeId }`, `ouverture.poser { typeId }`).<br>Changer de type : sélection → inspecteur → champ « Type » → **aperçu** (occurrences touchées, éventuelles propriétés qui changent, vues marquées) → contrôle → validation = lot de `<classe>.modifier { typeId }` (un par occurrence, atomique) ; inverse = même commande avec l'ancien `typeId`. Les identités, ouvertures hébergées et références sont conservées (changement de type ≠ recréation) ; une référence vers une caractéristique qui disparaîtrait passe « à réparer » (R12).<br>Sélection par type : état d'affichage (R10).<br>Mise à jour de catalogue : commande `catalogue.mettreAJour` (**nom proposé, à figer par L1.2**, absent de l'annexe B) : applique la version cible aux définitions utilisées, liste dans l'aperçu les occurrences dont une propriété issue du type change ; inverse = retour à la version précédente. |
| Données et dépendances | `atelier_objects.definition_id` ; `atelier_definitions` (version) ; propriétés d'occurrence (`atelier_properties`). Modules : `atelier-model` (réducteurs des classes, contrôle « type de la bonne classe »), interface (sélecteur de type dans l'outil et l'inspecteur), Documents (nomenclatures par type, lot 5, marquées « à recalculer »), échanges (lot 6 : `IfcRelDefinesByType`). Publication (lot 7) : la version de catalogue utilisée est figée (T12, T15). |
| Résultats | Occurrences créées ou retypées ; journal, révision `n + 1` ; vues et nomenclatures marquées ; rapport de mise à jour de catalogue (occurrences touchées, propriétés changées). |
| Cas limites | `typeId` inexistant ou d'une autre classe (type de porte sur un mur) → 400 `{ chemin: "commands[0].params.typeId", message }`. Sélection mixte (murs + portes) pour un changement de type → refus « classes différentes ». Occurrence sur calque verrouillé → refus (DA-05-01), tout ou rien. Type supprimé par un autre utilisateur entre l'aperçu et l'envoi → 409. Mise à jour vers une version inexistante ou antérieure → 400. Changement de type d'un mur qui rendrait une ouverture invalide (si le type impose une valeur — non prévu au lot 3) → refus listant les ouvertures. Requête répétée → T06 ; lecteur → 403 ; 423 ; hors ligne : changement de type exécutable localement, rejoué. |
| Compatibilité | **Import P.118** : 135 murs → `cloison`, 61 → `mur`, 24 sans `type` (exactement les 24 murs de `exteriorWallIds`, calque « Murs ») → `non-type` ; les 7 murs `type: "mur"` du calque « Garde-corps » (hauteur 1,10 m) gardent le type `mur` (aucun reclassement silencieux, voir DA-07-01) ; portes et fenêtres → `non-type` (aucun type dans la source, DA-05-14). **IFC 4.3** (lot 6) : `IfcRelDefinesByType` entre occurrence et `IfcWallType` ; un objet IFC importé sans type → `non-type`. **DXF** : sans objet (vues). |
| Validation | **Unité** `packages/atelier-model/src/commandes/mur.test.ts` et `ouverture.test.ts` : placement avec `typeId` existant → occurrence liée ; type d'une autre classe refusé. `src/commandes/type.test.ts` : changer le type de 3 cloisons en `mur` → 3 occurrences modifiées, identités et ouvertures inchangées, une révision ; inverse → empreinte identique ; `catalogue.mettreAJour` → rapport exact. **Import** `src/importeur/p118.test.ts` : effectifs par type 135 / 61 / 24, `non-type` = ensemble exact de `exteriorWallIds`. **API** `apps/api/src/atelier-commands.test.ts` : 400 type d'une autre classe ; T06 ; 409. **Scénario** `apps/web/e2e/scenarios/05-atelier.mjs` : sur P.118 importé, modifier le type d'un mur (critère d'acceptation du lot 3a « modifier le type ») → révision + 1, porte hébergée conservée ; annuler / rétablir ; second navigateur à la même révision. `11-accessibilite.mjs` : changer de type au clavier. |
| Règles métier | Aucune règle réglementaire. Changer de type ne vaut ni vérification de performance ni qualification structurelle (**non évaluées**, R3). |
| Extensions à spécifier | Bibliothèques de composants entre projets ; composants intelligents à règles (DA-05-16, hors périmètre) ; catalogues de fabricants (avec source et version) ; remplacement d'un type par un autre avec correspondance de paramètres.<br>**Ambiguïté (au chef de projet)** : répartition DA-05-14 / DA-05-15 (catalogue / usage) recommandée par ces fiches ; nom de la commande de mise à jour de catalogue (hors annexe B). |

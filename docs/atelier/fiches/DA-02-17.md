| Identité | **DA-02-17** « Gumball manipulation » (Exigences V4.1, annexe B.3, module M02, étape cible P1). **Interprétation particulière** (annexe B.3) : « Manipulateur de déplacement, rotation et échelle ; équivalent fonctionnel ». Critère de recette commun B.3 : « Transformations réversibles ; sélection, copie et dépendances conservées ». Sous-exigences : **DA-02-17-a** manipulateur 2D sur la sélection (poignées déplacer x / y / libre, anneau de rotation, poignées d'échelle) — lot 3a ; **-b** pivot déplaçable et accrochable — lot 3a ; **-c** saisie de valeur pendant la manipulation (DA-02-16) — lot 3a ; **-d** manipulateur 3D dans la vue three.js (axes x, y, z, rotation autour de z, échelle) — lot 3b ; **-e** alternative sans glisser (clavier, inspecteur, palette) — lots 3a et 3b. Fiches liées : DA-02-01 (déplacer), DA-02-03 (tourner), DA-02-05 (échelle) — **elles fixent les classes admises et les effets** ; DA-02-15, DA-02-16, DA-02-14, DA-04-07 (pousser / tirer, autre geste 3D). |
| Situation utilisateur | L'architecte sélectionne un meuble, un poteau ou un groupe et le déplace, le tourne ou le met à l'échelle directement dans le plan ou dans la vue 3D, au doigt ou à la souris, avec la possibilité de taper la valeur exacte. Résultat : la même transformation que par les outils Déplacer / Tourner / Échelle, en un geste. |
| Entrées et unités | Sélection typée (classes admises par la commande émise) ; poignée saisie ; déplacement `{ dx, dy, unit: "m" }` (et `dz` en 3D, voir Comportement) ; angle `{ value, unit: "°" }` ; facteur d'échelle (sans unité, > 0), uniforme ou par axe ; pivot `{ x, y, frame: "local", unit: "m" }` (par défaut : centre de la boîte englobante de la sélection — **Recommandation**). Valeurs exactes possibles au clavier pendant le geste (DA-02-16) ; accrochage du point d'arrivée et du pivot (DA-02-15). Taille des cibles : au moins 24 × 24 px CSS (WCAG 2.2, critère 2.5.8, niveau AA, cahier §5.8) ; 44 px au toucher **recommandé**. |
| Comportement | Le manipulateur est un **mode d'interaction**, pas une commande : son affichage, sa position et le pivot sont des états d'affichage (R10). Cycle UX3 : sélection → manipulateur affiché → saisie d'une poignée → **aperçu** continu (réducteur pur local, aucune requête par mouvement) avec valeur courante affichée (distance, angle, facteur) → contrôle → validation au relâcher (ou `Entrée` après saisie) → **une** commande par geste : `transformer.deplacer` (`params: { vecteur }`), `transformer.tourner` (`params: { centre, angle }`), `transformer.echelle` (`params: { centre, facteur }` ou `{ fx, fy }`), noms de l'annexe B ; `Échap` pendant le geste annule sans commande. Maintien d'une touche pendant un déplacement → copie (`transformer.copier`, DA-02-02) — **Recommandation**.<br>**3D (lot 3b)** : poignées x / y dans le plan du niveau ; poignée z seulement pour les classes qui portent un `decalageBase` (`solide`, `dalle`, `escalier`) : elle modifie ce décalage — **Hypothèse**, le paramètre `dz` de `transformer.deplacer` est à figer par L1.2 ; sinon la poignée z est absente. Rotation autour de l'axe vertical seulement (objets du bâtiment non inclinés) ; les anneaux autour de x / y ne sont pas affichés au lot 3b. Changer de niveau n'est pas un déplacement en z (commande dédiée, hors fiche).<br>**Alternative sans glisser** (WCAG 2.2, critère 2.5.7 « mouvements de glissement ») : mêmes transformations par les champs de l'inspecteur, la palette (« Déplacer de… », « Tourner de… ») et les flèches du clavier (pas de grille, DA-02-15), avec les mêmes commandes. |
| Données et dépendances | Interface : `apps/web/src/modules/atelier/plan2d/**` (2D, SVG / Canvas, `pointer events`) et `apps/web/src/modules/atelier/rendu3d/**` (3D, three.js ; un contrôle de transformation de three.js, licence MIT, est une option — choix de bibliothèque délégué au chef de projet, §10.2) ; aucun import de `three` ni du DOM dans `packages/atelier-model` / `core-geometry` (R6). Réducteurs et effets : ceux des commandes `transformer.*` (fiches DA-02-01 / 03 / 05) ; écritures, journal, événements et références : idem ces fiches. |
| Résultats | Sélection transformée ; une entrée de journal par geste (« Déplacer », « Tourner », « Mettre à l'échelle ») ; révision `n + 1` par geste, jamais par image. |
| Cas limites | Geste interrompu (pointeur perdu, `pointercancel`, changement d'onglet) → aperçu abandonné, aucune commande. Geste de longueur nulle (déplacement < `tolCoincidence`, angle 0°, facteur 1) → aucune commande. Classe non admise dans la sélection → poignée correspondante désactivée avec le motif au survol / au focus (ex. échelle sur un mur : selon DA-02-05). Calque verrouillé → manipulateur affiché désactivé, motif « calque verrouillé : <nom> ». Facteur ≤ 0 ou retournement par échelle négative → refus (le miroir est DA-02-04). Objet modifié par autrui pendant le geste → 409 à la validation, aperçu remplacé par l'état serveur, résolution explicite. Lecteur → manipulateur absent. Deux doigts pendant un geste → navigation (pan / zoom), le geste en cours est annulé. Hors ligne : commande locale, rejouée. WebGL indisponible (lot 3b) → manipulateur 3D absent, 2D disponible. |
| Compatibilité | Aucun format. Prototype : déplacement d'objet par glisser (outil Déplacer), outils Tourner objet et Échelle séparés, poignées de Pousser / Tirer (L, l, H) — fonctions conservées ; le manipulateur unifié est nouveau. |
| Validation | **Unité** : sans objet propre (les réducteurs sont validés par DA-02-01 / 03 / 05) ; test de la fonction pure de conversion geste → paramètres (`packages/core-geometry/src/manipulateur.test.ts` : glisser de 120 px à l'échelle 1 px = 0,025 m → vecteur (3 ; 0) ; angle d'anneau → angle ; facteur par poignée de coin). **Scénario** `05-atelier.mjs` (lot 3a) : sur P.118 importé, sélectionner un poteau de la mezzanine, glisser la poignée x en saisissant 2,00 → poteau déplacé de 2 m exactement, **une seule** entrée de journal et révision + 1 ; anneau de rotation + saisie 90° ; annuler / rétablir. Lot 3b : même geste dans la vue 3D, et poignée z d'un `solide` → `decalageBase` modifié et persisté. `11-accessibilite.mjs` : même transformation sans glisser (clavier / inspecteur), cibles ≥ 24 px, aucune violation axe. `12-mesures.mjs` : `⏱` latence d'aperçu pendant le glisser et durée de validation (aucun seuil annoncé avant mesure, R14). |
| Règles métier | Aucune règle réglementaire. Accessibilité : WCAG 2.2 AA (cahier §5.8) — critères 2.5.7 et 2.5.8 cités ci-dessus. |
| Extensions à spécifier | Rotation autour d'axes horizontaux (objets inclinés) ; échelle non uniforme en 3D ; manipulateur de sous-éléments (faces, arêtes) ; alignement du manipulateur sur un repère de saisie temporaire (DA-02-16). **Question au chef de projet (L1.2)** : `transformer.deplacer` accepte-t-il un `dz` (décalage de base) ou faut-il passer par `solide.modifier` / `dalle.modifier` ? |

| Champ | Contenu |
| --- | --- |
| Identité | **DA-02-06** « Stretch » (Exigences V4.1, annexe B.3, M02, P1). Critère commun B.3. Tâche **L3a.2**. Sous-exigences : **DA-02-06-a** étirer : déplacer par un vecteur les **sommets / extrémités** situés dans une fenêtre de capture, les autres restant fixes ; **-b** étirer un ensemble de murs joints en conservant les jonctions (allonger une pièce) ; **-c** étirer un contour (dalle, solide, pièce, esquisse) en déplaçant un côté. Règles communes : fiche **DA-02-01**. Fiches liées : DA-02-14 (points de contrôle, un sommet à la fois), DA-04-07 (pousser / tirer sur une dimension nommée), DA-07-01. |
| Situation utilisateur | L'architecte agrandit une salle de 1,20 m vers l'est : il capture le mur est et les extrémités des murs nord et sud qui y aboutissent, donne le vecteur ; les murs nord et sud s'allongent, le mur est se déplace, la dalle et la pièce suivent si elles sont capturées. |
| Entrées et unités | `fenetre` : polygone de capture (rectangle en général) `{ points: [{ x, y, frame: "local", unit: "m" }…] }` ; `cibles` : objets candidats (sélection courante ou tout ce qui intersecte la fenêtre sur le niveau actif) ; `vecteur` `{ dx, dy, frame: "local", unit: "m" }`. Le réducteur dérive la liste exacte des **sommets capturés** par objet (`{ objetId, caracteristique }` : `mur:arete-debut`, `mur:arete-fin`, `dalle:contour[i]`, `esquisse:sommet[i]`) ; cette liste figure dans les `params` validés (pas de recalcul ambigu côté serveur). |
| Comportement | Cycle UX3 : « Étirer » (synonymes « stretch », « allonger ») → fenêtre de capture (de droite à gauche) → **aperçu** (sommets capturés surlignés, objets entièrement capturés = déplacés, partiellement = déformés, longueurs résultantes) → vecteur → validation.<br>Commande (annexe B) : `{ type: "transformer.etirer", cibles, params: { sommets: [{ objetId, caracteristique }], vecteur } }`. Inverse : même liste, `−vecteur`.<br>Règles par classe (**Recommandation**, à figer par L1.2) : **mur** : extrémité capturée déplacée, l'autre fixe ; mur entièrement capturé = déplacé ; épaisseur, hauteur, type inchangés. **Ouvertures** : leur `distance` depuis l'extrémité **non déplacée** est conservée (la porte ne glisse pas quand on allonge le mur du côté opposé) ; `t` recalculé ; ouverture hors emprise après raccourcissement → refus listant les ouvertures. Jonctions : les murs dont l'extrémité commune est capturée restent joints. **Poteau**, **texte** : déplacés si leur point est capturé. **Escalier** : refus s'il n'est que partiellement capturé (paramètres liés, DA-07-10) ; déplacé s'il est entièrement capturé. **Contours** : sommets capturés déplacés ; trous capturés suivent. **Cotation** : recalculée par ses références (elle « suit » la nouvelle longueur, c'est l'intérêt d'une cote référencée) ; cotation libre (P.118) capturée → ses points capturés déplacés. **Pièces** : `polygones` étirés seulement si la pièce est dans la sélection ; sinon `piece.detecter` propose. Calque verrouillé : tout ou rien. |
| Données et dépendances | Axe des murs, `t` des ouvertures, contours, positions ; caractéristiques nommées (cahier §5.2) utilisées comme adresses des sommets ; `core-geometry` (test point-dans-polygone, jonctions) ; événement → vues, quantités, surfaces à recalculer. |
| Résultats | Objets déformés ou déplacés ; jonctions conservées ; journal « Étirer n objets » ; aires et longueurs périmées. |
| Cas limites | Aucun sommet capturé → pas de commande. Étirement qui rend un segment ou un mur < `longueurMin` = 0,001 m (**proposée**), ou un contour d'aire < `aireMin` = 1·10⁻⁶ m² → refus. Contour devenant auto-sécant → accepté pour une esquisse (signalé), refusé pour une dalle (**Hypothèse**, cohérente avec DA-01-02). Ouverture hors emprise → refus. Sommets capturés d'un objet sur calque verrouillé → refus du lot. Liste `sommets` incohérente avec l'état serveur (objet modifié entre-temps) → 409 `motif: "caractéristique introuvable"`. Repère / unité invalides → 400. 403 / 423 ; idempotence ; hors ligne rejoué. |
| Compatibilité | Aucun format concerné. Prototype : pas d'outil « Étirer » (les poignées L / l de Pousser/Tirer en tiennent lieu pour un objet unique) — fonction nouvelle. |
| Validation | **Unité** `transformer.test.ts` : rectangle de 4 murs 6 × 4 m joints, porte sur le mur sud à `distance` 1,00 m de l'extrémité ouest ; fenêtre capturant le mur est et les extrémités est des murs nord / sud ; vecteur (1,20 ; 0) → murs nord / sud 7,20 m, mur est en x = 7,20, jonctions conservées, porte toujours à 1,00 m de l'extrémité ouest ; inverse → empreinte identique ; mur raccourci sous la porte → refus ; escalier partiellement capturé → refus. **API** : 409 si un sommet listé n'existe plus. **Scénario** `05-atelier.mjs` : étirer une salle de la mezzanine de P.118 de 1,00 m ; pièce proposée à la redétection ; annuler ; second navigateur. |
| Règles métier | Aucune règle réglementaire ; l'agrandissement d'une pièce ne contrôle aucune surface minimale (non évaluée, R3) ; l'écart avec la Programmation est signalé par les liaisons existantes, pas par cette commande. |
| Extensions à spécifier | Étirement 3D (hauteurs par sommet, `vertexOffsets` / `topOffsets` de P.118 : conservés à l'import, non édités au lot 3a) ; étirement d'arcs (rayon conservé ou non) ; option « étirer les murs non capturés joints » (propagation) — **Recommandation** : non au lot 3a. |

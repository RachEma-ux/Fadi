# DA-03-15 — Construction modeling / Modélisation de la construction — module M05 → Atelier — lot 3a

**État : prototype (lot 3a)** (à spécifier → spécifiée → prototype → vérifiée → disponible). Preuve liée : recette `apps/web/e2e/atelier-nouveau.mjs`, tests `apps/web/src/modules/atelier/nouveau/nouveau.test.ts` et `packages/atelier-model/src/commandes/commandes.test.ts` ; compte rendu `lots/lot-3a.md`.

| Champ | Contenu |
| --- | --- |
| Identité | DA-03-15 (M05, étape cible P1). Interprétation retenue : modélisation de la construction = définition constructive déclarée des éléments du bâtiment (types, épaisseurs, hauteurs, alignement, décalages, statut extérieur, statut de conception, structure déclarée) ; aucun calcul, aucune vérification ni aucune composition inventés. Sous-exigences : -a paramètres constructifs typés ; -b types et héritage (DA-05-14, DA-05-15) ; -c valeurs déclarées, statut et provenance ; -d « non évalué » explicite. |
| Situation utilisateur | Décrire comment chaque élément est construit (type, dimensions, position par rapport à son axe ou à son niveau) avec ce que le projet déclare, en distinguant ce qui est saisi, importé, calculé ou à confirmer. |
| Entrées et unités | Paramètres constructifs du tableau 5.2 : `mur` (`typeId`, `epaisseur`, `hauteur` ou `niveauHaut`, `alignement`, `exterieur`), `dalle` (`epaisseur`, `decalageBase`), `escalier` (`largeur`, `hauteurAFranchir`, `marches`, `contremarches`, `epaisseurPaillasse`, `decalageBase`), `poteau` (`formeId`, `largeur`, `profondeur`, `hauteur`, `angle`, `statutConception`), `solide` (`hauteur`, `decalageBase`, `epaisseur`) ; grandeurs `{ value, unit }` en m ou °, aires en m² ; `structureDeclaree` (système, portée, charge « à confirmer »). |
| Comportement | **Cycle.** Sélection → inspecteur, section « Construction » → paramètre ou type → aperçu (écarts avec le type, objets touchés) → contrôle → validation ; commandes de la classe (`mur.modifier`, `dalle.modifier`, `escalier.modifier`, `poteau.*`, `solide.modifier`) ; types : `type.definir`, `type.modifier` ; propriétés : `propriete.definir`. |
| | **Alignement et position.** `alignement` (gauche, axe ou droite) précise de quel côté de l'axe se développe l'épaisseur ; changer l'alignement déplace la matière, pas l'axe : l'aperçu montre l'emprise avant et après et liste les ouvertures et les pièces touchées. `exterieur` est la valeur déclarée à l'import d'après `exteriorWallIds` (§5.2), jamais recalculée à partir de la géométrie. |
| | **Déclaré, jamais vérifié.** `statutConception` des poteaux est repris tel quel du prototype, sans interprétation ; `structureDeclaree` (système, portée, charge) porte un statut explicite « à confirmer » (R4), jamais une justification structurelle ; aucune section, aucune portée, aucune charge n'est calculée, vérifiée ni suggérée (R3) ; les propriétés portent `provenance` et `statut` (DA-06-07). |
| | **Contrôles.** Dimension ≤ 0, unité fausse (T03), `hauteur` et `niveauHaut` à la fois, `typeId` inconnu : refusés avec `chemin` ; valeur absente : « non évaluée » et quantités sans valeur (jamais 0) ; calque verrouillé : lot refusé en entier ; aucune composition en couches ni aucun matériau n'existe au lot 3a. |
| Données et dépendances | Paramètres des classes citées ; `definition` des types ; relations `heberge` et `delimite` touchées par un changement d'épaisseur ou d'alignement (recalculées ; R12 si une ouverture sort de son hôte) ; `structureDeclaree`, `hypothese`, `source` (statut explicite, R4). Événement de commande validée : vues, quantités et bilan Harmonie « à recalculer » (R11, T07) ; microversion +1. |
| Résultats | Éléments à définition constructive déclarée, écarts au type visibles, valeurs absentes « non évaluées », statuts et provenances lisibles ; effets listés ; inverse = valeurs précédentes. |
| Cas limites | **Valeurs.** Mur de type `non-type` : conservé, aucune valeur déduite ; changement d'alignement qui ferait sortir une ouverture : « à réparer » avec propositions ; poteau sans `statutConception` : « non évalué » ; hauteur d'escalier qui contredit les élévations : contradiction affichée avec les valeurs retenues (DA-07-10), jamais tranchée en silence. |
| | **Concurrence et réseau.** `baseRevision` dépassée et objet ou type modifié depuis → 409 avec `conflits[].objetId` ; un objet supprimé par autrui ne réapparaît pas ; même `requestId` → une seule révision (T06). Hors ligne : réducteur local, file Dexie, rejeu dans l'ordre, brouillon si incompatible. 403 / 404 / 423 selon R13. |
| Compatibilité | Import P.118 : `typeId` (`cloison`, `mur`, `non-type`), `epaisseur`, `hauteur`, `alignement` et `exterieur` (d'après `exteriorWallIds`) des 220 murs ; 120 poteaux de forme `basic-square` avec leur `statutConception` ; `meta.structure`, `meta.assumptions`, `meta.sources` en hypothèses, sources et valeurs « à confirmer » (R4) ; aucune valeur recalculée. IFC (lot 6) : `IfcWallType`, `IfcPropertySet` (DA-06-07) ; couches (`IfcMaterialLayerSet`) non produites : aucune composition n'existe. DXF : sans objet. |

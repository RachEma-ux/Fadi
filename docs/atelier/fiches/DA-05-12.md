# DA-05-12 — Objects / Objets — module M04 → Atelier — lot 3a

| Champ | Contenu |
| --- | --- |
| Identité | DA-05-12 (M04, étape cible P1). Contrat commun des objets du modèle : identité, classe, niveau, calque, nom, paramètres typés, représentations. Sous-exigences : -a inspecteur d'objet ; -b renommer ; -c dupliquer ; -d supprimer ; -e identités et références stables. Les paramètres propres à chaque classe sont spécifiés dans la fiche de la classe (par exemple DA-07-10 pour l'escalier) ; le recalcul des représentations l'est en DA-03-09. |
| Situation utilisateur | Inspecter n'importe quel objet : savoir ce qu'il est, où il est, de quoi il dépend, d'où viennent ses valeurs, puis le renommer, le dupliquer ou le supprimer sans perdre ni inventer son identité. |
| Entrées et unités | `objetId` stable `${projectId}_${id}` ; `classe` (tableau 5.2) ; `niveauId` ; `calqueId` (classes qui en portent) ; `nom` ; paramètres typés `{ value, unit }` ; points `{ x, y, frame: "local", unit: "m" }`. Commandes de la classe (`mur.modifier`, `solide.modifier`, `esquisse.modifier`…) ; copie : `transformer.copier` ; suppression : commandes `*.supprimer`. |
| Comportement | **Cycle.** Sélection → inspecteur (classe, identifiant, niveau, calque, nom, paramètres avec unité et provenance, relations, représentations) → modification d'un champ → aperçu (valeurs dérivées recalculées, effets listés) → contrôle → validation ; Échap restaure la valeur. Plusieurs objets : champs communs seulement ; une modification d'une sélection mixte est un seul lot. |
| | **Identité.** Un identifiant n'est jamais réutilisé après suppression ; une copie reçoit de nouvelles identités ; une commande rejouée (même `requestId`) renvoie les identifiants déjà attribués, jamais d'autres (T06). Les objets importés gardent les identifiants de l'export (R7). |
| | **Valeurs.** Les champs dérivés (aire calculée, distance d'une ouverture) sont en lecture seule : les modifier est refusé (400). Une valeur absente est « non évaluée » (R3), jamais 0 ni vide ; provenance et statut sont affichés (DA-06-07). Les représentations (`plan-2d`, `solide-3d`, `symbole`) sont affichées avec leur autorité (`parametrique`, `derivee`, `importee`), leur moteur, sa version et leur empreinte, jamais éditées à la main (R15). |
| | **Contrôles.** Unité différente de l'unité attendue refusée (T03) ; nom vide refusé ; objet d'un calque verrouillé ou d'un niveau supprimé : lot refusé en entier ; objet à représentation importée (autorité `importee`) : seules les commandes `transformer.*` sont admises (R16, lot 6). |
| | **Palette (UX2) et aide (UX4).** « propriétés », « inspecteur » ; synonymes « properties », « objet » ; actif si au moins un objet est sélectionné ; exemple court : renommer un mur. |
| Données et dépendances | Classes et relations du tableau 5.2 (`heberge`, `delimite`, `joint-a`, `contient`, `porte`, `relie`, `reference`) ; entités `definition`, `occurrence`, `representation`. Suppression d'un objet référencé : les références (cotation, étiquette, ouverture) passent « à réparer » avec propositions (R12, `reference.reparer`). Événement de commande validée : vues, quantités et bilan Harmonie « à recalculer » (R11, T07) ; microversion +1. |
| Résultats | Objet modifié, renommé, dupliqué ou supprimé ; fiche de l'objet à jour ; références à réparer listées ; inverse = valeurs précédentes (un objet supprimé est recréé avec son identité). |
| Cas limites | **Données.** Champ sans unité, unité inconnue, nom vide, valeur non numérique : refusés avec `chemin` ; objet inconnu ou supprimé : refusé ; classe sans commande de modification : lecture seule ; représentation dérivée en échec : objet valide dans le modèle, représentation « indisponible » listée. |
| | **Concurrence et réseau.** `baseRevision` dépassée et objet modifié ou supprimé depuis → 409 avec `conflits[].objetId` et état serveur, résolution explicite côté client ; un objet supprimé par autrui ne réapparaît pas, même après un rejeu hors ligne (brouillon) ; même `requestId` → une seule révision (T06). Hors ligne : réducteur local, file Dexie, rejeu dans l'ordre. 403 / 404 / 423 selon R13. |
| Compatibilité | Import P.118 : 220 `mur`, 84 `porte`, 126 `fenetre`, 120 `poteau`, 32 `escalier`, 6 `dalle`, 45 `piece`, 807 `solide` de rôle `solid`, 64 `cotation`, 95 `texte`, avec leurs identifiants d'origine (par exemple `EX118-mezz-W-009`, `EX118-mezz-D-001`) et la provenance `import` ; aucune valeur recalculée à l'import. |
| | IFC : identité par `GlobalId` à fixer à l'annexe C (lot 6) ; un objet importé d'IFC a l'autorité `importee` et aucun historique paramétrique inventé (R16). DXF : sans objet. |

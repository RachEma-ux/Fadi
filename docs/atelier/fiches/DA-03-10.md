| Champ | Contenu |
| --- | --- |
| Identité | DA-03-10 (M02, étape cible P1). Interprétation retenue : modélisation directe = modifier un objet en agissant sur sa forme à l'écran (poignées, faces, déplacement) plutôt qu'en saisissant des paramètres ; chaque geste se résout en commande typée sur les paramètres canoniques (R9, R15). Sous-exigences : -a protocole commun des gestes ; -b correspondance poignée ou face → paramètre ; -c refus sur objets importés. Fiches de gestes : DA-02-14 (poignées 2D, lot 3a), DA-02-01 (déplacer), DA-04-07 (pousser / tirer, lot 3b). |
| Situation utilisateur | Modifier un objet en le manipulant directement, avec un résultat prévisible, mesuré et annulable, qui reste un objet paramétrique et non une forme figée. |
| Entrées et unités | Geste (glisser, toucher, flèches, saisie numérique, DA-02-16) ; cible : objet ou sous-élément (poignée, face, arête) ; valeurs en m ou °, points `{ x, y, frame: "local", unit: "m" }` ; accrochages DA-02-15. Aucun paramètre propre : les valeurs finales passent aux commandes de la classe (`mur.modifier`, `esquisse.modifier`, `dalle.modifier`, `poteau.*`, `solide.modifier`, `ouverture.deplacer`, `transformer.*`). |
| Comportement | **Cycle.** Survol (cible surlignée, affichage R10) → prise de la poignée ou de la face → glisser avec lecture numérique (distance, angle, nouvelles dimensions) → aperçu fantôme calculé par le même réducteur que le serveur → contrôle → relâcher ou Entrée valide ; Échap, `pointercancel` ou perte de focus annulent sans commande. |
| | **Table poignée → paramètre.** Mur : extrémités (`axe`, par `mur.modifier`) ; ouverture : le long du mur (`ouverture.deplacer`) ou largeur (`ouverture.modifier`) ; dalle : sommets (`contour`) ; poteau : `point` et `angle` ; esquisse : sommets ; solide : sommets (`contour`) en plan, faces haute, basse et latérales en 3D (DA-04-07). Le détail de chaque poignée est dans DA-02-14 (2D) et DA-04-07 (3D) ; cette fiche n'en ajoute aucune. |
| | **Invariants.** Aucun geste ne modifie le modèle avant validation ; la géométrie dérivée (maillage, symbole) n'est jamais éditée (R15) ; les objets non sélectionnés ne bougent pas ; un geste qui rend une référence incertaine la liste (« à réparer », R12) ; un geste sur un calque verrouillé, un niveau supprimé ou un objet supprimé est refusé en entier ; un objet à représentation importée (autorité `importee`) n'admet que `transformer.*` (R16). |
| | **Clavier et toucher (T16).** Chaque geste a son équivalent clavier (flèches, saisie, Entrée, Échap) et toucher (un doigt édite, deux doigts déplacent ou zooment la vue) ; la 3D suit les mêmes règles (lot 3b, accessibilité). |
| Données et dépendances | Aucune classe nouvelle ; commandes des classes manipulées. Événement de commande validée : vues et quantités « à recalculer » (R11, T07) ; microversion +1. L'état de geste (cible, poignée, accrochage) est un paramètre d'affichage (R10), jamais dans le modèle. |
| Résultats | Objet modifié, représentation dérivée recalculée ; effets listés ; entrée de journal avec inverse ; aucun état de geste conservé. |
| Cas limites | **Gestes.** Geste interrompu (`pointercancel`, perte de focus, appui d'un second doigt) : annulé sans commande ; déplacement nul : aucun lot ; aperçu invalide : couleur d'erreur et motif affichés, validation désactivée ; objet supprimé par autrui pendant le geste : 409 à la validation, rien n'est écrit. |
| | **Concurrence et réseau.** `baseRevision` dépassée et cible modifiée depuis → 409 avec `conflits[].objetId` et état serveur ; même `requestId` → une seule révision (T06). Hors ligne : réducteur local, file Dexie, rejeu dans l'ordre, brouillon si incompatible. 403 / 404 / 423 selon R13. |
| Compatibilité | Import P.118 : tous les objets natifs importés (murs, poteaux, dalles, escaliers, solides, esquisses) sont modifiables par geste, les valeurs hors du paramètre touché restant exactes. IFC : objets importés en représentation importée : `transformer.*` seulement (R16). DXF : sans objet. |
| Validation | **Unité** (`packages/atelier-model/src/poignees.test.ts`, avec DA-02-14) : pour chaque poignée de la table, le geste produit la commande attendue et les valeurs canoniques finales (jamais un maillage) ; geste annulé : aucune commande ; objet importé : seuls `transformer.*` admis ; même réducteur dans le navigateur et sur le serveur : mêmes résultats. |
| | **API** (`apps/api/src/routes/atelier-commands.test.ts`) : commandes issues de gestes → 200 et `effets` ; paramètre invalide → 400 avec `chemin` ; même `requestId` → même réponse ; `baseRevision` périmée → 409 ; rôle lecture → 403. |
| | **e2e** (`apps/web/e2e/scenarios/05-atelier.mjs`, bloc « 3D · édition directe ») : copie de travail de P.118 : étirer par poignée l'extrémité d'un mur (`EX118-mezz-W-009`), puis tirer la face haute d'un solide ; Échap en cours de geste : aucune révision ; annuler ; clavier seul ; second navigateur à la même révision. |
| Règles métier | Aucune règle réglementaire. R3 : aucune dimension complétée par un geste. R9 : tout geste se termine par une commande typée. R10 : l'état de geste est de l'affichage. R12 : références incertaines « à réparer ». R15 : une seule géométrie canonique. |

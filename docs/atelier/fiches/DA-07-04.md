# DA-07-04 — Openings / Ouvertures — module M05 → Atelier — lot 3a

**État : prototype (lot 3a)** (à spécifier → spécifiée → prototype → vérifiée → disponible). Preuve liée : recette `apps/web/e2e/atelier-nouveau.mjs`, tests `apps/web/src/modules/atelier/nouveau/nouveau.test.ts` et `packages/atelier-model/src/commandes/commandes.test.ts` ; compte rendu `lots/lot-3a.md`.

| Champ | Contenu |
| --- | --- |
| Identité | DA-07-04 (M05, étape cible P1). Une ouverture est un objet de classe `ouverture` (building.architecture) : baie sans menuiserie percée dans un mur hôte. Elle partage avec `porte` (DA-07-02) et `fenetre` (DA-07-03) un seul modèle (`murHoteId`, `position`, `largeur`, `hauteur`, `allege`, `repere`, `typeId`) et une seule famille de commandes `ouverture.*` ; cette fiche porte la mécanique commune. Sous-exigences : -a poser (`ouverture.poser`) ; -b modifier (`ouverture.modifier`) ; -c déplacer le long de l'hôte (`ouverture.deplacer`) ; -d supprimer (`ouverture.supprimer`). Référence de comportement : prototype, ouvertures qui glissent sur leur mur hôte. |
| Situation utilisateur | Percer un mur d'une baie de position et de dimensions choisies, la déplacer le long du mur, et savoir ce qui devient incertain quand le mur change. |
| Entrées et unités | `classe` (`ouverture` ici ; `porte`, `fenetre` : DA-07-02, -03) ; `murHoteId` (mur existant) ; `position` : `t` ∈ [0, 1] le long de l'axe de `a` vers `b`, ou distance saisie en m depuis l'extrémité choisie (convertie en `t` ; `distance` dérivée, jamais saisie en double) ; `largeur` > 0, `hauteur` > 0, `allege` ≥ 0 `{ value, unit: "m" }` (allège depuis la base du mur) ; `repere` (texte) ; `typeId` (définition du catalogue). |
| | Unité autre que m refusée (T03). Aucune dimension, allège, repère ni type par défaut (R3) : `largeur` est requise pour le contrôle d'emprise ; `hauteur` et `allege` absentes restent « non évaluées » (vide 3D non construit) ; une allège de 0 m est une saisie explicite, jamais une hypothèse. |
| Comportement | **Cycle.** Outil « Ouverture » → survol d'un mur (hôte candidat surligné) → paramètres (largeur, hauteur, allège, repère, type) → position par clic accroché ou distance saisie → aperçu fantôme avec distances aux extrémités du mur et aux ouvertures voisines → contrôle → validation ; Échap annule sans commande. |
| | **Commandes.** `ouverture.poser` (classe `porte`, `fenetre` ou `ouverture`) ; `ouverture.modifier` (dimensions, allège, repère, type) ; `ouverture.deplacer` (le long de l'hôte : nouveau `t` ; changer d'hôte est une extension) ; `ouverture.supprimer`. Changer de classe n'est pas une modification sur place : suppression et pose dans un même lot, identifiant nouveau, références « à réparer ». |
| | **Contrôle d'emprise.** L'emprise horizontale (`t` fois la longueur de l'axe, plus ou moins la demi-largeur) doit tenir dans l'axe de l'hôte à la tolérance de longueur (DA-01-01), sinon refus avec la plage de `t` admise. Recouvrement avec une autre ouverture du même hôte : refusé à la pose, signalé sans correction pour une donnée importée. Allège + hauteur au-delà de la hauteur du mur : refusé si cette hauteur est évaluée, sinon contrôle « non évalué ». Emprise qui mord sur une jonction : signalée dans l'aperçu. |
| | **Suivre l'hôte (R12).** Hôte déplacé : l'ouverture suit (`t` inchangé). Hôte scindé : réaffectation (DA-07-01). Hôte raccourci ou étiré : emprise hors du mur, ouverture « à réparer » avec propositions (déplacer dans l'emprise, supprimer, détacher), jamais déplacée en silence. Hôte supprimé : refusé tant que des ouvertures y sont hébergées, sauf option explicite de les supprimer avec lui (listées). Palette (UX2) : « ouverture » ; synonymes « baie », « opening » ; exemple court : percer une baie dans un mur (exemple, jamais valeur par défaut) ; aide (UX4). |
| Données et dépendances | Classes `ouverture`, `porte`, `fenetre` ; relation `heberge-par` (ouverture → mur) et son inverse `heberge` ; caractéristique `ouverture:centre` (cotations) ; `typeId` vers une définition ; symbole en plan et vide en 3D dérivés (R15). Événement `atelier.commande.validee` : vues, quantités et bilan Harmonie « à recalculer » (R11, T07) ; microversion +1. |
| Résultats | Ouverture posée, modifiée, déplacée ou supprimée ; `distance` dérivée affichée ; effets dans le panneau des modifications (références à réparer, quantités à recalculer) ; inverse = valeurs précédentes enregistrées. |
| Cas limites | **Hôte et géométrie.** `murHoteId` jamais existé → 400 avec `chemin` ; hôte supprimé par autrui depuis `baseRevision` → 409 avec `conflits[].objetId` ; objet importé sans hôte : conservé avec le problème « hôte introuvable », jamais supprimé. Largeur ≤ 0 ; mur plus court que la largeur ; emprise hors du mur hôte ; calque de l'hôte verrouillé : refus du lot en entier. |
| | **Concurrence, réseau, droits.** `baseRevision` dépassée et ouverture ou hôte modifié depuis → 409 avec état serveur, résolution explicite ; même `requestId` → aucune seconde révision (T06) ; hors ligne : réducteur local, file Dexie, rejeu dans l'ordre, brouillon si incompatible ; 403 motivé, 404 sans accès, 423 pendant une réservation d'autrui (R13). |
| Compatibilité | Import P.118 (section 6) : seulement des portes et des fenêtres (84 + 126 = 210 ouvertures hébergées, relation `heberge-par` complète), aucune `ouverture` générique ; `t` conservé, `distance` dérivée, `sill` → `allege`, `mark` → `repere` ; hôte absent → objet créé et problème « hôte introuvable ». |
| | IFC (annexe C, lot 6) : `IfcOpeningElement` + `IfcRelVoidsElement` (mur → ouverture) ; `IfcRelFillsElement` lorsqu'une porte ou une fenêtre remplit l'ouverture ; une `ouverture` seule reste un vide. DXF : aucune sortie propre. |
| Validation | **Unité** (`packages/atelier-model/src/commandes/ouverture.test.ts`) : pose valide (`t` conservé, `distance` dérivée) ; emprise hors du mur refusée avec la plage admise ; largeur ≤ 0, unité ≠ m, hôte inexistant refusés ; recouvrement refusé ; déplacement le long de l'hôte : dimensions inchangées ; hôte raccourci : « à réparer » avec propositions ; changement de classe : un lot, références à réparer ; inverse restitue valeurs et références bit à bit. |

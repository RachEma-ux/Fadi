| Situation utilisateur | L'architecte organise le dessin par calques (murs, cloisons, mobilier, cotations…) : il en crée, change leur couleur, en verrouille pour ne pas les modifier par erreur, en masque pour lire le plan. Résultat : une liste ordonnée de calques de projet, chaque objet portant un calque existant, et une vue filtrée sans changer la révision quand le masquage n'est que visuel. |
| Entrées et unités | `nom` (texte non vide après suppression des espaces de bord, unique dans le projet ; comparaison sensible à la casse **proposée, à confirmer**) ; `couleur` et `remplissage` (couleur sRVB `#rrggbb`, sans unité ; `remplissage` facultatif : absent = « non renseigné », jamais une couleur inventée) ; `visible` (booléen, valeur de projet) ; `verrouille` (booléen) ; `ordre` (entier ≥ 0, unique dans le projet). | Comportement | Commandes de la famille `calque.*` (annexe B ; noms détaillés **proposés, à figer par L1.2**) : `calque.creer`, `calque.modifier` (nom, couleur, remplissage, visible, verrouille), `calque.reordonner`, `calque.supprimer`, `calque.affecter` (`cibles: objetIds`, `params: { calqueId }`). Inverses : `calque.supprimer` ↔ `calque.creer` (même identifiant, même ordre) ; `calque.modifier` / `calque.affecter` ↔ même commande avec les anciennes valeurs ; `calque.reordonner` ↔ ordre précédent.<br>Cycle UX3 : navigateur du projet (repère « Calques ») → inspecteur → **aperçu** (objets concernés surlignés, effectif affiché) → contrôle → validation.<br>**Supprimer** un calque non vide exige `params.calqueDestinationId` : les objets sont réaffectés dans le même lot (liste montrée avant accord), sinon refus. **Verrouillé** (**exigence de cette fiche**, conforme au champ `verrouille` du cahier §5.2) : toute commande qui crée, modifie ou supprime un objet d'un calque verrouillé est refusée avec le motif « calque verrouillé : <nom> » — y compris un `transformer.*` sur une sélection mixte (lot atomique : tout ou rien). Les commandes `calque.*` elles-mêmes restent permises sur un calque verrouillé (pour le déverrouiller).<br>**Visibilité** : `calque.modifier { visible }` change la valeur de projet (commande, révision + 1) ; le masquage rapide dans la zone de travail (œil du navigateur) est un état d'affichage local, jamais une commande (R10) — **recommandation** de cette fiche, voir la question « contradiction visibilité » dans Extensions. Un objet d'un calque masqué n'est ni sélectionnable ni accrochable dans la vue. |

Microversion `model_revision + 1` par lot validé. |

| Cas limites | Nom vide ou déjà pris → 400 `{ chemin: "commands[0].params.nom", message }`. Couleur hors motif `#rrggbb` → 400. Suppression du dernier calque → refus si des objets existent (**proposée, à confirmer** : un objet a toujours un calque). Suppression d'un calque non vide sans destination → 400 listant les objets. Destination = calque supprimé ou verrouillé → refus. Affectation vers ou depuis un calque verrouillé → refus. Ordre en double → 400. À l'import, calque cité par un objet mais non déclaré → calque créé **et** listé dans le rapport (jamais d'objet sans calque ni de calque créé silencieusement). Deux utilisateurs renomment le même calque → 409 `{ objetId, motif, etatServeur }`. Lecteur → 403 ; réservation d'autrui → 423. Requête répétée (même `requestId`) → réponse enregistrée (T06). Hors ligne : commandes `calque.*` exécutables localement, rejouées à la reconnexion ; incompatibles → brouillon visible. |

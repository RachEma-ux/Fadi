# DA-05-01 — Layers / Calques — module M04 → Atelier — lot 3a

**État : prototype (lot 3a)** (à spécifier → spécifiée → prototype → vérifiée → disponible). Preuve liée : recette `apps/web/e2e/atelier-nouveau.mjs`, tests `apps/web/src/modules/atelier/nouveau/nouveau.test.ts` et `packages/atelier-model/src/commandes/commandes.test.ts` ; compte rendu `lots/lot-3a.md`.

| Champ | Contenu |
| --- | --- |
| Identité | DA-05-01 (M04, étape cible P1). Sous-exigences : -a créer, renommer et réordonner un calque ; -b couleur et remplissage ; -c visibilité (`visible`) ; -d verrouillage (`verrouille`) ; -e affecter des objets à un calque ; -f supprimer un calque. Référence de comportement : prototype, les 20 calques de P.118 (couleur, remplissage, visible, verrouillé). |
| Situation utilisateur | Organiser les objets d'un projet en calques nommés pour les colorer, les masquer ou les protéger ensemble, sans changer leur nature ni leur niveau. |
| Entrées et unités | `calque` : `nom` (texte non vide, unique dans le projet, casse ignorée), `couleur`, `remplissage` (valeurs du prototype conservées telles quelles ; type précis fixé au lot 1 d'après les 20 calques importés, sans interprétation), `visible`, `verrouille` (booléens), `ordre` (entier : rang dans le panneau et ordre de superposition). Aucune grandeur : pas d'unité. |
| | Affectation : `cibles` (objets des classes qui portent `calqueId`) et `calqueId` de destination. Le calque actif (celui qui reçoit les nouveaux objets) est un paramètre de session, jamais du modèle (R10). |
| Comportement | **Cycle.** Panneau Calques (liste ordonnée : pastille de couleur, œil, cadenas, nombre d'objets) → sélection d'un calque ou d'objets → paramètres → aperçu (objets touchés comptés par niveau, effets listés) → contrôle → validation ; un clic sur l'œil ou le cadenas valide en un geste, annulable ; Échap annule sans commande. |
| | **Commandes** (famille `calque.*` de l'annexe B ; sous-commandes proposées par cette fiche) : `calque.creer`, `calque.modifier` (nom, couleur, remplissage, `visible`, `verrouille`, `ordre`), `calque.supprimer` (avec un calque de destination si des objets existent), `calque.affecter` (une sélection de plusieurs classes est un seul lot : « Affecter N objets au calque X »). |
| | **R10 : décision.** `visible` et `verrouille` sont des propriétés du calque dans le modèle : elles viennent du prototype (R7 interdit de les omettre), elles sont partagées par toute l'équipe, elles déterminent le contenu des documents dérivés (R11) et `verrouille` est une protection que le serveur doit faire respecter (R9, R13). Les basculer est donc une commande (révision +1, journal, inverse) ; plusieurs bascules simultanées forment un seul lot. N'entrent jamais dans le modèle : caméra, sélection, calque actif, niveau visible, mode, filtres de classe et ensembles d'affichage (DA-05-03). Visibilité effective d'un objet = `visible` du calque ET filtres locaux ; un objet masqué reste dans les quantités et les exports. |
| | **États.** Verrouillé : visible et accrochable, non modifiable. Masqué : ni dessiné, ni sélectionnable, ni accrochable. Le masquage n'est pas une protection : seul `verrouille` fait refuser une commande. |
| | **Contrôles.** Nom vide ou en double refusé ; `ordre` hors plage refusé (les autres rangs sont décalés dans le même lot, effets listés) ; suppression d'un calque non vide sans calque de destination refusée avec la liste des objets (jamais de réaffectation silencieuse, R12) ; destination inconnue ou verrouillée refusée ; objet dont le calque source est verrouillé : lot refusé en entier ; `calqueId` ne se modifie que par `calque.affecter` (un seul chemin de contrôle). |
| | **Palette (UX2) et aide (UX4).** « calque » ; synonymes « layer », « couche » ; affectation active si au moins un objet d'une classe qui porte `calqueId` est sélectionné ; exemple court : verrouiller un calque. |
| Données et dépendances | Classe `calque` (projet) ; `calqueId` porté, au tableau 5.2, par `mur`, `solide`, `esquisse.*`, `cotation`, `texte`, `etiquette` ; `porte`, `fenetre` et `ouverture` suivent le calque de leur mur hôte (dérivé, non stocké ; proposition de cette fiche). Les autres classes (dalle, toiture, escalier, pièce, espace, zone, poteau, reference-plan) n'ont pas de `calqueId` au tableau 5.2 : si l'export P.118 leur associe un calque, le contrat doit être complété avant le lot 1 (R7) — question au chef de projet. |
| | Événement `atelier.commande.validee` : vues, quantités et bilan Harmonie « à recalculer » (R11, T07) ; microversion +1. |
| Résultats | Calque créé, modifié, supprimé ou réordonné ; objets réaffectés (état « local » puis « synchronisé ») ; effets listés dans le panneau des modifications ; inverse = valeurs précédentes, y compris les anciens `calqueId` des objets réaffectés. |
| Cas limites | **États.** Création ou modification d'un objet sur un calque verrouillé : lot refusé en entier, rien n'est écrit ; dernier calque libre verrouillé : création d'objets inactive dans la palette ; calque masqué : objets invisibles et non sélectionnables mais présents dans le modèle. |
| | **Concurrence et réseau.** `baseRevision` dépassée et calque ou cible modifié depuis → 409 avec `conflits[].objetId` (calque ou objet) et état serveur, résolution explicite côté client ; calque verrouillé par autrui depuis `baseRevision` : 409, déjà verrouillé : 400 avec motif ; objet supprimé par autrui pendant l'affectation : il ne réapparaît pas ; même `requestId` → réponse enregistrée (T06). Hors ligne : réducteur local, file Dexie, rejeu dans l'ordre, brouillon si incompatible (calque supprimé ou rempli entre-temps). 403 / 404 / 423 selon R13. |
| Compatibilité | Import P.118 : 20 `calque` avec `nom`, `couleur`, `remplissage`, `visible`, `verrouille` conservés exactement et `ordre` d'origine, sans renommage ni fusion (R7 : rapport nominatif des 20). DXF : table des calques à l'export des vues (nom et couleur ; le remplissage n'a pas d'équivalent, omis au rapport), à spécifier avec l'export (lot 5). |
| | IFC : `IfcPresentationLayerWithStyle` (`LayerOn`, `LayerBlocked`) candidat, à confirmer à l'annexe C (lot 6) ; sinon omis nominativement au rapport d'échange. |
| Validation | **Unité** (`packages/atelier-model/src/commandes/calque.test.ts`) : création ; nom en double refusé ; `verrouille` activé : `mur.modifier` sur ce calque refusé et lot mixte refusé en entier ; suppression d'un calque non vide sans destination refusée, avec destination : objets réaffectés et listés ; `visible` modifié : révision +1 et vues « à recalculer » ; inverse restitue calques et `calqueId` bit à bit ; calque actif et filtres ne produisent aucune commande. |
| | **API** (`apps/api/src/routes/atelier-commands.test.ts`) : `calque.modifier` → 200, révision +1, `effets` ; même `requestId` → même réponse ; `baseRevision` périmée et calque modifié → 409 avec `conflits[].objetId` ; nom vide → 400 avec `chemin` ; rôle lecture → 403 ; réservation d'autrui → 423. |
| | **e2e** (`apps/web/e2e/scenarios/05-atelier.mjs`, bloc « Organisation · calques ») : copie de travail de P.118 : les 20 calques du rapport d'import listés avec leurs valeurs ; masquer un calque : second navigateur à la même révision, annuler, rétablir ; verrouiller un calque puis tenter de déplacer un de ses murs : refus motivé, aucun changement ; panoramique et zoom : révision inchangée (R10). |
| Règles métier | Aucune règle réglementaire. R3 : aucune convention de nommage de calques (normative ou d'agence) n'est imposée ni présumée ; aucune couleur ou aucun remplissage par défaut n'est une donnée de projet. R9 : toute bascule de `visible` ou `verrouille` passe par `calque.modifier`. R10 : décision ci-dessus. |
| Extensions à spécifier | Calques gelés ; calques imbriqués ; états de calques enregistrés et partagés (lot 5, vues) ; types de trait et épaisseurs par calque (non fournis, R3) ; calque des classes sans `calqueId` ; calques hérités d'un import DXF (lot 6). |

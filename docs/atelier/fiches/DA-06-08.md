# DA-06-08 — Building-element classification / Classification des éléments — module M05 → Atelier — lot 3a

**État : prototype (lots 3a, 6)** (à spécifier → spécifiée → prototype → vérifiée → disponible). Preuve liée : `packages/atelier-model/src/commandes/commandes.test.ts` (`classification.affecter`), export IFC (`echanges/echanges.test.ts`) ; comptes rendus `lots/lot-3a.md`, `lot-6.md`.

| Champ | Contenu |
| --- | --- |
| Identité | DA-06-08 (M05, étape cible P1). Sous-exigences : -a classe IFC d'un objet ou d'une définition ; -b référence de classification (système, code) ; -c retrait (« non classé »). Ces deux déclarations sont distinctes de la classe Fadi (DA-05-02, nature de l'objet). Contrat : `classification.affecter` (annexe B), classe IFC et code de classification facultatifs (§5.2). |
| Situation utilisateur | Déclarer à quelle classe IFC et à quel code d'un système de classification appartient un élément, pour la nomenclature et l'export, sans que Fadi le devine. |
| Entrées et unités | `classification.affecter` : `cible` (`objetId`, ou identifiant de définition : `typeId`, `blocId` d'un composant), `classeIfc` (nom de classe du schéma IFC 4.3, par exemple `IfcWall`) et/ou `classification` `{ systeme, edition, code, libelle }` ; `null` retire (« non classé »). `systeme` est nommé par l'utilisateur ; un `code` sans `systeme` est refusé (ambigu). Aucune grandeur : pas d'unité. |
| Comportement | **Cycle.** Sélection (objets ou définition) → onglet Classification de l'inspecteur → classe IFC (liste du schéma, recherche) et/ou système, édition, code → aperçu (cibles, valeurs remplacées, héritage de la définition) → contrôle → validation ; Échap annule sans commande. Sélection mixte : un seul lot « Classer N objets ». |
| | **R3 : jamais devinée.** Aucune classe IFC ni aucun code n'est déduit du nom, de la forme, du type, du rôle ou de la classe Fadi. Un objet sans affectation est « non classé ». La correspondance classe Fadi → classe IFC (annexe C, lot 6) ne sert qu'à l'export, est nommée au rapport d'échange et n'écrit rien dans le modèle. |
| | **Héritage.** Une classification posée sur une définition (type, composant) s'applique à ses occurrences ; celle de l'occurrence la surcharge ; modifier la définition ne réécrit jamais une surcharge. |
| | **Contrôles.** Classe IFC absente du schéma 4.3 chargé : refusée, avec la liste des classes proches ; code ou système vide : refusé ; aucun référentiel de codes n'est livré : le code est validé seulement comme texte non vide ; aucune cohérence croisée classe Fadi / classe IFC n'est contrôlée au lot 3a ni présentée comme vérifiée (contrôle déclaré non exécuté, annexe C, lot 6) ; cible d'un calque verrouillé : lot refusé en entier. |
| | **Palette (UX2) et aide (UX4).** « classification », « classe IFC » ; synonymes « classer », « IFC » ; actif si au moins un objet ou une définition est sélectionné ; exemple court : affecter une classe IFC à un type de mur. |
| Données et dépendances | Classification portée par les occurrences et les `definition` (comme DA-06-07) : `classeIfc` et référence de classification, provenance (`saisie`, `import`) et statut (`declaree`, `a-verifier`). Liste des classes IFC 4.3 : issue du schéma publié, versionnée, jamais saisie à la main. Événement de commande validée : quantités et bilan « à recalculer » (R11, T07) ; microversion +1. |
| Résultats | Classe IFC et référence de classification posées, remplacées ou retirées ; état « non classé » visible ; effets listés ; inverse = valeurs précédentes. |
| Cas limites | **Valeurs.** Classe IFC valide mais incohérente avec la classe Fadi (par exemple `IfcDoor` sur un `mur`) : admise au lot 3a avec le statut `declaree`, signalée dans le panneau des problèmes dès que l'annexe C est chargée (lot 6) ; même code sur plusieurs objets : admis ; système inconnu : admis, nommé tel quel. |
| | **Concurrence et réseau.** `baseRevision` dépassée et cible modifiée depuis → 409 avec `conflits[].objetId` ; un objet supprimé par autrui ne réapparaît pas ; même `requestId` → une seule révision (T06). Hors ligne : réducteur local, file Dexie, rejeu dans l'ordre, brouillon si incompatible. 403 / 404 / 423 selon R13. |
| Compatibilité | Import P.118 : aucune classification déduite des types (`cloison`, `mur`, `non-type`), des rôles de solides ou des noms ; un champ de classification présent dans l'export est repris tel quel (provenance `import`), sinon l'objet est « non classé » (R7, rapport nominatif). |
| | IFC : `IfcClassification` et `IfcClassificationReference` (`ReferencedSource`, `Identification`) à l'import et à l'export ; classe IFC d'une entité importée conservée telle que lue (R16) ; `IfcWallType` et autres types : DA-05-14 et DA-05-15. DXF : sans objet. |
| Validation | **Unité** (`packages/atelier-model/src/commandes/classification.test.ts`) : affectation à un objet, à une définition, héritage et surcharge ; classe IFC inconnue refusée ; code sans système refusé ; aucun objet classé sans commande (état importé de P.118 : tous « non classés » hors champs d'export) ; retrait ; inverse restitue. |
| | **API** (`apps/api/src/routes/atelier-commands.test.ts`) : `classification.affecter` → 200 et `effets` ; classe inconnue → 400 avec `chemin` ; même `requestId` → même réponse ; `baseRevision` périmée → 409 ; rôle lecture → 403. |
| | **e2e** (`apps/web/e2e/scenarios/05-atelier.mjs`, bloc « Propriétés · classification ») : copie de travail de P.118 : tous les objets « non classés » au départ ; affecter `IfcWall` à un type de mur (hérité par ses murs) et un code de classification à `EX118-mezz-W-009` ; annuler ; recharger : identique ; second navigateur à la même révision. |
| Règles métier | Aucune règle réglementaire. R3 : une classification n'est jamais devinée ni complétée ; aucun système de classification (CFC, Uniclass, OmniClass…) n'est livré ni présumé. R16 : un objet importé d'IFC n'a pas d'historique paramétrique inventé. |
| Extensions à spécifier | Référentiels de classification chargés explicitement (édition, source, version) avec validation des codes ; contrôle croisé classe Fadi / classe IFC (annexe C, lot 6) ; classification en lot par règle (lot 8, proposition jamais imposée). |

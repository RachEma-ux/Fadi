# DA-03-09 — Parametric modeling / Modélisation paramétrique — module M02 → Atelier — lot 3a (représentation 3D : lot 3b)

**État : prototype (lots 1–5)** (à spécifier → spécifiée → prototype → vérifiée → disponible). Preuve liée : `packages/atelier-model/src/commandes/commandes.test.ts`, `documents/documents.test.ts` (représentations recalculées de façon reproductible) ; comptes rendus `lots/lot-3a.md`, `lot-5.md`.

| Champ | Contenu |
| --- | --- |
| Identité | DA-03-09 (M02, étape cible P1). Interprétation retenue : modélisation paramétrique = chaque objet a des paramètres typés (§5.2) dont dépendent ses représentations dérivées ; les contraintes (DA-06-01, DA-06-02, lot 5) et les expressions (DA-06-09, P2) n'en font pas partie. Sous-exigences : -a modifier un paramètre canonique ; -b recalcul reproductible des représentations ; -c paramètres dérivés en lecture seule. Contrôle commun de la section : représentation identifiée, géométrie valide dans les tolérances du cas. |
| Situation utilisateur | Changer une valeur (épaisseur, hauteur, largeur, élévation) et obtenir un objet à jour dans toutes ses représentations, avec la liste de ce qui en dépend, sans perdre l'identité de l'objet. |
| Entrées et unités | Paramètres canoniques du tableau 5.2, tous `{ value, unit }` (m, °) ou points `{ x, y, frame: "local", unit: "m" }` ; commande de la classe : `mur.modifier`, `ouverture.modifier`, `dalle.modifier`, `escalier.modifier`, `poteau.*`, `solide.modifier`, `esquisse.modifier`, `niveau.modifier` ; champs dérivés : lecture seule. |
| Comportement | **Cycle.** Sélection → inspecteur (paramètres éditables, dérivés marqués) → nouvelle valeur (saisie, ou poignée, DA-03-10) → aperçu : représentation recalculée par le même réducteur que le serveur, relations touchées et effets listés → contrôle → validation ; Échap restaure la valeur. |
| | **Recalcul reproductible (R15).** Représentations `plan-2d`, `symbole` et (lot 3b) `solide-3d` : autorité `parametrique` (canonique) ou `derivee`, `moteur`, `versionMoteur`, `empreinteEntrees` ; mêmes paramètres et même version du moteur donnent la même représentation, à l'identique ; empreinte inchangée : aucun recalcul ; version du moteur changée : représentation « à recalculer », signalée, jamais remplacée en silence. |
| | **Dépendances.** Une modification se propage seulement par les relations du modèle : `heberge` (les ouvertures gardent `t`, `largeur`, `hauteur` ; contrôle d'emprise), `joint-a` et `delimite` (dérivées, recalculées), cotations rattachées (valeur recalculée, référence conservée). Une référence rendue incertaine passe « à réparer » avec propositions (R12). Aucun objet non sélectionné n'est modifié par le paramètre d'un autre. |
| | **Contrôles.** Unité fausse refusée (T03) ; valeur hors borne ou dimension ≤ 0 refusée ; `hauteur` et `niveauHaut` à la fois refusés ; champ dérivé modifié : 400 avec `chemin` ; objet d'un calque verrouillé : lot refusé en entier ; objet à représentation importée (autorité `importee`) : aucun paramètre n'est inventé (R16). |
| | **Hors périmètre.** Arbre de construction ou historique paramétrique ; contraintes géométriques et dimensionnelles (lot 5, DA-06-01, DA-06-02) ; formules et règles (DA-06-09, DA-06-10 : P2). |
| Données et dépendances | Paramètres des classes `niveau`, `mur`, `porte` / `fenetre` / `ouverture`, `dalle`, `escalier`, `piece`, `poteau`, `solide`, `esquisse.*` ; entité `representation` ; relations `heberge`, `joint-a`, `delimite`, `reference`. Événement de commande validée : vues, quantités et bilan Harmonie « à recalculer » (R11, T07) ; microversion +1. |
| Résultats | Objet à jour avec ses représentations recalculées et identifiées ; effets (objets dépendants, références à réparer) dans le panneau des modifications ; inverse = valeurs précédentes. |
| Cas limites | **Valeurs.** Paramètre absent : « non évalué », représentation correspondante « non évaluée » et listée (jamais 0 ni valeur déduite) ; changement d'épaisseur d'un mur qui ferait sortir une ouverture de son hôte : ouverture « à réparer » avec propositions ; deux paramètres incompatibles entre eux : refus expliqué par le champ en conflit. |
| | **Concurrence et réseau.** `baseRevision` dépassée et objet modifié ou supprimé depuis → 409 avec `conflits[].objetId` et état serveur, résolution explicite côté client ; un objet supprimé par autrui ne réapparaît pas ; même `requestId` → une seule révision (T06). Hors ligne : réducteur local, file Dexie, rejeu dans l'ordre, brouillon si incompatible. 403 / 404 / 423 selon R13. |
| Compatibilité | Import P.118 : 220 `mur`, 84 `porte`, 126 `fenetre`, 120 `poteau`, 32 `escalier`, 6 `dalle`, 807 `solide` importés avec leurs paramètres exacts ; leurs représentations sont calculées, jamais importées ; aucune valeur n'est recalculée à l'import. IFC : un objet importé d'IFC n'a pas d'historique paramétrique inventé (R16) ; paramètres exportés en `IfcPropertySet` (DA-06-07, annexe C, lot 6). DXF : sans objet. |
| Validation | **Unité** (`packages/atelier-model/src/representations.test.ts`) : mêmes paramètres et même version du moteur, deux exécutions : même empreinte et même géométrie ; paramètre modifié : nouvelle empreinte ; version du moteur changée : « à recalculer » ; épaisseur de mur modifiée : ouvertures gardent `t`, emprise contrôlée, cotation rattachée recalculée ; champ dérivé refusé ; inverse restitue. |
| | **API** (`apps/api/src/routes/atelier-commands.test.ts`) : `mur.modifier` (épaisseur) → 200, révision +1, `effets` ; unité fausse → 400 avec `chemin` ; même `requestId` → même réponse ; `baseRevision` périmée → 409 ; rôle lecture → 403. |
| | **e2e** (`apps/web/e2e/scenarios/05-atelier.mjs`, bloc « Objets · paramétrique ») : copie de travail de P.118 : mur `EX118-mezz-W-009` : changer l'épaisseur, porte `EX118-mezz-D-001` toujours à t = 0,5 ; annuler : valeurs initiales identiques ; second navigateur à la même révision. |
| Règles métier | Aucune règle réglementaire. R3 : aucune valeur par défaut ; absente = « non évaluée ». R9 : toute modification par une commande. R12 : références incertaines « à réparer ». R15 : géométrie canonique paramétrique, représentations dérivées par un moteur identifié et versionné. |
| Extensions à spécifier | Contraintes (lot 5) ; familles et tables de familles (DA-06-03, DA-06-04 : P2) ; expressions et règles ; recalcul à la demande des objets calculés par une ancienne version du moteur (proposition) ; historique paramétrique des objets natifs (non prévu). |

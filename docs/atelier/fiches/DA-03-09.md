# DA-03-09 — Parametric modeling / Modélisation paramétrique — module M02 → module Fadi Atelier — lot 3a + 3b

**État : prototype** (à spécifier → spécifiée → prototype → vérifiée → disponible). Preuve liée : part 3a : dessins de plan dérivés des paramètres par classe (`socle/dessin.ts`, `apps/web/src/modules/atelier/objets/dessinateurs.ts`), dépendances lues dans l'inspecteur (niveau haut d'un mur, distance au centre d'une baie dérivée de `t`), types partagés avec dimensions proposées (`type.definir`, `apps/web/src/modules/atelier/objets/inspecteur.ts`), métré « à recalculer » à une nouvelle révision (`apps/web/src/modules/atelier/documents/metre.ts`) ; tests `apps/web/src/modules/atelier/objets/inspecteur.test.ts` « mur : changement de type par une liste, refus d'un type inconnu, longueur calculée en lecture seule », « types : créer un type depuis l'objet (type.definir + affectation en un lot), renommer, dimension proposée », « baie : distance au centre modifiable (ouverture.deplacer), bornée au mur », `apps/web/src/modules/atelier/documents/exports.test.ts` « chaque quantité, par type, exacte, marquée de la révision et de l'empreinte » ; PR #60, #59. Reste : -b représentation 3D et -d recalcul 3D : part 3b (L3b.1) ; plan de lecture et tableau des surfaces « à recalculer » après une modification d'épaisseur (« 05-atelier.mjs ») non repris dans `apps/web/e2e/scenarios/14-nouvel-atelier.mjs`.

Parts : lot 1 pose le contrat (paramètres canoniques, représentations dérivées, empreintes) ; lot 3a l'expose en
2D (inspecteur, plan) ; lot 3b en 3D (solides dérivés, rendu). Pas d'arbre de fonctions général (historique de
features rejouable) au lot 3 : la paramétrie est **par objet**.

Fiches liées : DA-03-10, DA-03-13, DA-07-01, DA-04-01, DA-04-07. |
| Situation utilisateur | L'architecte change l'épaisseur d'un mur, l'altitude d'un niveau ou la largeur d'une porte, et tout ce qui en dépend suit : le solide du mur, les ouvertures qu'il héberge, les murs dont la hauteur suit le niveau, les vues et quantités (marquées « à recalculer »). Résultat : un modèle cohérent sans redessiner. |
| Entrées et unités | Paramètres canoniques par classe (cahier §5.2), toujours `{ value, unit }` (m, m², °) ou coordonnées `{ x, y, frame: "local", unit: "m" }` ; références de dépendance (`niveauHaut`, `murHoteId`, `typeId`, `niveauId`). Aucun paramètre sans unité ; aucune valeur par défaut tirée de P.118 (R3). |
| Comportement | Toute modification = commande `<classe>.modifier` (annexe B : `mur.modifier`, `ouverture.modifier`, `dalle.modifier`, `solide.modifier`, `niveau.modifier`, `type.modifier`…). Le réducteur pur applique le paramètre puis calcule les **effets** : objets dépendants re-dérivés (ex. `niveau.modifier { elevation }` → murs à `niveauHaut` re-dérivés, escaliers liés signalés), contrôles de cohérence (emprise des ouvertures), documents à recalculer. Un paramètre dépendant n'est jamais écrit silencieusement sur un autre objet : soit il est **dérivé** (non stocké, recalculé), soit la commande liste l'objet affecté dans l'aperçu et l'inclut au lot. Les dérivées sont recalculées à l'identique dans le navigateur (aperçu) et sur le serveur (R9). Une incompatibilité (ouverture hors emprise, niveau haut sous le niveau bas) → refus motivé ou problème listé, jamais une correction automatique. |
| Données et dépendances | `atelier_objects.params` (canonique), `atelier_definitions` (types versionnés), `atelier_representations` (`autorite` `parametrique` pour la canonique, `derivee` pour les dérivées, `moteur: "fadi-geometry"`, `versionMoteur`, `empreinteEntrees` = empreinte des paramètres + dépendances + version du moteur), `atelier_relations` (`heberge`, `joint-a`, `delimite`, `relie`). Modules : `atelier-model` (ontologie, réducteurs, graphe de dépendances), `core-geometry` (dérivations pures), API (événement `atelier.commande.validee` → vues, quantités, bilan Harmonie périmés, T07). |
| Résultats | Paramètre modifié ; dérivées recalculées et ré-identifiées ; liste des objets affectés et des documents à recalculer dans la réponse (`effets`) et dans le panneau des modifications ; révision `n + 1`. |
| Cas limites | Paramètre d'unité incompatible → 400 (T03). Dépendance cyclique (impossible au lot 3 par construction : `niveauHaut` d'un mur vers un niveau, hôte d'une ouverture vers un mur) → refus si elle apparaît. Objet dépendant verrouillé (calque verrouillé, réservation d'autrui) → refus de tout le lot (atomique) avec la liste. Moteur de dérivation en échec sur un objet → représentation absente marquée « à vérifier », problème listé, paramètres conservés. Version du moteur changée → toutes les dérivées « à recalculer ». Conflit 409 sur un objet dépendant modifié par autrui. |
| Compatibilité | **Import P.118** : les paramètres existent dans les données (axe, épaisseur, hauteur, `t`, largeur…) et deviennent canoniques sans arrondi (`docs/atelier-drawall.md` §4.2 : « fonction de conception réelle, jamais inventée ») ; les hauteurs des murs P.118 sont des valeurs (`height`), pas des `niveauHaut` : aucune dépendance au niveau n'est inventée à l'import. **IFC 4.3** : IFC ne porte pas la paramétricité (D5) ; export = géométrie dérivée + paramètres en propriétés ; un objet importé d'IFC a `autorite: "importee"`, sans historique paramétrique inventé (R16). |
| Validation | **Unité** `packages/atelier-model/src/commandes/*.test.ts` : `mur.modifier { epaisseur }` → solide dérivé re-calculé, `empreinteEntrees` changée, ouvertures conservées ; `niveau.modifier { elevation }` sur le niveau haut → murs à `niveauHaut` plus hauts, murs à `hauteur` inchangés ; ouverture rendue hors emprise → refus listant l'ouverture ; deux dérivations aux mêmes entrées → même empreinte (reproductibilité) ; inverse → empreinte du modèle identique. `src/ontologie/*.test.ts` : aucun paramètre sans unité. **API** `apps/api/src/atelier-commands.test.ts` : réponse `effets.documents` non vide après modification (T07). **Scénario** `apps/web/e2e/scenarios/05-atelier.mjs` : épaisseur d'un mur modifiée dans l'inspecteur → plan et 3D à jour, porte conservée, plan de lecture et tableau des surfaces marqués « à recalculer ». |

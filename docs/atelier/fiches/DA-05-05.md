# DA-05-05 — Groups / Groupes — module M04 → module Fadi Atelier — lot 1 + 3a

**État : spécifiée** (à spécifier → spécifiée → prototype → vérifiée → disponible). Preuve liée : — (à lier aux lots 1 et 3a).

Portée : lot 1 pour la relation de groupe et les commandes `groupe.creer` / `groupe.dissoudre` ; lot 3a pour la
sélection et l'édition par groupe dans l'éditeur 2D. Un groupe n'est **pas** un bloc (définition réutilisable,
DA-05-06, lot 5) : il rassemble des occurrences existantes, sans définition partagée.

| Champ | Contenu |
| --- | --- |
| Identité | **DA-05-05** « Groups » (Exigences V4.1, annexe B.6, M04, P1 ; critère B.6 : « Identités, occurrences et références stables lors de la réutilisation »). Sous-exigences : **DA-05-05-a** grouper une sélection d'objets ; **-b** dissoudre un groupe (les objets restent, identités inchangées) ; **-c** sélectionner un groupe d'un clic, entrer dans le groupe pour sélectionner un membre ; **-d** transformer un groupe (déplacer, copier, tourner, miroir… — DA-02) comme un seul lot ; **-e** nommer un groupe. Tâches : L1.1, L1.2, L3a.2 (sélection). Fiches liées : DA-02-01 / 02 / 03 / 04 (transformations), DA-05-06 (blocs, lot 5), DA-05-12 (objets), DA-05-01 (calques verrouillés). |
| Situation utilisateur | L'architecte rassemble un ensemble (une table et ses chaises, un bloc sanitaire dessiné en solides) pour le déplacer ou le copier d'un geste, puis le dissout s'il veut retoucher les éléments séparément. Résultat : un groupe nommé, des transformations appliquées à tous ses membres dans une seule révision, et des objets intacts après dissolution. |
| Entrées et unités | `objetIds[]` (≥ 2 objets existants, **proposé**) ; `nom` (texte facultatif ; à défaut, « Groupe n » affiché, non stocké comme donnée inventée) ; pour la dissolution : `groupeId`. Sans unité, sans hypothèse ni source. |
| Comportement | Commandes de l'annexe B : `groupe.creer` (`cibles: objetIds`, `params: { nom? }`) → crée un groupe et pose `group_id` sur chaque membre ; inverse `groupe.dissoudre` (même identifiant de groupe conservé dans l'inverse pour que rétablir le recrée à l'identique). `groupe.dissoudre` (`cibles: [groupeId]`) → retire `group_id`, supprime le groupe ; inverse `groupe.creer` avec le même identifiant et les mêmes membres. Renommer : `groupe.modifier` (**nom proposé, à figer par L1.2** — absent de l'annexe B).<br>**Recommandation** : un objet appartient à au plus un groupe, pas de groupes imbriqués au lot 3 (simplicité, références stables) ; tous les membres sur un même niveau (**proposé, à confirmer**).<br>Sélection : clic sur un membre → sélection du groupe entier (état d'affichage, R10) ; double-clic ou `Entrée` → « entrer dans le groupe », sélection d'un membre ; `Échap` → sortir. Transformation d'un groupe = une commande `transformer.*` dont les `cibles` sont tous les membres, dans un lot atomique (UX3 : aperçu de tous les membres avant validation). Supprimer un groupe sélectionné = suppression de chaque membre par sa commande de classe, dans un lot, liste montrée avant accord. |
| Données et dépendances | `atelier_objects.group_id` (cahier §5.5) ; groupe = entité de projet (identifiant stable `${projectId}_${id}`, `nom`) ; stockage exact (ligne `atelier_objects` de classe `groupe` ou table dédiée) **à figer par L1.1 / L2.1**. Modules : `atelier-model` (réducteurs, contrôle d'appartenance unique), interface (sélection hiérarchique), transformations DA-02. Aucune vue à recalculer pour la création ou la dissolution seule (la géométrie ne change pas) ; une transformation de groupe marque les vues comme toute transformation (T07). |
| Résultats | Groupe créé / dissous / renommé ; journal, révision `n + 1` ; navigateur : groupes listés avec leurs membres ; inspecteur : nom du groupe, effectif, classes des membres. |
| Cas limites | Moins de 2 objets → 400 (**proposé**). Objet déjà membre d'un autre groupe → 400 « déjà dans le groupe <nom> » (pas de déplacement silencieux d'un groupe à l'autre). Membres sur des niveaux différents → 400 (**proposé**). Membre sur un calque verrouillé → refus « calque verrouillé : <nom> » (DA-05-01), y compris pour une transformation de groupe (tout ou rien). Objet inexistant ou supprimé entre l'aperçu et l'envoi → 409. Dissolution d'un groupe inconnu → 404 dans `details`. Suppression d'un membre → il quitte le groupe ; groupe réduit à un membre → **proposé** : conservé (pas de dissolution implicite). Ouverture hébergée (porte, fenêtre) groupée sans son mur : permise, mais une transformation qui la sortirait de son hôte suit les règles de DA-07-02 / 03 (refus si hors emprise). Lecteur → 403 ; 423 ; requête répétée → T06 ; hors ligne : exécutable localement. |

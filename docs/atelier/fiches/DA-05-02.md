# DA-05-02 — Classes / Classes d'objets — module M04 → Atelier — lot 3a

**État : prototype (lot 3a)** (à spécifier → spécifiée → prototype → vérifiée → disponible). Preuve liée : recette `apps/web/e2e/atelier-nouveau.mjs`, tests `apps/web/src/modules/atelier/nouveau/nouveau.test.ts` et `packages/atelier-model/src/commandes/commandes.test.ts` ; compte rendu `lots/lot-3a.md`.

| Champ | Contenu |
| --- | --- |
| Identité | DA-05-02 (M04, étape cible P1). Interprétation retenue : une « classe » est une classe de l'ontologie du modèle (`mur`, `porte`, `dalle`, `solide`, `esquisse.*`, `cotation`…, tableau 5.2), c'est-à-dire la nature d'un objet, fixée à sa création. Elle se distingue du calque (organisation choisie, DA-05-01) et de la classification (classe IFC et code, DA-06-08). Sous-exigences : -a navigateur de classes ; -b filtre d'affichage et de sélection par classe ; -c classes admises par commande. |
| Situation utilisateur | Se repérer dans un projet par nature d'objet : savoir ce qu'il contient, ne sélectionner ou n'afficher que des murs, des cotations ou des solides, et savoir quelles commandes s'appliquent à une sélection. |
| Entrées et unités | `classe` (identifiant du tableau 5.2) et `ontologie` (`building.architecture`, `building.structure`, `drawing`, `annotation`, `projet`) portées par chaque occurrence ; filtre = ensemble de classes. Aucune grandeur : pas d'unité. |
| Comportement | **Cycle.** Panneau Classes (ontologie → classe → nombre d'objets du projet et du niveau) → cocher des classes pour filtrer l'affichage ou la sélection (clic, lasso) → aperçu immédiat, objets masqués comptés → « Sélectionner tout » d'une classe sur le niveau visible. Pas de contrôle ni de validation : ce sont des paramètres d'affichage (R10), jamais des commandes. |
| | **Classes admises.** Chaque commande déclare ses classes admises (annexe B) ; la palette (UX2) et l'aide (UX4) les lisent dans le même registre que les réducteurs : une commande est active si au moins un objet d'une classe admise est sélectionné, et l'aide dit pourquoi elle est inactive (« Déplacer : aucune classe admise dans la sélection »). |
| | **Invariants.** La classe d'un objet ne change jamais : convertir un solide en mur crée un autre objet (aucune commande de conversion). Aucune commande ne crée, ne renomme ni ne supprime une classe : en ajouter une est un changement de contrat du modèle (version de `atelier-model`), non une donnée de projet. Visibilité effective = `visible` du calque (modèle, DA-05-01) ET filtre de classe, niveau visible et ensemble d'affichage (DA-05-03), tous locaux. |
| Données et dépendances | Lecture seule : champ `classe` de chaque occurrence, registre des classes dans `packages/atelier-model` (ni `react`, ni DOM, R6). Rien n'est écrit : pas de révision, pas de journal, aucun document « à recalculer » ; les filtres sont conservés localement par utilisateur et par projet (Dexie). |
| Résultats | Inventaire par classe (comptes, sélection) transmis aux commandes ; aucun objet, document ni sortie persisté dans le modèle. |
| Cas limites | **Affichage.** Filtre qui exclut tout : plan vide avec message, pas d'erreur ; objets masqués par un filtre toujours présents dans les quantités et les exports (masquer n'est pas supprimer) ; objet d'une classe inconnue d'un client plus ancien (contrat plus récent) : listé « classe inconnue », en lecture seule, jamais ignoré (R7). |
| | **Concurrence et réseau.** Sans objet pour les filtres : aucune requête, donc ni 409 ni requête répétée. Objet supprimé par un autre utilisateur pendant une sélection : il quitte la sélection au rafraîchissement ; une commande émise sur lui reste refusée par le serveur (409, il ne réapparaît pas). Hors ligne : filtres et comptes fonctionnent sur l'état local. |
| Compatibilité | Import P.118 : les comptes du navigateur égalent le rapport d'import (R7) : 220 `mur`, 84 `porte`, 126 `fenetre`, 120 `poteau`, 32 `escalier`, 6 `dalle`, 45 `piece`, 6 `niveau`, 64 `cotation`, 95 `texte`, 807 `solide` de rôle `solid` (autres rôles : même classe, comptés à part). |
| | IFC : la classe Fadi n'est pas la classe IFC ; la correspondance (annexe C, lot 6) ne sert qu'à l'export, est nommée au rapport d'échange et n'écrit jamais de classification (DA-06-08). DXF : sans objet. |
| Validation | **Unité** (`packages/atelier-model/src/classes.test.ts`) : le registre contient chaque classe du tableau 5.2 avec son ontologie ; toute classe admise par une commande existe au registre ; filtre par classe appliqué à l'état importé de P.118 : comptes exacts ; le filtre ne produit aucune commande ni changement de révision. |
| | **API** (`apps/api/src/routes/atelier-commands.test.ts`) : commande dont une cible est d'une classe non admise → 400 avec `chemin` de la cible et classes admises ; aucune route n'écrit un filtre ou une préférence d'affichage. |
| | **e2e** (`apps/web/e2e/scenarios/05-atelier.mjs`, bloc « Organisation · classes ») : copie de travail de P.118 : le navigateur affiche les comptes du rapport d'import ; filtre « mur » : seuls les murs se sélectionnent au lasso ; filtre retiré : tout revient ; révision identique avant et après (R10). |
| Règles métier | Aucune règle réglementaire. R3 : aucune classe, aucune ontologie ni aucune correspondance IFC n'est déduite d'un nom, d'une forme ou d'une propriété. R10 : les filtres de classe sont de l'affichage. |
| Extensions à spécifier | Classes d'organisation définies par l'utilisateur (attributs de dessin à la manière des classes de logiciels de CAO) : non spécifiées, elles exigent une nouvelle entité au tableau 5.2 (décision du chef de projet) ; conversion d'un objet vers une autre classe ; filtres enregistrés et partagés (lot 5, vues). |

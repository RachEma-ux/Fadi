# DA-02-14 — Control-point editing / Édition par points de contrôle — module M02 → module Fadi Atelier — lot 3a

| Champ | Contenu |
| --- | --- |
| Identité | **DA-02-14** « Control-point editing » (Exigences V4.1, annexe B.3, module M02, étape cible P1 ; critère de recette commun B.3). Retenue (proposition §5.1, lot 3) ; tâche **L3a.2**. Sous-exigences : **DA-02-14-a** afficher les points de contrôle de l'objet sélectionné (sommets, extrémités, milieux, centre, poignées de rayon, points de contrôle de spline) ; **-b** déplacer un point ; **-c** insérer un sommet sur un segment ; **-d** supprimer un sommet ; **-e** même geste sur les contours de `dalle` et de `solide` et sur les extrémités d'un `mur`. Fiches liées : DA-01-02 à 05 (primitives), DA-02-15 / 16 (accrochage, saisie de précision), DA-02-17 (manipulateur), DA-07-01 (murs). |
| Situation utilisateur | L'architecte ajuste une forme sans la redessiner : tire un coin de dalle, ajoute un sommet sur un contour, recentre un cercle, allonge un mur par son extrémité. Résultat : l'objet modifié en place (même identité), ses dépendances recalculées ou signalées. |
| Entrées et unités | Objet sélectionné d'une classe admise : `esquisse.ligne`, `.polyligne`, `.arc`, `.cercle`, `.rectangle`, `.polygone`, `.spline`, `.construction`, `.hachure` (contour), `solide`, `dalle`, `mur` (extrémités `a` / `b` seulement). `operations` : liste ordonnée de `{ op: "deplacer", point: <nom ou indice>, vers: { x, y, frame: "local", unit: "m" } }`, `{ op: "inserer", segment: i, en: {…} }`, `{ op: "supprimer", sommet: i }`. Points nommés par classe : ligne `debut` / `fin` / `milieu` (déplace la ligne entière) ; arc `debut` / `fin` / `milieu` (passe par trois points) ; cercle `centre` / `rayon` ; rectangle `coin[0..3]` (le coin opposé reste fixe, le rectangle reste rectangle, son angle est conservé) ; polyligne / polygone / contours `sommet[i]` ; spline `controle[i]`. Saisie : pointeur avec accrochage, ou coordonnées / déplacement relatif au clavier (DA-02-16). |
| Comportement | Cycle UX3 : sélection → poignées affichées (taille des cibles : voir DA-02-17) → glisser une poignée ou la choisir au clavier (`Tab` entre poignées, flèches = pas de grille, saisie de valeur) → **aperçu** continu (local, réducteur pur) → contrôle → validation au relâcher / `Entrée` ; `Échap` restaure. Un geste = **une** commande (pas une par mouvement de pointeur).<br>Commande émise (annexe B) : `{ type: "transformer.pointsDeControle", cibles: [id], params: { operations } }`, `label` « Modifier les points ». Pour un `mur`, l'effet et les contrôles sont ceux de `mur.modifier` (axe) : jonctions recalculées, ouvertures dont l'emprise deviendrait invalide listées et la commande refusée (règle DA-07-01) — **Recommandation** : le réducteur délègue au réducteur de `mur.modifier`. Pour les esquisses, `esquisse.modifier` (DA-01-02) et `transformer.pointsDeControle` produisent le même effet : **Recommandation** que le second se ramène au premier dans le réducteur (un seul chemin de validation). Inverse : `transformer.pointsDeControle` avec les anciennes positions / sommets. |
| Données et dépendances | Réducteur `transformer.pointsDeControle` (`packages/atelier-model`) ; géométrie pure (`core-geometry`) : aire, auto-intersection, rectangle conservé par coin opposé. Écritures `atelier_objects.params`, journal, événement → vues, quantités (aire de dalle) et bilan Harmonie « à recalculer » ; pièces proposées à nouveau si un mur bouge (DA-07-15). **Références** (cahier §5.2) : déplacer un sommet conserve les caractéristiques (`dalle:contour[i]` reste l'arête i) ; **insérer** un sommet coupe l'arête i en deux et **supprimer** un sommet fusionne deux arêtes → les références vers ces arêtes passent « à réparer » avec propositions (R12, T05), les indices des autres arêtes sont réindexés de façon déterministe (**Hypothèse**, à valider par L1.3). |
| Résultats | Objet modifié (même identifiant) ; inspecteur : longueurs, aire, nombre de sommets mis à jour ; journal ; révision `n + 1` ; références à réparer éventuelles dans le panneau des problèmes. |
| Cas limites | Point déplacé hors repère `local` ou unité ≠ `m` → 400 (R5, T03). Deux sommets consécutifs confondus (< `tolCoincidence` 1·10⁻⁶ m, proposée) → fusion proposée dans l'aperçu, refus côté serveur (le serveur ne corrige jamais). Suppression qui laisse un contour fermé à moins de 3 sommets, ou une ligne à moins de 2 → refus. Contour de `dalle` rendu auto-sécant, trou sortant du contour ou touchant le contour → refus (**Hypothèse** : une dalle exige un contour simple) ; esquisse auto-sécante → acceptée et signalée (règle DA-01-02). Aire < `aireMin` (1·10⁻⁶ m²) → refus. Sommet d'un `solide` à `vertexOffsets` : déplacer admis (la hauteur du sommet suit son indice), **insérer** refusé (hauteur du nouveau sommet inconnue, R3), supprimer admis avec la valeur supprimée listée. Rectangle : un coin tiré hors de l'orthogonalité est impossible par construction (le rectangle est recalculé) ; pour une forme libre → décomposer d'abord (DA-02-13). Extrémité de mur déplacée hors du niveau → refus. Calque verrouillé → refus. Lecteur 403 ; réservation 423 ; objet modifié par autrui 409 ; `requestId` répété → une seule modification ; hors ligne : local, rejoué. |
| Compatibilité | Aucune incidence de format propre. Import P.118 : les 967 tracés importés (contours `points`, trous `holes[].poly`) et les 220 murs sont éditables par cette commande ; les valeurs importées ne sont modifiées que par la commande validée (jamais à l'import). Prototype : poignées de déplacement d'objet et Pousser / Tirer (DA-04-07) ; pas d'édition de sommets — fonction nouvelle. |
| Validation | **Unité** (`packages/atelier-model/src/commandes/transformer.test.ts`) : dalle (0 ; 0), (10 ; 0), (10 ; 8), (0 ; 8) ; sommet 2 déplacé en (11 ; 8) → aire 84 m² ; insertion en (5 ; 0) → 5 sommets, aire inchangée 80 m², cotation sur l'arête 0 « à réparer » avec deux propositions ; suppression jusqu'à 2 sommets → refus ; dalle auto-sécante → refus ; cercle `rayon` tiré en (3 ; 0) depuis le centre (0 ; 0) → r = 3 m ; rectangle coin 2 tiré → rectangle, coin opposé inchangé ; extrémité de mur déplacée → jonctions recalculées, porte hors emprise → refus listant la porte ; inverse → empreinte identique. **API** : 400, 409, idempotence. **Scénario** `05-atelier.mjs` : sur la dalle de la mezzanine de P.118, déplacer un sommet au clavier (saisie relative 1,00 m), aire affichée modifiée, surfaces marquées « à recalculer », annuler → aire d'origine identique ; `11-accessibilite.mjs` : sélection d'une poignée et déplacement au clavier. |
| Règles métier | Aucune règle réglementaire. Modifier une dalle ou un mur ne vaut pas validation structurelle (non évaluée, R3 / R4). |
| Extensions à spécifier | Poignées de tangente des splines et de courbure des segments d'arc ; édition simultanée de sommets de plusieurs objets (sommets partagés) ; points de contrôle 3D (`vertexOffsets` en hauteur, en lien avec DA-04-07) ; points de contrôle des escaliers, pièces, zones. **Question au chef de projet (L1.2)** : confirmer que `transformer.pointsDeControle` et `esquisse.modifier` coexistent et se ramènent au même réducteur. |

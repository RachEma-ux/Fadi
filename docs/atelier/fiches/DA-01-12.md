# DA-01-12 — Hidden-line management / Gestion des lignes cachées — module M11 → Documents (vues dans l'Atelier) — lot 5

**État : prototype (lot 5)** (à spécifier → spécifiée → prototype → vérifiée → disponible). Preuve liée : tests `packages/atelier-model/src/documents/documents.test.ts` (prisme A devant prisme B : arête cachée sur [1 ; 2], visible sur [2 ; 3] ; faces coplanaires ; ouverture dans un mur ; même SVG octet pour octet) ; recette `apps/web/e2e/atelier-documents.mjs` ; compte rendu `lots/lot-5.md`. Écart : fonction de visibilité dans `packages/atelier-model/src/documents/visibilite.ts` ; calcul analytique par intervalles, donc pas de cas cyclique à signaler.

| Champ | Contenu |
| --- | --- |
| Identité | DA-01-12 (M11, étape cible P1), ciblée lot 5. Équivalent borné de DA-14-19 (Make2D) : projection 2D avec gestion de visibilité par tri des faces, **pas** un moteur de lignes cachées général (proposition §4.8, cahier §5.9). S'applique aux façades et aux coupes (éléments en arrière-plan) ; les plans par niveau : DA-14-02. |
| Situation utilisateur | Obtenir une façade ou une coupe lisible où ce qui est derrière une face n'est pas tracé comme visible, avec le choix de l'omettre ou de le montrer en pointillé, et savoir quand le résultat est ambigu. |
| Entrées et unités | Vue dérivée : plan de projection (façade : plan vertical d'orientation donnée ; coupe : plan vertical quelconque et profondeur, m), révision `n` du modèle, objets référencés (murs, ouvertures, dalles, poteaux, escaliers, solides). |
| | Paramètre de la vue `lignesCachees` parmi `omises`, `pointilles`, `toutes` : propriété de la définition de vue (`atelier_views`), pas du modèle. Unités : m dans le repère local ; tolérances de visibilité et de coplanarité déclarées par l'opération, consignées dans `decisions.md`. |
| Comportement | **Cycle.** Vue ouverte dans l'Atelier (vues techniques de travail, lot 3b) ou produite par le serveur (lot 5) → réglage « lignes cachées » dans l'inspecteur de la vue → aperçu → la vue est régénérée pour la révision courante ; révision et fraîcheur (à jour / à recalculer) restent visibles (R11, recette B.15). |
| | **Commandes.** Aucune commande du modèle : le réglage est un paramètre de la définition de la vue et ne modifie pas la révision du modèle (R10, R11). L'annexe B ne contient pas de commande `vue.*` : à ajouter au catalogue si la définition de vue est modifiable par commande (point à trancher au lot 5). |
| | **Algorithme.** Fonction pure de `core-geometry` : projection orthogonale, tri des faces par profondeur, découpe des arêtes par les faces plus proches, classement visible / caché. Faces issues du modèle paramétrique (R15) ; faces coplanaires fusionnées à tolérance déclarée. |
| | **Limite assumée.** Le tri par faces est exact quand l'ordre de profondeur est total ; faces qui se coupent ou se recouvrent cycliquement : signalées dans le rapport de la vue (liste des faces ambiguës), jamais résolues en silence ni présentées comme exactes. |
| | **Contrôles.** Vue sans objet dans le plan : message « vue vide », jamais une page blanche muette ; plan de coupe dégénéré refusé. |
| | **Palette (UX2) et aide (UX4).** « lignes cachées » ; synonymes « arêtes cachées », « visibilité », « hidden line » ; exemple court : façade nord, arêtes cachées en pointillé. |
| Données et dépendances | Document dérivé rattaché à la révision `n` avec empreinte (révision, objets référencés, paramètres de vue, version du moteur). Périmé par `atelier.commande.validee`, il reste consultable mais ne peut pas être présenté comme actuel (R11) ; un calcul tardif pour `n` livré après `n + 1` reste rattaché à `n` (essai Architecture §12). |
| | Modules : Documents (`produced_documents`, catalogue) et Atelier (vues techniques de travail du lot 3b) ; `core-geometry` pour la visibilité. |
| Résultats | Vue vectorielle (SVG) avec arêtes classées visibles / cachées et rapport de la vue (objets référencés, faces ambiguës), enregistrée au catalogue avec révision et empreinte. |
| Cas limites | **Calcul.** Face ambiguë ; modèle modifié pendant le calcul : vue rattachée à l'ancienne révision, marquée périmée ; calcul interrompu : aucun document partiel présenté comme complet ; objets référencés supprimés depuis : vue périmée, objets listés. |
| | **Concurrence.** Une production n'est pas une commande du modèle : pas de 409 ; si le modèle avance pendant le calcul, le document reste rattaché à `n` et périmé. Une production répétée (même couple révision et paramètres) renvoie le document enregistré, jamais un doublon (idempotence, T06). |
| | **Réseau et droits.** Hors ligne : vue de travail locale (lot 3b) disponible, production serveur et enregistrement au catalogue indisponibles avec le motif (périmètre local annoncé) ; `read` pour consulter, `write` pour produire ; 403 motivé, 404 sans accès, 423 pendant une réservation d'autrui (R13). |
| Compatibilité | P.118 : vues dérivées du modèle importé (murs, ouvertures, dalles, poteaux, solides) ; le prototype affichait ses faces par tri de profondeur (`drawFaces`, déjà dans `core-geometry`) : comportement de référence. |
| | Exports SVG ; DXF (arêtes cachées sur un calque dédié ou un type de trait, à fixer au lot 5) ; PDF (rendu du SVG). IFC : documents dérivés non échangés, « omis » au rapport d'échange. |
| Validation | **Unité** (`packages/core-geometry`, nouvelle fonction de visibilité) : prisme A devant prisme B → arêtes de B partiellement cachées (valeurs vérifiables à la main) ; face coplanaire ; ouverture dans un mur ; cas cyclique signalé ; même révision, même SVG octet pour octet (reproductibilité). |
| | **API** (`apps/api/src/routes/atelier-views.test.ts`, lot 5) : production d'une façade → document au catalogue avec révision et empreinte ; commande ensuite → fraîcheur « à recalculer » (T07) ; production refusée sans droit `write` (403). |
| | **e2e** (`apps/web/e2e/scenarios/07-documents.mjs`) : façade nord de P.118 générée, mode « lignes cachées » changé, révision et fraîcheur affichées ; après un mur dessiné (`05-atelier.mjs`), la façade passe « à recalculer » et ne s'affiche plus comme actuelle. |
| Règles métier | Aucune règle réglementaire ; types de trait des arêtes cachées (pointillé normalisé) : convention non introduite sans source (R3). |
| Extensions à spécifier | Lignes cachées pour corps quelconques (maillages, B-Rep, lot optionnel OCCT) ; vues isométriques ; arêtes cachées en 3D (mode filaire) ; faces ambiguës résolues par découpe exacte ; hauteur de coupe des plans (DA-14-02). |

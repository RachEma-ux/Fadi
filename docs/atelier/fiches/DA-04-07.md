# DA-04-07 — Push/Pull / Pousser / tirer — module M02 → module Fadi Atelier — lot 3b

**État : spécifiée** (à spécifier → spécifiée → prototype → vérifiée → disponible). Preuve liée : — (à lier au lot 3b).

Au lot 3, pousser / tirer agit sur les **paramètres** d'objets paramétriques (hauteur, épaisseur, longueur,
largeur, décalage de base) ; il ne déplace pas une face quelconque d'un B-Rep (lot optionnel OCCT, D-003, R15).

| Comportement | Outil « Pousser / tirer » (palette : « push/pull », « pousser », « tirer », « étirer en hauteur ») → sélection → poignées par axe (couleurs distinctes, comme le prototype : L longueur, l largeur, H hauteur ; choix d'axe explicite quand deux poignées se superposent) → glissement : **aperçu** par le réducteur pur, cote dynamique affichée, accrochage aux altitudes des niveaux et aux arêtes d'autres objets (**recommandation**) → saisie clavier possible à tout moment (champ de valeur focalisé, `Entrée` valide, `Échap` annule sans commande) → contrôle → validation. Clavier seul : sélectionner, choisir l'axe (flèches), saisir la valeur (T16).<br>Commandes émises (annexe B, aucune commande dédiée) : `mur.modifier` (`hauteur` ou `niveauHaut`, `epaisseur`, `axe`), `dalle.modifier` (`epaisseur`, `decalageBase`), `solide.modifier` (`hauteur`, `decalageBase`, `contour` pour largeur / longueur d'un contour rectangulaire), `poteau.modifier` (nom proposé dans la famille `poteau.*`, à figer par L1.2), `label` « Pousser / tirer : <paramètre> ». Inverse = même commande avec les anciennes valeurs. Pour un mur dont la hauteur est donnée par `niveauHaut`, tirer la hauteur remplace `niveauHaut` par une `hauteur` explicite, **annoncé dans l'aperçu** (« le mur ne suit plus le niveau R+1 »), jamais silencieusement. **Exigence** : le pousser / tirer n'écrit qu'un paramètre canonique ; le solide est re-dérivé (R15). |
| Données et dépendances | Paramètres canoniques du cahier §5.2 (`mur.hauteur`, `epaisseur`, `axe` ; `dalle.epaisseur`, `decalageBase` ; `solide.hauteur`, `decalageBase`, `contour` ; `poteau.largeur`, `profondeur`, `hauteur`). Modules : `atelier-model`, `core-geometry` (poignées, projection), rendu three.js (lancer de rayon, lot 3b), API. Événement → vues, quantités (longueurs, aires de murs), bilan Harmonie « à recalculer ». |
| Résultats | Paramètre modifié et persisté ; objet re-dessiné en 2D et 3D ; inspecteur à jour ; entrée de journal ; révision `n + 1` ; documents marqués. |
| Cas limites | Valeur ≤ 0 (hauteur, épaisseur, longueur < 0,01 m pour un mur — tolérance de DA-07-01 —, `longueurMin` pour un solide) → aperçu rouge, refus 400. Hauteur de mur qui rend une ouverture hors emprise → refus listant les ouvertures, ou lot complété par l'utilisateur (déplacement / suppression). Épaisseur qui fait se recouvrir deux murs joints → jonction recalculée ; jonction impossible → problème listé, pas de correction silencieuse. Contour non rectangulaire : poignées largeur / longueur absentes (DA-02-14 / DA-02-06 à la place). Objet sur calque verrouillé → refus motivé. Objet modifié par autrui pendant le geste → 409 `{ objetId, motif, etatServeur }`. Requête répétée → une seule modification (T06). Perte de contexte WebGL pendant le geste → geste abandonné sans commande. Hors ligne : exécutable localement, rejoué. |
| Compatibilité | **Import P.118** : hauteurs, épaisseurs et `baseOffset` copiés bit à bit ; un solide avec `vertexOffsets` / `topOffsets` (hauteurs par sommet) n'offre au lot 3 que la poignée « base » et « hauteur » si tous les décalages sont égaux ; sinon pousser / tirer est **désactivé avec motif** (« hauteurs par sommet : modification non prise en charge »), **recommandation**. IFC / DXF : sans objet (paramètres exportés par DA-04-01 / DA-07-01). |

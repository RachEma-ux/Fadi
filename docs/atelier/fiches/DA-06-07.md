| Identité | DA-06-07 (M05, étape cible P1). Sous-exigences : -a définir ou modifier une propriété sur un objet ; -b définir une propriété sur une définition (type, composant), héritée par ses occurrences ; -c retirer une propriété (« non évaluée »). Contrat : propriété typée `{ nom, valeur, unite, provenance, statut }` (§5.2). La classification est traitée à part (DA-06-08). |
| Situation utilisateur | Attacher à un objet ou à une définition des propriétés BIM nommées, typées, avec leur provenance et leur statut de vérification, pour les retrouver dans l'inspecteur, les quantités et l'export IFC. |
| Entrées et unités | `propriete.definir` : `cible` (`objetId`, ou identifiant de définition : `typeId`, `blocId` d'un composant), `nom`, `valeur` (nombre, texte ou booléen ; `null` = « non évaluée »), `unite` (obligatoire pour un nombre, absente sinon), `statut` (`declaree`, `verifiee`, `a-verifier`). `provenance` (`saisie`, `import`, `calcul`, `regle`) est fixée par le service de commandes d'après l'origine du lot (interface : `saisie` ; importeur : `import`), jamais librement par la requête. |
| Comportement | **Cycle.** Sélection (un ou plusieurs objets, ou une définition) → onglet Propriétés de l'inspecteur → ajouter ou modifier (nom, valeur, unité, statut) → aperçu (origine : occurrence ou définition, valeur surchargée) → contrôle → validation ; Échap annule sans commande. Sur une sélection mixte : un seul lot « Définir la propriété X sur N objets ». |
| | **Héritage.** Une propriété d'une définition s'applique à ses occurrences ; la même propriété définie sur l'occurrence la surcharge pour elle seule ; modifier la définition ne réécrit jamais une surcharge. L'inspecteur indique l'origine, la provenance et le statut de chaque valeur. |
| | **Statut et provenance (R3, R4).** Une valeur saisie est `declaree` ; `verifiee` n'est posé que par une action explicite de l'utilisateur ou par une règle tracée, jamais par un recoupement automatique ; une valeur importée de P.118 déclarée « à confirmer » est `a-verifier` (R4). `calcul` et `regle` sont réservées aux propriétés dérivées (aire calculée, résultat de règle), qui ne s'écrivent pas par `propriete.definir`. |
| | **Contrôles.** Nombre sans unité ou unité inconnue refusés (T03) ; texte ou booléen avec unité refusé ; nom vide ou en double sur la même cible refusé ; propriété dérivée : 400 ; cible d'un calque verrouillé : lot refusé en entier ; aucune conversion d'unité en silence. |
| | **Palette (UX2) et aide (UX4).** « propriété », « propriété BIM » ; synonymes « property », « pset » ; actif si au moins un objet ou une définition est sélectionné ; exemple court : définir une propriété textuelle « Remarque » sur 4 murs. |

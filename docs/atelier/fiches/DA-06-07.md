# DA-06-07 — BIM properties / Propriétés BIM — module M05 → module Fadi Atelier — lot 3a

**État : prototype** (à spécifier → spécifiée → prototype → vérifiée → disponible). Preuve liée : inspecteur : paramètres déclarés avec unité et provenance (`apps/web/src/modules/atelier/ui/inspecteur-generique.ts`), propriétés saisies définies, modifiées ou retirées par `propriete.definir`, propriétés importées (`import.*`) en lecture seule (`apps/web/src/modules/atelier/objets/inspecteur.ts`) ; tests `apps/web/src/modules/atelier/objets/inspecteur.test.ts` « propriétés BIM (propriete.definir) et classification (classification.affecter) ; préfixe d'import réservé », `apps/web/src/modules/atelier/ui/ui.test.ts` « mur : paramètres déclarés, unités, provenance, lecture seule de la géométrie », « descripteur enregistré prioritaire, sinon repli ; en-tête et propriétés en lecture » ; PR #60, #56. Reste : -e sélection multiple (l'inspecteur ne montre que le dernier objet choisi, `ui/Inspecteur.tsx`) ; -f propriétés portées par le type et héritées (types créés avec `proprietes: []`) ; -d import des champs non canoniques de P.118 hors module (lot 1), non vérifié ici ; étapes « 05-atelier.mjs » / « 11-accessibilite.mjs » du champ Validation (ancien Atelier) non reprises dans `apps/web/e2e/scenarios/14-nouvel-atelier.mjs`.

| Identité | **DA-06-07** « BIM properties » (Exigences V4, annexe B.7, module M05, étape cible P1 ; critère commun B.7 : « Recalcul reproductible ; incompatibilités de paramètres et contraintes expliquées »). Objet : la **propriété typée** du cahier §5.2 (`{ nom, valeur, unite, provenance, statut }`, table `atelier_properties`, Architecture V4 §4 « Valeur, unité, provenance et statut sont explicites »). Sous-exigences : **DA-06-07-a** lire les propriétés d'un objet dans l'inspecteur ; **-b** définir, modifier ou retirer une propriété saisie ; **-c** distinguer paramètre canonique, propriété saisie, importée, calculée et issue d'une règle ; **-d** importer sans perte les champs non canoniques de P.118 ; **-e** lire et modifier les propriétés d'une sélection multiple (valeurs communes / divergentes) ; **-f** propriétés portées par une définition (type) et héritées par les occurrences. Fiches liées : DA-06-08 (classification), DA-05-12 (objets), DA-05-14 / 15 (bibliothèques de types), DA-07-* (classes porteuses), DA-16 (tableaux, lot 5), lot 6 (jeux de propriétés IFC). |
| Situation utilisateur | L'architecte sélectionne un mur, une porte ou une pièce et veut voir et compléter ses informations non géométriques (repère, finition, résistance au feu déclarée, statut d'un choix), en sachant d'où vient chaque valeur et si elle a été vérifiée ; il veut qu'elles alimentent tableaux et échanges sans qu'une valeur importée passe pour une exigence ni pour une valeur vérifiée. |
| Entrées et unités | `objetIds` (un ou plusieurs objets existants) ; `nom` (identifiant de propriété : nom libre ou nom déclaré dans l'ontologie de la classe) ; `valeur` (nombre, texte, booléen, énumération, référence d'objet) ; `unite` **obligatoire** pour une grandeur (m, m², m³, °, kg, kN/m²… ; stockage SI, conversion d'affichage seulement, T03) et **absente** pour un texte, un booléen ou une énumération ; `provenance` ∈ {`saisie`, `import`, `calcul`, `regle`} ; `statut` ∈ {`declaree`, `verifiee`, `a-verifier`} ; `source` facultative (identifiant d'une `source` du projet, ex. `CAD-S01`). Les **paramètres canoniques** (axe, épaisseur, hauteur, largeur…) ne sont pas des propriétés : ils se modifient par la commande de leur classe (`mur.modifier`, `ouverture.modifier`…) et l'inspecteur les montre dans un bloc distinct. Les propriétés `calcul` (aire calculée, longueur) sont dérivées et non saisissables. Aucune valeur par défaut n'est proposée pour une propriété réglementaire ou structurelle (R3). |
| Comportement | Sélection → inspecteur (blocs : paramètres, propriétés, classification, relations) → saisie d'une valeur et de son unité → contrôle (dimension de l'unité compatible avec celle déclarée pour la propriété, type de valeur, énumération admise, droits `write`, objet existant, révision de départ) → aperçu (documents et tableaux qui citent la propriété marqués « à recalculer ») → validation = commande `propriete.definir` (annexe B, famille Organisation) : création ou remplacement ; le retrait explicite (valeur `null` ou commande dédiée) est figé par L1.2 dans la même famille. Sélection multiple : une seule commande atomique pour tous les objets ; valeurs divergentes affichées « valeurs multiples » sans écrasement tant que l'utilisateur ne saisit pas. Passer une propriété de `declaree` à `verifiee` est une saisie explicite (auteur et date au journal), jamais automatique. Une propriété de provenance `import` modifiée devient `saisie` ; l'ancienne valeur reste lisible au journal. Annuler / rétablir = commande inverse, nouvelle microversion. |
| Données et dépendances | `atelier_properties` (`objet`, `nom`, `valeur`, `unite`, `provenance`, `statut`, `source`) ; révision du modèle à chaque `propriete.definir` ; événement `atelier.commande.validee` → tableaux (DA-16, lot 5) et exports marqués périmés (R11). Propriétés portées par une **définition** (`atelier_definitions`) : héritées par les occurrences ; une valeur d'occurrence prime et est signalée « surchargée ». `packages/atelier-model` (ontologie, L1.1) porte le schéma des propriétés déclarées par classe (nom, dimension, énumération admise) ; une propriété non déclarée reste admise et est marquée « non déclarée dans l'ontologie » (Architecture V4 §4 : « Une propriété inconnue est signalée comme telle »). Modules : `atelier-model` (validation, réducteur), service de commandes (API), inspecteur (`apps/web/src/modules/atelier/ui/**`). |
| Résultats | Propriétés visibles et éditables dans l'inspecteur avec provenance et statut ; colonnes disponibles pour les tableaux (lot 5) ; jeux de propriétés à l'export IFC (lot 6) ; entrée du journal, révision `n + 1`. |
| Cas limites | Unité incompatible (« 3 kg » pour une longueur) → 400 `{ chemin, message }` (T03). Grandeur sans unité → refus. Texte au lieu d'un nombre → refus. Énumération hors liste → refus. Propriété `calcul` saisie à la main → refus « valeur dérivée ». Statut `verifiee` posé par un script ou l'assistant sans accord explicite → refus (T19, lot 8). Objet supprimé entre-temps → 409 `{ objetId, motif, etatServeur }`. Même propriété modifiée par deux comptes → 409 sur l'objet. Requête répétée (même `requestId`) → une seule révision (T06). Valeur texte très longue : limite **proposée** 4 000 caractères (tolérance déléguée au chef de projet, §10.2, à consigner) ; enveloppe ≤ 1 Mo (cahier §8). Hors ligne : commande en file Dexie, état `local` visible jusqu'à validation. |
| Compatibilité | **Import P.118** (cahier §6, R7) : chaque champ source qui n'est pas un paramètre canonique devient une propriété de provenance `import`, statut `declaree`, valeur copiée telle quelle. Murs : `lineRef` (196, valeur `axe`), `color` (220), `designRevision` (105). Portes : `mark` (52, → paramètre `repere`), `name` (45), `openingType` (`sliding` 38, `sectional` 1, `hinged` 1 ; absent sur 44 → aucune propriété créée, jamais devinée), `clearWidthVerified` (32, toutes `false`), `nominalWidth` (26), `designRevision` (38), `siteAccess` (1), `sourceMarker` (1). Poteaux : `designStatus` (120 : « Implantation proposée contre façade ; section non dimensionnée »). Solides (`paths` à rôle `solid`, `clearance`, `ramp-*`) : `fixtureType` (51 : `basin` 30, `wc` 16, `urinal` 5), `adapted` (51), `accessory` (30), `stairAccessory` (186), `stairLanding` (13), `serviceShaft` (10), `siteAccess` (28), `planOnly` (1), `stairGroup` (60), `incomingDisplay` (1), `designRevision` (488), `color`. Tracés de pièces (`paths` rôle `room`) : `sanitaryBlock`, `designRevision`. Escaliers : `designRevision` (24), `stairGroup` (24), `incomingDisplay` (6). Le champ `structural` des dalles (système, portée 20 m, charge 500 kg/m², « Charge d'exploitation supposée, à confirmer ») est importé en **hypothèse** et structure déclarée « à confirmer » (R4), jamais en propriété vérifiée. Les champs géométriques `vertexOffsets` (104) et `topOffsets` (19) des solides ne sont **pas** des propriétés : ils relèvent de la géométrie du `solide` (voir Extensions). **IFC 4.3** (lot 6) : propriétés en `IfcPropertySet` ; correspondance avec les jeux standard (`Pset_WallCommon`, `Pset_DoorCommon`…) **non évaluée** à ce stade — seuls `Pset_StairCommon` (escaliers) et `Qto_SpaceBaseQuantities` (aires) sont fixés par l'annexe C ; hypothèses et sources dans `Fadi_Hypotheses` / `Fadi_Sources`. |
| Validation | **Unité `packages/atelier-model`** : `propriete.definir` crée / remplace / retire avec inverse exact (état et empreinte du modèle identiques après annuler) ; refus d'unité incompatible, de grandeur sans unité, de saisie d'une propriété `calcul` ; héritage type → occurrence et surcharge signalée ; propriété non déclarée marquée ; import P.118 : nombre de propriétés `import` par famille égal au nombre de champs non canoniques présents dans la source (effectifs ci-dessus, aucun champ perdu, R7), aucune propriété `openingType` créée sur les 44 portes qui n'en ont pas, `clearWidthVerified` reste `false` statut `declaree`. **API** (`apps/api`, base `fadi_test`) : 400 détaillé sur unité incompatible (T03) ; 403 pour le rôle `read` ; même enveloppe deux fois → une révision (T06). **Scénario `apps/web/e2e/scenarios/05-atelier.mjs`** : sélectionner la porte `P05` (sous-sol) de P.118, lire `openingType = sliding` (provenance import), saisir une propriété texte, annuler, rétablir, relire au second navigateur à la même révision. **`11-accessibilite.mjs`** : modifier une propriété au clavier seul (tâche définie, §5.8). |
| Règles métier | Aucune valeur réglementaire n'est créée par défaut ; une propriété du type « résistance au feu » ou « largeur de passage » n'est **jamais** marquée conforme ni vérifiée sans saisie explicite d'un utilisateur. Exigence, hypothèse et recommandation restent des objets distincts de `packages/domain-model` (R4) : une propriété n'en est pas un substitut. Repère : une propriété qui porte une coordonnée la porte taguée (`local`, `cadastral` ou `geographic`, R5) ; aucune conversion implicite. |

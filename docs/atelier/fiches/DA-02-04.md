| Champ | Contenu |

| Identité | **DA-02-04** « Mirror » (Exigences V4.1, annexe B.3, M02, P1). Critère commun B.3. Tâche **L3a.2**. Sous-exigences : **DA-02-04-a** symétrie d'une sélection par rapport à un axe du plan du niveau, en place ; **-b** symétrie avec copie (cas usuel : logement symétrique) ; **-c** traitement des objets orientés (murs, ouvertures, poteaux, escaliers, textes). Règles communes : fiche **DA-02-01**. Fiches liées : DA-07-01 (alignement des murs), DA-07-02 / 03 (portes, fenêtres), DA-07-10 (escaliers). |
| Situation utilisateur | L'architecte dessine une moitié de plan (deux logements dos à dos, un sanitaire) et obtient l'autre moitié par symétrie autour d'un axe accroché, sans que les murs changent de face ni que les portes perdent leur hôte. |
| Entrées et unités | `cibles` ; `axe` = deux points distincts `p1`, `p2` `{ x, y, frame: "local", unit: "m" }` ; `copier` (booléen ; par défaut **vrai** dans l'outil, parce que c'est l'usage d'un miroir — **Recommandation** ; la valeur est visible et modifiable avant validation). |
| Comportement | Cycle UX3 : sélection → « Miroir » (synonymes « mirror », « symétrie ») → deux points de l'axe → **aperçu** → validation.<br>Commande (annexe B) : `{ type: "transformer.miroir", cibles, params: { axe: { p1, p2 }, copier } }`. Inverse : même commande sans copie (involution) ou suppression des copies.<br>Effets par classe (**Exigence** B.3 « dépendances conservées » ; règles de cette fiche = **Recommandation** à figer par L1.2) : **mur** : les extrémités sont réfléchies (`a' = M(a)`, `b' = M(b)`) ; le sens de l'axe s'inverse donc par rapport à l'environnement, et `alignement` `gauche` ↔ `droite` est **permuté** pour que la matière reste du même côté physique de la ligne réfléchie ; `axe` inchangé. **Ouvertures hébergées** : `t` conservé (relatif à a→b réfléchi, donc position réfléchie correcte), largeur / hauteur / allège inchangées. **Sens d'ouverture des portes** : le modèle du cahier §5.2 et les données P.118 ne portent **pas** de sens (main) ni de côté d'ouverture (`openingType` : `sliding` 38, `hinged` 1, `sectional` 1, absent 44) ; la symétrie ne peut donc rien inverser : le symbole de plan dérivé est réfléchi, et dès qu'un paramètre `sens` existera (DA-07-02), le miroir le **permutera** (gauche ↔ droite) — à reporter dans DA-07-02. **Poteau** : `point` réfléchi, `angle' = 2θ − angle` (θ = angle de l'axe). **Escalier** : axe réfléchi, sens de montée conservé (départ / arrivée réfléchis) ; un escalier non symétrique (paliers, accessoires) reste cohérent car seules ses données géométriques sont réfléchies. **Texte** : position réfléchie, texte **jamais** écrit en miroir (lisibilité). **Contours** (dalle, solide, pièce, esquisse) : réfléchis puis **réorientés** (ordre des sommets inversé) pour conserver le sens de parcours canonique ; les caractéristiques indexées `dalle:contour[i]` sont renumérotées → références « à réparer » avec propositions (R12). Calque verrouillé : tout ou rien. |
| Données et dépendances | Comme DA-02-01 ; plus `alignement` (mur), `angle` (poteau), ordre des sommets. `core-geometry` : réflexion 2D pure, orientation de polygone. Événement → vues, quantités, bilan Harmonie à recalculer. |
| Résultats | Objets réfléchis ou copies réfléchies ; références renumérotées listées « à réparer » ; journal « Miroir de n objets ». |
| Cas limites | `p1` et `p2` confondus (< `tolCoincidence` = 1·10⁻⁶ m, **proposée**) → refus. Axe en repère non `local` → 400 (R5). Miroir en place d'un objet symétrique par rapport à l'axe → résultat identique, commande acceptée et journalisée (pas d'optimisation silencieuse). Copie superposée à l'original (objet coupé par l'axe) → avertissement « objets superposés ». Ouverture seule → refus (règle commune 2). Code de pièce dupliqué par la copie → problème listé (cf. DA-02-02). 403 / 409 / 423 ; idempotence ; hors ligne rejoué. |
| Compatibilité | IFC (lot 6) : l'objet réfléchi est exporté avec un placement direct (jamais une matrice de symétrie négative, mal lue par certains visualiseurs — **Recommandation** à vérifier sur le corpus du lot 6). Prototype : outil « Miroir » — fonction conservée. |
| Validation | **Unité** `transformer.test.ts` : mur (0 ; 0)→(4 ; 0) `alignement: gauche`, porte `t = 0,25`, miroir autour de l'axe x = 5 avec copie → copie (10 ; 0)→(6 ; 0), `alignement: droite`, porte `t = 0,25` dont le centre est en (9 ; 0) ; faces matières de l'original et de la copie symétriques (contrôle sur le polygone `wallPolygon`) ; deux miroirs successifs sans copie → état initial à `tolCoincidence` ; dalle avec cotation sur `dalle:contour[1]` → référence « à réparer » avec proposition ; texte non retourné. **API** : idempotence, 400 axe dégénéré. **Scénario** `05-atelier.mjs` : sur P.118 importé, miroir avec copie d'une cloison portant une porte ; nombre de portes + 1, chaque porte hébergée ; annuler. |
| Règles métier | Aucune règle réglementaire. La symétrie d'un sanitaire adapté (`adapted` dans P.118) n'est pas présentée comme conforme à une règle d'accessibilité : non évaluée (R3). |

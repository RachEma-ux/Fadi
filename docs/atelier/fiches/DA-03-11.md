Preuve prévue : —

| Champ | Contenu |
| --- | --- |
| Identité | DA-03-11 (M02, P2). L'édition directe d'une surface libre (déplacement de sommets) et la conversion explicite d'un objet paramétrique en surface libre (`surfaceLibre.depuisObjet`) couvrent la modélisation synchrone retenue ; les objets paramétriques gardent leurs paramètres (pas d'édition directe de leurs faces). |
| Situation utilisateur | Passer d'un objet paramétrique à une forme éditable directement, en le disant. |
| Entrées et unités | `surfaceLibre.depuisObjet { sourceId, niveaux?, nom?, id? }` ; outil Surface libre avec un objet sélectionné. |
| Comportement | Le maillage de l'objet source (dédoublonné) devient maillage de contrôle ; l'objet source reste (suppression explicite si voulue) ; origine conservée. Cycle UX : sélection → paramètres → aperçu → contrôle → validation (UX1–UX4) ; l'outil vit dans l'inspecteur, sans ruban ni écran distinct (T01). |
| Données et dépendances | Classe `surface-libre` (`ParamsSurfaceLibre` : sommets 3D relatifs au niveau, faces à 3 ou 4 indices, `niveaux` 0–4, `origine`, `ferme`) ; `geometrie-3d.ts` (`triangulerFaces`, `subdiviserLoop`, `proprietesMasse`) ; `batiment-p2.ts` (`maillageSurfaceLibre`, `controleDepuisMaillage`) ; réducteurs `surfaceLibre.creer / modifier / supprimer / depuisObjet / deplacerSommet / subdiviser`. Commandes du contrat `atelier-commands/3` ; journal, idempotence, inverse exact (R9). |
| Résultats | Surface libre nommée « <source> (surface libre) », origine { classe, id }. |
| Cas limites | Source sans maillage : refus ; maillage > 50 000 sommets : refus nommé. `baseRevision` périmée : 409 avec objets en conflit ; même `requestId` : une seule révision (T06) ; objet verrouillé : 423 ; hors ligne : réducteur local puis file Dexie ; unité absente ou incompatible, dimension requise absente : 400 (T03, R3). |
| Compatibilité | IFC : `Fadi_SurfaceLibre.Origine`. |
| Validation | Tests : solide → 8 sommets, 12 faces ; recette : coque → surface libre. |
| Règles métier | Pas de conversion implicite (R15). Une grandeur absente est « non évaluée » (R3) ; géométrie seulement, aucune vérification réglementaire. |
| Extensions à spécifier | Édition directe des faces d'un solide exact (push / pull), reconnaissance de features. |

Preuve prévue : —

| Champ | Contenu |
| --- | --- |
| Identité | DA-19-03 (M15, P2). Graphe de génération (`GrapheGeneration`, `automatisation/graphes.ts`) : nœuds **paramètre** (typé, défaut, bornes), **calcul** (expression arithmétique sûre), **série** (boucle bornée) et **niveaux**, **règle** (comparaison qui refuse nommément), **commande** (gabarit du contrat, dont les commandes de génération des ontologies `trame.generer`, `ossature.generer`, `reseau.router`) ; **liens** = qui lit quoi (câblage visuel : un nœud n'emploie qu'une variable fournie par un ancêtre). Équivalent fonctionnel de Dynamo ; l'import de graphes `.dyn` n'est pas garanti (déclaré, source DA-19-03). |
| Situation utilisateur | Décrire une génération paramétrée par un dessin de nœuds reliés plutôt que par un script, la proposer, l'inspecter, l'accepter. |
| Entrées et unités | Graphe intégré (`GRAPHES_INTEGRES` : « Trame de poteaux contrôlée », « Ossature bois d'un mur ») ou du projet (`graphe.definir { id, nom, description, noeuds, liens }` → définition `graphe` versionnée avec le modèle) ; valeurs des paramètres typées avec unités (`longueur` en m) ; `POST /atelier/graphes/:id/proposer { parametres, niveauId? }`. |
| Comportement | Validation (`validerGraphe`) : identifiants uniques, liens valides, **aucun cycle**, chaque variable lue reliée à son fournisseur, 3 séries au plus, au moins une commande, commandes `interne.*` refusées. Compilation (`compilerGraphe`) en `ScriptAtelier` (calculs inlinés, séries et commandes en ordre topologique) → `developperScript` → **même boucle contrôlée** que l'assistant (`boucleControlee` : essai à blanc, journal des hypothèses — valeurs par défaut et calculs —, aperçu) → accord explicite par `POST /assistant/propositions/:id/accepter`. Un refus du modèle est nommé, jamais contourné (pas de correction automatique pour un graphe). Cycle UX : sélection du graphe → paramètres → aperçu → contrôle → validation (UX1–UX4) ; tout vit dans le panneau d'automatisation (T01). |
| Données et dépendances | `automatisation/graphes.ts`, `commandes/graphes.ts` (réducteurs `graphe.definir` / `graphe.supprimer`, `graphesDuProjet`, `grapheDe`), `automatisation/scripts.ts` (lot 8), `automatisation/assistant.ts` (boucle), table `atelier_propositions` ; `panneaux/Graphes.tsx` (`VueGraphe` SVG, `EditeurGraphe`). Commandes du contrat `atelier-commands/3` ; journal, idempotence, inverse exact (R9). |
| Résultats | Une proposition (`generateur: graphes-fadi/1`, `regle: graphe:<id>`) : séquence de commandes ordinaires, hypothèses, essais, effets ; après accord, une révision étiquetée « Assistant : Graphe « nom » vN ». |
| Cas limites | Variable non reliée : refus nommé « variable « x » (nœud y) non reliée au nœud z » ; cycle : refus ; paramètre requis absent : refus nommé ; règle non tenue : proposition **échouée** sans commande ; ontologie de la commande inactive : refus du modèle nommé à l'essai ; 500 commandes au plus par développement ; `baseRevision` périmée à l'accord : 409 ; lecteur : 403 ; hors ligne : le graphe du projet se dépose par le réducteur local puis la file Dexie, la proposition attend le serveur. |
| Compatibilité | Définitions `graphe` dans l'archive du modèle (vérifiées par `verifierModele`) ; absentes de l'IFC (ce sont des recettes de génération, pas des objets de l'ouvrage). |
| Validation | Tests : validation / câblage / cycle, compilation (calculs inlinés), proposition et refus nommés, graphe intégré 3 × 2 poteaux, ossature créée puis générée, graphes du projet (définir, redéfinir, supprimer, archive) ; API : liste, échec nommé, proposition puis accord, graphe du projet, droits ; recette : graphe dessiné (17 nœuds, 22 liens), échec nommé, proposition → accord → 4 poteaux, graphe composé dans l'éditeur et déposé, proposé. |
| Règles métier | Aucune valeur normative : les règles d'un graphe intégré sont géométriques (section < pas, 400 poteaux au plus) ; toute règle métier vient du projet avec sa source (R3) ; T19. |
| Extensions à spécifier | Import / export `.dyn`, nœuds de lecture du modèle (sélections, mesures), nœuds de documents (vues, feuilles), sous-graphes, exécution partielle par nœud. |

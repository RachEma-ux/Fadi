| Champ | Contenu |
| --- | --- |
| Identité | DA-21-05 (M16, étape cible P1). Le modèle typé de l'Atelier, les données de projet (site, hypothèses, sources, structure déclarée), les liaisons avec les autres modules (Programmation, Harmonie, Documents) et les documents dérivés sont gérés ensemble : une source unique, des liaisons explicites, des dérivés marqués périmés. Sous-exigences : -a instantané complet (`GET /model`) ; -b source unique, écriture par commandes seulement (R9) ; -c événements et péremption des dérivés (R11, T07) ; -d liste unique des problèmes (`GET /problemes`). Référence de comportement : aucune (nouveau comportement Fadi). |
| Situation utilisateur | Retrouver au même endroit le modèle, ses données de projet et l'état de tout ce qui en dérive, savoir ce qui est à jour, périmé ou à réparer, et ne jamais avoir deux sources pour la même donnée. |
| Entrées et unités | `GET /model?revision=n`, `GET /model/niveaux/:niveauId` (chargement par niveau), `GET /problemes` ; événements `atelier.commande.validee { projectId, revision, objetIds, types, auteur }` ; propriétés typées `{ nom, valeur, unite, provenance, statut }` (provenance : saisie, import, calcul, regle ; statut : declaree, verifiee, a-verifier). Toute grandeur est `{ value, unit }`, toute coordonnée est taguée (R5). |
| Comportement | **Instantané.** `GET /model` renvoie, à une révision donnée, niveaux, objets, relations, définitions, calques, site, hypothèses et sources ; une valeur absente est « non évaluée » (R3) ; hypothèses, sources et structure déclarée gardent leur statut explicite (R4), jamais promues en exigences. |
| | **Source unique.** Aucune écriture directe en base hors du service de commandes (R9) ; la copie locale Dexie est un cache de lecture et une file d'envoi, jamais une source ; les liaisons avec Programmation (`programme`), Harmonie et Documents sont des références explicites vers des `objetId`, jamais des copies de valeurs. |
| | **Dérivés.** À chaque lot validé, l'événement `atelier.commande.validee` (boîte de sortie, traité dans le processus de l'API, idempotent par identifiant) marque périmés vues, documents et quantités, périme le bilan Harmonie, invalide l'aperçu conceptuel et notifie ; un dérivé périmé reste consultable mais n'est pas présenté comme actuel (R11) ; il porte la révision et l'empreinte dont il est issu. |
| | **Problèmes.** `GET /problemes` réunit références à réparer (R12), conflits en attente, documents périmés et réserves Harmonie ; chaque entrée nomme l'objet, le motif, la révision et, s'il y a lieu, la proposition de réparation. |
| Données et dépendances | Classes de la section 5.2 (aucune nouvelle classe) ; `projects.model_revision` ; journal et boîte de sortie ; documents dérivés (révision, empreinte) ; liaison `programme` ; bilan Harmonie ; identifiants stables `${projectId}_${id}` (règle existante). |
| Résultats | Instantané typé complet ; liste des problèmes ; dérivés marqués à jour ou périmés avec leur révision ; aucun doublon de donnée entre modules. |
| Cas limites | **Cohérence.** Événement traité deux fois : un seul effet (idempotent par identifiant) ; traitement d'événement en échec : relancé, la validation du lot n'est pas annulée, le dérivé reste « à recalculer » ; objet référencé par un autre module supprimé : référence « à réparer » listée, jamais supprimée en silence ; niveau non chargé référencé par un objet chargé : chargé à la demande, jamais présumé absent. |
| | **Concurrence, réseau, droits.** `baseRevision` périmée → 409 détaillé ; même `requestId` → réponse enregistrée (T06) ; hors ligne : instantané Dexie lisible, écritures en file, rejeu dans l'ordre, brouillon si incompatible ; 403 motivé, 404 sans accès, 423 pendant une réservation d'autrui (R13). |
| Compatibilité | Contrat `atelier-commands/1` ; instantané et journal en JSON typé ; import P.118 (section 6) : rapport nominatif de chaque famille (220 murs, 84 portes, 126 fenêtres, 32 escaliers, 45 pièces, 6 niveaux, calques, hypothèses, sources, structure), `ui` hors modèle (R10). |

| Champ | Contenu |
| --- | --- |
| Identité | DA-01-09 (M01, étape cible P1). Interprétation de l'inventaire : « éditeur d'esquisses paramétriques ; équivalent fonctionnel, pas atelier CATIA intégré » = le **mode esquisse de l'éditeur de plan** (mêmes objets, mêmes commandes, même éditeur ; aucun atelier séparé). Au lot 3a le mode est sans contraintes ; panneau de contraintes et diagnostic au lot 5 (DA-01-07 / 08). |
| Situation utilisateur | Passer en mode esquisse pour construire un contour ou un profil sans risquer de modifier le bâtiment, puis en sortir avec des objets d'esquisse prêts à être extrudés ou hachurés. |
| Entrées et unités | Niveau actif (plan d'esquisse = plan horizontal du niveau, repère `local`, m) ; calque actif ; outils d'esquisse (DA-01-02 à 06, 10, 11) et transformations (DA-02). Entrer et sortir du mode = réglage d'affichage (R10) : aucune commande, aucune révision. |
| Comportement | **Cycle.** Entrer (bouton « Esquisse », palette « esquisser ») → barre d'outils d'esquisse, grille et accrochages (DA-02-15) actifs → chaque geste suit sélection → paramètres → aperçu → contrôle → validation → sortir (« Terminer l'esquisse » ou Échap hors geste). **Aucun brouillon d'esquisse** : chaque objet validé existe aussitôt dans le modèle, journalisé et annulable (R9) ; sortir du mode ne valide ni n'annule rien. |
| | **Niveaux d'affichage (UX1).** Essentiel : les outils du prototype (ligne, polygone, rectangle, cercle) ; Contextuel et Complet : arc, spline, main levée, axe, hachure et transformations selon la sélection ; outils épinglables, accès permanent à la palette complète ; ces réglages ne changent ni le sens des commandes ni le modèle. |
| | **Filtre d'affichage.** En mode esquisse, les classes d'architecture (murs, dalles, escaliers, poteaux, pièces) sont atténuées et non sélectionnables par défaut (filtre de sélection, R10) ; les objets d'autres niveaux affichés en fond restent en lecture seule ; un clic sur un objet d'architecture propose de quitter le mode. |
| | **Profils.** Un profil exploitable est une esquisse fermée simple : `esquisse.rectangle`, `esquisse.cercle` ou `esquisse.polygone` ; il est proposé à `solide.extruder` (DA-04-01, lot 3b) et à `esquisse.hachure` (DA-01-11). Les chaînes de lignes et d'arcs jointifs ne sont pas des profils au lot 3a. |
| | **Conversion explicite.** Une esquisse n'est jamais interprétée comme un mur ou une dalle (Concept §3) : la conversion est une commande (`solide.extruder`, `mur.tracer`), jamais implicite. |
| | **Clavier et toucher (T16).** Entrée par la palette (Ctrl / ⌘ K), tracé par saisie de précision (DA-02-16), sortie par Échap : tâche réalisable au clavier seul. Au toucher, la puce d'outil actif (conservée) nomme l'outil d'esquisse courant ; mode immersif des étapes 10 / 11 conservé. |
| | **Palette (UX2) et aide (UX4).** « esquisse » ; synonymes « croquis », « sketch », « esquisser » ; actif si un niveau modifiable est choisi ; exemple court : entrer en mode esquisse, tracer un rectangle et un cercle, terminer. |
| Données et dépendances | Aucune donnée propre : le mode n'écrit rien. Objets `esquisse.*` du niveau et du calque actifs ; état du mode, filtre de sélection et calque actif conservés par utilisateur dans le navigateur (préférence d'affichage), jamais dans le modèle. |
| | Références : aucune caractéristique nommée d'esquisse avant le lot 5 ; au lot 5 le mode affiche marqueurs de contraintes, degrés de liberté et références « à réparer » (DA-01-07, R12). |
| Résultats | Objets d'esquisse prêts à servir de profils ; aucune quantité n'est produite à partir d'une esquisse seule. |
| Cas limites | **Interface.** Changement de niveau pendant un geste : geste annulé sans commande ; calque actif verrouillé ou masqué : outils désactivés avec le motif affiché ; rôle lecture : mode consultable, outils inactifs (403 motivé si une commande est forcée) ; 423 pendant une réservation d'autrui : outils inactifs avec le motif. |
| | **Concurrence et réseau.** Chaque geste suit les cas limites de son outil (409 détaillé, `requestId` unique par lot) ; hors ligne : mode complet (réducteur local, file Dexie rejouée dans l'ordre) ; aucune requête n'est émise par le mode lui-même. |
| Compatibilité | P.118 : sans objet (aucun `esquisse.*` importé ; les tracés sont des `solide`, non éditables comme esquisses). DXF, IFC : voir les fiches des objets d'esquisse. |
| Validation | **Unité** : pas de réducteur propre (mode d'interface) ; la logique de profil fermé est couverte par `packages/atelier-model/src/commandes/esquisse.test.ts` (rectangle, cercle, polygone simple admis ; polygone auto-sécant refusé). |
| | **API** (`apps/api/src/routes/atelier-commands.test.ts`) : aucune route propre ; entrer et sortir du mode n'émettent aucun `POST /commands` (`model_revision` inchangée, `GET /journal?apres=n` vide). |
| | **e2e** (`apps/web/e2e/scenarios/05-atelier.mjs`, bloc « 2D · mode esquisse ») : entrer, tracer un rectangle et un cercle (révision +1 chacun), sortir ; entrer et sortir seuls n'avancent pas la révision (R10) ; murs atténués et non sélectionnés ; clavier seul (palette, saisie, sortie) ; axe-core sans violation critique ni sérieuse à 1536 px et 390 px. |
| Règles métier | Aucune règle réglementaire. |
| Extensions à spécifier | Plans d'esquisse verticaux ou posés sur une face (3D) ; chaînes jointives comme profils (détection proposée, jamais imposée) ; esquisses nommées et groupes (DA-05-05) ; contraintes et diagnostic (lot 5). |

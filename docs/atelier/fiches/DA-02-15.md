# DA-02-15 — Snapping / Accrochage — module M01 → module Fadi Atelier — lot 3a

**État : prototype** (à spécifier → spécifiée → prototype → vérifiée → disponible). Preuve liée : accrochages extrémité, milieu, perpendiculaire, intersection, orthogonal (Maj), grille 0,50 m, objet, points caractéristiques (centre, quadrants) (`apps/web/src/modules/atelier/plan2d/accrochage.ts`, `plan2d/dessinateurs.ts`), bascule globale et par mode, étiquette et annonce `aria-live` (`plan2d/ZonePlan.tsx`) ; tests `apps/web/src/modules/atelier/plan2d/fondations.test.ts` « milieu exact de (0;0)–(4;0) », « extrémité, intersection, perpendiculaire, sur l'objet », « grille 0,50 : (1,26 ; 0,74) → (1,5 ; 0,5) ; priorité : extrémité à 5 px et grille plus proche → extrémité », « orthogonal avec Maj : coordonnée exacte de la référence, l'autre sur la grille », « désactivé → point brut ; rien dans le rayon → brut ; déterminisme ; point d'un autre repère ignoré », `apps/web/src/modules/atelier/plan2d/controleur.test.ts` « accrochage visible : extrémité marquée et libellée près du curseur, tolérance 8 px convertie en mètres », « ligne au pointeur : les deux points posés sur la grille 0,50 m, y vers le haut » ; PR #57. Sous-exigences : **DA-02-15-a** modes d'accrochage exigés par le cahier §5.8 : extrémité, milieu, perpendiculaire, intersection, orthogonal, grille 0,50 m ; **-b** mode centre (arcs, cercles) et « sur l'objet » (point le plus proche) — **Recommandation** ; **-c** activation globale et par mode, indicateur visible et annoncé ; **-d** accrochage disponible dans tous les gestes qui saisissent un point (tracés, transformations, points de contrôle, cotations). Fiches liées : DA-02-16 (saisie de précision), DA-01-01 (dessin de précision), DA-02-14, DA-02-17, DA-07-01. |
| Situation utilisateur | Pendant un tracé ou une transformation, l'architecte veut atteindre exactement l'extrémité d'un mur, le milieu d'une cloison, l'intersection de deux axes ou un point de grille, sans saisir de coordonnées. Résultat : le point retenu est la valeur **géométriquement exacte** du point accroché, et l'utilisateur voit quel accrochage a joué. |
| Entrées et unités | Position du pointeur (écran) convertie en point `{ x, y, frame: "local", unit: "m" }` du niveau actif ; objets candidats : objets visibles du niveau actif (calques masqués exclus) ; réglages : accrochage actif (booléen), modes actifs, pas de grille `{ value, unit: "m" }` (**Exigence** cahier §5.8 : grille 0,50 m conservée du prototype ; pas modifiable comme dans le prototype), rayon de capture en pixels CSS (8 px souris, 16 px toucher — **proposés, à confirmer**). Ces réglages sont des **préférences d'interface** de l'utilisateur, pas des données de projet : ni commande, ni révision (R10). Repère de la grille : origine et axes du repère `local` du projet (**Hypothèse** ; grille orientée : extension). |
| Comportement | L'accrochage **n'est pas une commande** : c'est une aide à la saisie. À chaque mouvement du pointeur, la fonction pure `accrocher(point, candidats, reglages) → { point, type, source? }` propose le meilleur candidat dans le rayon de capture, selon une priorité déclarée (**Recommandation** : extrémité > intersection > milieu > centre > perpendiculaire > sur l'objet > orthogonal > grille) ; l'indicateur affiche le type (icône **et** libellé texte, annoncé par une région `aria-live` polie) ; le point accroché alimente l'aperçu du geste en cours ; à la validation, ses coordonnées exactes deviennent les paramètres de la commande du geste (`esquisse.*`, `mur.tracer`, `transformer.*`…). Orthogonal : contraint la direction depuis le point précédent aux axes locaux (0°, 90°, 180°, 270°) ; combinable avec la saisie de longueur (DA-02-16). Désactivation temporaire par une touche maintenue (raccourci à fixer par la maquette L0.3) ; bascule globale dans la barre d'outils comme dans le prototype (`atelier-snap`). L'accrochage ne crée **aucune** référence persistante au lot 3a (la source n'est pas stockée dans le modèle) ; les cotations rattachées (lot 5) utiliseront la source de l'accrochage pour proposer une référence (DA-15). |
| Données et dépendances | Calcul pur dans `packages/core-geometry` (`accrochage.ts` : extrémités, milieux, intersections segment / segment, segment / arc, pied de perpendiculaire, centre, projection sur l'objet, arrondi au pas de grille) ; index spatial des candidats du niveau (P.118 : jusqu'à 237 tracés, 220 murs au total) pour tenir le budget de trame ; interface dans `apps/web/src/modules/atelier/plan2d/**`. Lecture seule du modèle ; aucune écriture, aucun événement. Préférences : stockage local de l'utilisateur (Paramètres), avec repli par défaut si le stockage est indisponible. |
| Résultats | Point saisi exact (intersection calculée en double précision, jamais arrondie, R7) ; indicateur visuel et annonce accessible ; aucune révision. |
| Cas limites | Aucun candidat dans le rayon → point brut (ou point de grille si la grille est active). Plusieurs candidats à égale distance → priorité, puis le plus proche, puis ordre stable (identifiant) — résultat déterministe. Intersection de segments parallèles → pas de candidat. Intersection hors des segments (prolongement) → non proposée au lot 3a (**Recommandation** ; « intersection apparente » : extension). Objet d'un calque verrouillé : accrochable (le verrou interdit la modification, pas la lecture). Objet d'un autre niveau → non accrochable au lot 3a. Pas de grille ≤ 0 ou non numérique dans les préférences → refus de la saisie, valeur précédente conservée. Zoom extrême : rayon en pixels constant, donc tolérance en mètres variable — la valeur retenue reste exacte. Pas de dépendance réseau : fonctionne hors ligne. |
| Compatibilité | Aucun format. Prototype : grille 0,50 m, bascule d'accrochage et choix du pas (`S.snap`, `gridSize`, `atelier-snap-step`) — fonction et valeur de grille **conservées** (cahier §5.8) ; les modes objet sont nouveaux. Import P.118 : rien à importer (préférences d'affichage, pas de modèle ; `ui.*` reste un état local, cahier §6). |
| Validation | **Unité** (`packages/core-geometry/src/accrochage.test.ts`) : milieu de (0 ; 0)–(4 ; 0) → (2 ; 0) exact ; intersection de (0 ; 0)–(4 ; 4) et (0 ; 4)–(4 ; 0) → (2 ; 2) ; pied de perpendiculaire de (1 ; 3) sur l'axe x → (1 ; 0) ; grille 0,50 : (1,26 ; 0,74) → (1,5 ; 0,5) ; priorité : extrémité à 5 px et grille à 2 px → extrémité ; accrochage désactivé → point brut ; parallèles → aucun candidat ; déterminisme (même entrée, même sortie). Tolérance `tolCoincidence` 1·10⁻⁶ m. **Scénario** `05-atelier.mjs` : sur P.118 importé (mezzanine), tracer une ligne depuis le milieu d'un mur importé : `params.a` de la commande envoyée = milieu de l'axe du mur à 1·10⁻⁶ m près ; indicateur « Milieu » visible ; `11-accessibilite.mjs` : annonce `aria-live` présente, aucune violation axe ; `12-mesures.mjs` : `⏱` du temps de calcul d'accrochage par mouvement sur le niveau le plus chargé (r2, 237 tracés), sans seuil annoncé avant mesure (R14). |
| Règles métier | Aucune. Le pas de grille 0,50 m est une **exigence d'interface** (cahier §5.8), pas une trame constructive ni une donnée de projet. |

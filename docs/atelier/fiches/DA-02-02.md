| Champ | Contenu |
| --- | --- |
| Identité | DA-02-02 (M02, étape cible P1). `transformer.copier` : copie d'objets existants en objets nouveaux et indépendants. Sous-exigences : -a copie unique ; -b mode multiple (une copie par validation). Référence de comportement : prototype, outil « Copier » (copie un mur avec ses ouvertures ; une cotation copiée perd ses rattachements). |
| Situation utilisateur | Dupliquer une partie du plan (un local type, un poteau, un tracé) à un autre endroit du même niveau, avec ce qui lui est attaché et sans dupliquer des données qui n'ont de sens que pour l'original. |
| Entrées et unités | `niveauId` ; `cibles` ; `vecteur` (m, non nul) ; `nouveauxIds` (un par objet créé, de la forme `${projectId}_…`, fournis ou dérivés du `requestId` : le réducteur ne tire jamais un identifiant au hasard). |
| | Classes admises : `esquisse.*`, `mur` (avec ses ouvertures), `dalle`, `solide`, `poteau`, `escalier`, `reference-plan`, `cotation`, `texte`, `etiquette`. Refusées : `piece`, `espace`, `zone` (la copie dupliquerait code, nom et liaison au programme : `piece.creer`, `piece.detecter`) et `ouverture` seule (`ouverture.poser`). |
| Comportement | **Cycle.** Sélection → point de base → point d'arrivée (accrochés, DA-02-15) ou saisie (DA-02-16) → aperçu des copies (fantôme, effectifs créés) → contrôle → validation ; mode multiple : chaque validation est un lot, une action annulable. |
| | **Commandes.** `transformer.copier` : copies de même classe, mêmes paramètres, même `calqueId`, même `typeId` ; propriétés typées copiées avec provenance et statut. Une copie de mur reçoit des copies de ses ouvertures (nouvelles occurrences, même définition, `t` identique). |
| | **Valeurs non recopiées (R3).** `exterieur` d'un mur, `repere` d'une ouverture (un repère en double rendrait les tableaux ambigus), `statutConception` d'un poteau : « non évalués » sur la copie, jamais hérités de l'original. |
| | **Autres classes.** Escalier : la copie forme un nouveau `groupe`, jamais une occurrence de plus du groupe d'origine. Cotation rattachée : la copie est une cotation libre (valeurs résolues, indiqué à l'aperçu), l'original garde ses références ; aucune référence n'est créée vers l'original. |
| | **Contrôles.** Vecteur nul (copies superposées) refusé ; cible d'un autre niveau, supprimée ou sur un calque verrouillé : lot refusé en entier ; superposition avec un objet existant : signalée à l'aperçu, non bloquante. |
| | **Palette (UX2) et aide (UX4).** « copier » ; synonymes « copy », « dupliquer » ; actif si au moins un objet d'une classe admise est sélectionné ; exemple court : copier un poteau de 3,00 m vers la droite ; clavier complet par la saisie de précision (DA-02-16). |
| Données et dépendances | Crée des occurrences (identifiants déterministes) et des relations `heberge-par` pour les ouvertures copiées ; aucune référence existante modifiée (R12 sans objet) ; événement de commande validée : vues, quantités et bilan Harmonie « à recalculer ». |
| Résultats | N objets nouveaux (plus leurs ouvertures), sélectionnés après validation ; inverse = suppression exacte de ces objets ; effets listés (objets créés). |
| Cas limites | **Géométrie.** Copie d'une `piece` refusée avec l'action « Créer une pièce » ; sélection vide ; coordonnée résultante hors borne ; objets de niveaux différents. |
| | **Concurrence.** `baseRevision` dépassée et cible modifiée ou supprimée depuis → 409 détaillé ; même `requestId` → mêmes objets, aucune seconde copie (T06). |
| | **Réseau et droits.** Hors ligne : le rejeu reproduit les mêmes identifiants grâce à `nouveauxIds` ; file Dexie rejouée dans l'ordre ; 403 / 404 / 423 selon R13. |
| Compatibilité | Import P.118 : murs copiables avec leurs 210 ouvertures hébergées, 120 poteaux (`statutConception` importé : « Implantation proposée contre façade ; section non dimensionnée », non recopié), solides, dalles, textes ; les 45 pièces ne se copient pas par cette commande. |
| | IFC : une copie de mur donne un nouvel `IfcWall` et de nouveaux `IfcRelVoidsElement` ; `cotation` et `texte` en `IfcAnnotation` (export seulement). DXF : aucune sortie propre. |
| Validation | **Unité** (`packages/atelier-model/src/commandes/transformer.test.ts`) : copier un mur portant une porte : 2 murs, 2 portes, `t` égal, `repere` absent sur la copie ; copie de poteau : `statutConception` absent ; copie de cotation rattachée : libre ; même enveloppe, mêmes identifiants ; inverse supprime exactement les copies ; `piece` refusée. |
| | **API** (`apps/api/src/routes/atelier-commands.test.ts`) : 200 avec `applique[0].objetIds` égaux aux identifiants fournis ; même `requestId` → pas de seconde copie ; `piece` → 400 avec `chemin` et motif ; `baseRevision` périmée → 409. |
| | **e2e** (`apps/web/e2e/scenarios/05-atelier.mjs`, bloc « 2D · copier ») : copie du mur « Noyau A » de la mezzanine (`EX118-mezz-W-009`) sur la copie de travail de P.118 : murs +1, portes +1, repère de la porte copiée vide ; annuler : effectifs initiaux ; hors ligne : copie en file puis reprise à la reconnexion. |
| Règles métier | Aucune règle réglementaire. R3 : valeurs déclarées (`exterieur`, `statutConception`, `repere`) jamais recopiées sur un nouvel objet. |
| Extensions à spécifier | Copie vers un autre niveau ou un autre projet (presse-papiers) ; copie de pièce avec nouveau code ; copies multiples à pas irréguliers dans un seul lot ; réseau régulier : DA-02-12. |

# PL-01-02 — Measurements box / Champ Mesures (grammaire et affichage) — mode Planche → Atelier — lot Planche 1

**État : disponible — acceptée le 8 octobre 2026 (D-174)** (à spécifier → spécifiée → prototype → vérifiée → disponible). Preuve liée : tests vitest de `packages/planche-model` (lot 1, puis audit du 7 octobre : 407 tests), recette `apps/web/e2e/planche-outils.mjs` ; comptes rendus `docs/planche/lots/lot-1.md` à `lot-7.md`.

| Champ | Contenu |
| --- | --- |
| Identité | PL-01-02, analyse et formatage du champ Mesures (`packages/planche-model/src/saisie-vcb.ts`). Sous-exigences : -a analyse lexicale et syntaxique ; -b typage selon l'attente de l'outil ; -c locale (séparateurs) ; -d unités ; -e formatage d'affichage (valeur courante, « ~ ») ; -f erreurs nommées. Référence : `cahier-planche.md` §5.3 ; relevés [OD §0, §15.2], [OM §0.2], [MCP §0], [DOC §6]. |
| Situation utilisateur | (Servie à partir du lot 2.) Pendant ou juste après un geste, taper une valeur exacte (`3`, `4;3`, `8s`, `x3`, `1:2`) sans cliquer dans le champ, puis Entrée ; lire la valeur courante pendant le mouvement, avec « ~ » quand elle est approchée. |
| Entrées et unités | Texte saisi (chaîne) ; **attente** de l'étape courante, fournie par le catalogue (PL-01-04) : liste de formes admises parmi `longueur`, `liste` (n valeurs et leurs natures), `segments`, `rayon`, `angle`, `pente`, `reseau`, `facteur`, `coordonnees`, `nombre` (champ de vision, hauteur d'œil) ; **options** : `locale` ∈ { `fr`, `en` } (décision P-3 ; défaut proposé `fr`), `imperial` (booléen, décision P-4 ; **défaut : refusé** tant que la décision n'est pas prise — rien n'est supposé), unité du modèle (mètre). Longueurs rendues en **mètres**, angles en **degrés**. |
| Comportement | **-a / -b Grammaire** (cahier §5.3) : `liste` = éléments séparés par `SEP_LISTE`, éléments vides admis (`3;`, `;3`) ; `element` = nombre signé + unité facultative ; `coord_abs` `[a;b;c]`, `coord_rel` `<a;b;c>` ; `segments` = entier + `s` ou `S` ; `rayon` = longueur + `r` ou `R` ; `pente` = `nombre:nombre` → atan(montée / course) en degrés ; `reseau` = `xN`, `Nx`, `XN`, `NX`, `*N` (multiplier) ou `/N`, `N/` (diviser) ; espaces admis autour des séparateurs et entre nombre et unité. La fonction `analyserSaisie(texte, attente, options)` rend une valeur **typée** (union discriminée : `longueur { metres }`, `liste { elements: (Element \| null)[] }`, `segments { n }`, `rayon { metres }`, `angle { degres }`, `pente { montee, course, degres }`, `reseau { mode: "multiplier" \| "diviser", n }`, `facteur { valeurs }`, `coordonnees { repere: "absolu" \| "relatif", valeurs: [x, y, z] }`, `nombre { valeur }`) ou une **erreur nommée** ; une saisie qui correspond à une forme non admise par l'attente est une erreur (`type-inattendu`), jamais réinterprétée. Échelle : un nombre sans unité est un **facteur**, une longueur avec unité une **dimension cible** (obs [OM §4]). |
| | **-c Locale.** `fr` : `SEP_LISTE` = `;`, `SEP_DEC` = `,` ou `.` (`2,5` = `2.5` = 2,5) ; `en` : `SEP_LISTE` = `,`, `SEP_DEC` = `.` (forme relevée : `4m,3m`, `2m,90`). En `fr`, `4,3` est **4,3** (une valeur) ; en `en`, `4,3` est une liste de deux valeurs. Source de la règle : forum officiel [DOC §6.1, F1] (doc) — SketchUp pour une locale à virgule décimale. |
| | **-d Unités.** `mm` (× 0,001), `cm` (× 0,01), `m` (× 1), insensibles à la casse ; sans unité : unité du modèle (m) ; une unité tapée prime (doc [S39]). Avec `imperial` : `'` (× 0,3048) et `"` (× 0,0254), définitions exactes, et forme composée `5'6"` ; sans `imperial` : erreur `unite-non-admise`. Aucune autre unité (`km`, `yd` : doc nv). |
| | **-e Formatage.** `formaterLongueur(metres, { precision, locale, approchee })` → `1,93 m` / `~ 1,93 m` (précision par défaut 2 décimales, relevé Info modèle `0,00 m` [CP]) ; `formaterListe` → `1,93 m ; 0,59 m` en `fr` (`1.93 m, 0.59 m` en `en`) ; `formaterAngle` → `30,0` (1 décimale, relevé), `~ 26,6` ; `formaterAire` et `formaterVolume` : précision 2 (Info modèle), **zéros finaux retirés** (relevés `10.8 m²`, `9.68 m²`, `Volume 12 m³`, `9 m³` [MCP §1.1, §4.1], [CM §2]), alors que les longueurs les gardent (`4.00 m`, `0.00 m`) — règle déduite des relevés. Arrondi d'affichage au plus proche, la moitié s'éloignant de zéro ; l'affichage n'altère jamais la valeur (R7). Le texte **tel que tapé** est rendu à l'interface pour l'affichage après validation (obs [OM §0.2]) : le noyau ne le reformate pas. |
| | **-f Erreurs** (code + message français + position du premier caractère fautif) : `vide`, `non-reconnue`, `unite-non-admise`, `type-inattendu`, `nombre-de-valeurs` (trop ou trop peu pour l'attente), `hors-bornes` (bornes portées par l'attente ; segments 3 à 999, obs : message « Le nombre de segments d'une courbe doit être compris entre 3 et 999 »), `non-fini` (NaN, ∞). Réaction de SketchUp à une saisie non reconnue : non relevée (cahier L-26) ; choix Fadi : erreur annoncée, rien n'est appliqué. |
| Données et dépendances | Fonction pure, sans dépendance (R6) ; ne lit ni n'écrit le modèle ; aucune révision. Les bornes et formes admises viennent du catalogue (PL-01-04). |
| Résultats | Une valeur typée en unités SI (m, degrés) ou une erreur nommée ; des chaînes d'affichage. |
| Cas limites | `""` → `vide` ; `"  3  "` → 3 ; `"3 m m"` → `non-reconnue` ; `"--3"` → `non-reconnue` ; `"3e2"` (notation scientifique) → `non-reconnue` (choix Fadi, non relevé) ; `"1 000"` → `non-reconnue` ; `";"` en `liste` → deux éléments vides → `nombre-de-valeurs` si l'attente exige au moins une valeur ; `"x0"`, `"/0"`, `"x-2"` → `hors-bornes` (N ≥ 1 ; borne supérieure portée par l'outil) ; `"1:0"` → `hors-bornes` (course nulle) ; `"0s"` → `hors-bornes` ; `"2,5"` en `en` → liste [2 ; 5] ; `"2.5,3"` en `fr` → `non-reconnue` (la virgule n'est pas un séparateur de liste en `fr`) ; mélange de formes (`"[1;2;3]x2"`) → `non-reconnue` ; calcul (`"2+0,3"`) → `non-reconnue` (SketchUp n'en fait pas état ; le calcul de l'inspecteur de l'Atelier, D-049, n'est pas repris ici). |
| Compatibilité | Formes relevées en anglais : `3m`, `4m,3m`, `2m,90`, `8s`, `6s`, `x3`, `3x`, `/3`, `1:2`, `2`, `3m`, `60` (obs) ; formes documentées non relevées : `[x,y,z]`, `<x,y,z>`, `*N`, `N/`, `24r`, négatifs (doc). |
| Validation | **Unité** (`saisie-vcb.test.ts`), locale `fr` sauf mention : `3` → 3 m ; `2,7 m` → 2,7 ; `2.7m` → 2,7 ; `270cm` → 2,7 ; `2700 mm` → 2,7 ; `-3` → −3 ; `4;3` → [4 ; 3] ; `4 m ; 3 m` → [4 ; 3] ; `3;` → [3 ; vide] ; `;3` → [vide ; 3] ; `2;90` (attente longueur ; angle) → [2 m ; 90°] ; `8s` → 8 ; `1000s` → `hors-bornes` ; `2s` → `hors-bornes` ; `1:2` → 26,565051177077990° (atan 0,5, à 1e-12) ; `x3`, `3x`, `*3` → multiplier 3 ; `/3`, `3/` → diviser 3 ; `[1;2;3]` → absolu (1 ; 2 ; 3) ; `<1;0;0>` → relatif ; `24r` → rayon 24 m ; `abc` → `non-reconnue` en position 0 ; `2'` → `unite-non-admise` (sans `imperial`) et 0,6096 m (avec) ; `5'6"` (avec) → 1,6764 m ; locale `en` : `4m,3m` → [4 ; 3], `2.5` → 2,5. Formatage : 1,926 approchée → `~ 1,93 m` ; [1,93 ; 0,59] → `1,93 m ; 0,59 m` ; 26,565 approchée → `~ 26,6` ; 10,8 m² → `10,8 m²` ; 9,68 → `9,68 m²` ; 12 m³ → `12 m³` ; 0,125 m → `0,13 m` (0,125 est exact en binaire). **API, e2e** : sans objet au lot 1. |
| Règles métier | Aucune. Les conversions d'unités anglo-saxonnes sont des définitions exactes, pas des données (R3). |
| Extensions à spécifier | Autres unités si demandées ; précision d'affichage réglable (Info modèle, lot 5) ; correspondance avec la saisie de précision de l'Atelier (`longueur` ou `dx;dy`, DA-02-16) pour une éventuelle mise en commun après le lot 2. |
